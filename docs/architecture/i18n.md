# Interface localisation — a translatable, mirrorable Caotang UI

> Status: **partly built.** `packages/i18n` and the formatter locale are built (I2, #192): every number and date in the interface is formatted in the formatter locale (§4.1), and the writer's own names sort by the project language (§4.3). The rest is **specified, not built**: the interface has no message framework, every label, notice and error is a hardcoded English string in `apps/desktop/src` (and in the packages that hand text to it), and there is no interface-language setting and no right-to-left interface. The *content* side is already multilingual (project language, dialogue locales, Yarn locks, and PDFs that set CJK, Arabic, Hebrew and Devanagari), and this spec builds on it without changing it. The decisions in §12 bind the work when it is cut.
> Scope: one **interface language**, separate from the **project (content) language**. Covers message catalogs and the library, formatting, RTL mirroring, the agent's language, coherence finding messages, export boilerplate, testing, the translation workflow, and translated docs.
> Cross-refs: project language and EPUB identity = [epub-metadata.md](epub-metadata.md) · PDF scripts and bidi = [exporter.md](exporter.md), [screenplay.md](screenplay.md) §5 · findings = [coherence.md](coherence.md) §3–§5 · agent prompts and plan cards = [agent-harness.md](agent-harness.md) · keyboard map and centre views = [ui-modules.md](ui-modules.md) §2.5/§3 · bus and notices = [command-bus.md](command-bus.md) · MCP server, CLI and SDK = [extensibility.md](extensibility.md) · bundle gate = `tools/check-bundle-size.mjs`.

## 1. Evidence: prior art and the pain points this design avoids

| # | Pain point (evidence) | How the design avoids it |
|---|---|---|
| P1 | **Mixed-language UI.** Scrivener's German UI still alternates with English in 2026. "Preview Available" languages are knowingly incomplete (L&L forum 154014, 121207, 132845). Obsidian's macOS menu was untranslatable (obsidian-translations #808) | A per-language completion gate with an honest "partly English" label (D5). Missing strings fall back per message, not per screen. The ratchet test (§8.2) keeps new English from slipping in untranslated. |
| P2 | **A hard threshold hides a nearly done language.** Excalidraw hides any locale under 85%, so pt-BR and pt-PT vanished at 84% (excalidraw #10847) | The picker shows the percentage. "Preview" covers 60–94%, so a 1% dip never removes a language a user already chose. |
| P3 | **Translators lack placeholder context.** In Turkish the suffix depends on the noun: Zotero's "Welcome to %S!" became "Zotero'ya / Firefox'a / Word'e". Unnumbered `%S` cannot be reordered (Zotero forum 66383) | Named ICU placeholders only (`{title}`, never positional), plus a translator comment on every message with values. A lint rule (§8.2) enforces both. |
| P4 | **Big batches of new strings drop every language at once.** Joplin's table shows most languages at exactly 81% (Joplin localisation.md). Zotero holds back unstable strings (Zotero forum 108649) | Strings are extracted on `main` but pushed to translators per release, from the release branch. Feature work in a wave lands its English and its extraction together. |
| P5 | **Stale translations.** Zotero merges new English into every locale before a build (Zotero forum 93509). Logseq tracks entries "same as English" (`bb lang:pseudo`) | Source-text IDs: a changed English string is a new message, and the old translation is kept as fuzzy (PO `#, fuzzy`) and shown as English until reviewed. The CI reports untranslated, fuzzy and same-as-English counts. |
| P6 | **No way to check missing or invalid keys.** Logseq built `lang:missing`, `lang:validate-translations` and a CI job (logseq PR 4072, contributing-to-translations.md) | `lingui extract` drift check, compile with `failOnCompileError`, and placeholder parity. All run in `pnpm verify` (§8.2). |
| P7 | **RTL mirroring tied to the UI language.** Obsidian mirrors only when the UI language is RTL. Users who want English UI but RTL notes ask for decoupling (Obsidian forum 95714). Plugins break mirroring | The manuscript's direction follows the *project* language and `dir="auto"`, independent of UI mirroring (§5.4). UI mirroring follows the UI language. A separate "mirror without changing language" switch is D12. |
| P8 | **Icons and positions in RTL.** Obsidian flips every Lucide icon by default with an opt-out, uses logical CSS, a `--direction` variable, and `unicode-bidi: plaintext` for single-line user text (docs.obsidian.md Right-to-left) | The same toolkit: logical properties, one `--dir` variable, `unicode-bidi: plaintext` on titles, and an explicit list of icons that flip (§5.2). |
| P9 | **User content breaks UI sentences.** An opposite-direction title or a number next to it reorders the sentence (W3C "Inline markup and bidirectional text") | Every interpolated user string is isolated: `<bdi>` in JSX, FSI…PDI (U+2068/U+2069) in attributes and plain strings (§5.3). |
| P10 | **Text expansion.** Short English labels grow 200–300% in European languages, and long text about 30%. German compounds do not wrap ("Eingabeverarbeitungsfunktionen") (W3C "Text size in translation", IBM figures) | The pseudo-locale pads 40% *and* inserts unbroken compounds. An e2e overflow probe runs on the 960 px and 1100 px layouts that the user guide pins (§8.3). |
| P11 | **Keyboard layouts.** VS Code renders shortcuts in the current layout and supports scan-code bindings (`[KeyZ]`) because virtual keys move between layouts (VS Code keybindings docs) | `key` first, `code` fallback for non-Latin layouts, AltGr excluded, labels from the layout (§7.2, I10, #189). |
| P12 | **IME confirmation fires shortcuts.** The Enter that confirms a CJK candidate arrives as `keydown` during composition (MDN `KeyboardEvent.isComposing`; note MDN marks it "limited availability", hence the `keyCode 229` belt) | One shared `isImeEnter(event)` guard in every Enter handler (I0). |
| P13 | **Runtime ICU compilers violate strict CSP.** `messageformat` compiles with `new Function` (messageformat #180, #112). BigCommerce moved to `intl-messageformat` for this reason (checkout-sdk-js PR 2674) | Catalogs are compiled at build time. The shipped runtime has no message parser (§2). |
| P14 | **Language packs as separate installs lag the app.** VS Code ships English and installs Language Packs from the Marketplace, with a restart (VS Code Display Language) | Catalogs ship with the static build, one lazy chunk per locale, and switching does not reload the page (§3.3). ## 2. Library choice under `script-src 'self'`

React **19.3**, Vite **8.3.2** (Rolldown/oxc, no esbuild, `@vitejs/plugin-react` 6), TypeScript 6 strict, Vitest 5 in a Node environment, pnpm 12 with an empty `onlyBuiltDependencies`.

| | **Lingui 6** (compile-time macros) | **Paraglide JS 2** (inlang) | **FormatJS / react-intl** (precompiled) | **i18next + react-i18next** | **typesafe-i18n** | **Plain `Intl` + own catalogs** |
|---|---|---|---|---|---|---|
| CSP | Catalogs compiled at build. "Runtime stays around 2 kB and ships no message parser" | Messages compiled to ESM functions. No runtime parser | Precompile to AST (`formatjs compile --ast`) and alias the parser to `no-parser.js`, or the parser ships. AST formatting needs no eval | No eval in core. ICU only through a plugin (`intl-messageformat`, which is CSP-safe) | Small runtime parser, no eval | Safe |
| Runtime size | ≈ 2 kB core, plus `@lingui/react` | Per-message, tree-shaken. Vendor benchmark: 47 kB against i18next's 205 kB (5 locales, 200 messages) | Largest of the set. AST catalogs are "slightly larger" | Runtime dictionaries. Grows with the catalog (vendor benchmark above) | ~1–1.6 kB | 0 |
| Plurals, select, ICU | Full ICU MF1 (plural, select, selectordinal) on `Intl.PluralRules` | Variants. ICU MF1 through a plugin. Plural through `Intl.PluralRules` | Full ICU MF1 | Own `_one/_few/_many` suffixes (CLDR via `Intl.PluralRules`). ICU through a plugin | Own syntax, plural, switch-case | Hand-rolled |
| TS key safety | Source-text IDs (no keys to mistype). Typed explicit IDs available | **Best**: typed functions and parameters | Explicit IDs, partly typed | Typed via declaration merging | Strong, generated | Strong if generated |
| Extraction | `lingui extract` to **PO** (comments and context travel), native extractor, ESLint plugin, `failOnMissing` | Messages are authored in JSON. Nothing to extract | `formatjs extract` | `i18next-parser` (third party) | Generator | **None** |
| React | Yes: `<Trans>` with JSX inside messages, `useLingui` | Plain functions, plus the `ParaglideMessage` markup adapter. **`setLocale()` reloads the document by default**, and `{ reload: false }` is a warned "escape hatch" | Yes | Yes | Yes (adapter) | Yes |
| Vite 8 / Rolldown | `@lingui/vite-plugin` `macroTransform: true` (native Rust/SWC transform, prebuilt binaries, **no WASM fallback**). The Babel route goes through `@rolldown/plugin-babel` | First-class Vite plugin | Unplugin | No build step | Generator | — |
| Where the English lives | **In the component source** (`<Trans>Open as a separate copy</Trans>`) | In `messages/en.json` | In source (`defaultMessage`) with explicit IDs | In JSON | In TS dictionaries | In catalogs |
| Maintenance | Active (Crowdin-backed; v6 in 2026-04, native transform 2026-10) | Active (inlang, SvelteKit's official integration) | Active | Active | **Creator died 2023.** Repo moved to `codingcommons`, 24 open issues and 18 open PRs | Ours |

**Recommendation: Lingui 6** with the native macro transform, PO catalogs, and one lazily imported compiled catalog per locale. This is D1. The reasons, in order:

1. **The guards keep working.** Lingui's macros leave the English sentence where it is in the `.tsx`. `test/user-guide-claims.test.ts`, which greps `Home.tsx` for `'Open as a separate copy'`, still passes, and so do the ~2,790 e2e text selectors (with the e2e locale pinned to `en`, §8.4). Paraglide and i18next move every string into JSON, so each claim test would need rewriting against a catalog.
2. **CSP and bundle.** No parser ships. A compiled catalog is plain data, which fits `script-src 'self'` with nothing relaxed. The runtime adds about 2 kB to the entry, and each locale is its own chunk that the bundle gate measures (§3.5).
3. **Rich text and full ICU.** Many strings mix `<strong>`, `<kbd>` and links (PlanCard, AgentModeSettings). `<Trans>` keeps the sentence whole for translators. Paraglide would need its markup adapter on every such string.
4. **PO is universal.** Weblate, Crowdin, Transifex, Poedit and Tolgee all read it. Comments and context reach translators (P3).
5. **Live switching.** `i18n.activate()` re-renders under `I18nProvider` with no reload. Paraglide's default reload would cut through the pending journal and an open agent turn.

Rejected alternatives: **Paraglide** has better key typing and tree-shaking, but strings leave the source (breaking the doc-claim tests), switching reloads by default, and rich text is weaker. Revisit only if catalog size becomes the bottleneck. **FormatJS**: full ICU and CSP-safe when precompiled, but heavier and the alias is a footgun. **i18next**: a runtime dictionary model with non-ICU plural keys. **typesafe-i18n**: maintenance risk. **Plain Intl**: no extraction, PO or plural tooling for ~2,500 messages. We still use `Intl` directly for all *formatting* (§4).

Spike conditions for I3: `macroTransform` must work under Vite 8 and inside Vitest's transform (the macros run in `vitest.config.ts` too), or the `@rolldown/plugin-babel` preset is used instead. No `securitypolicyviolation` may appear in the e2e CSP check. `pnpm install` must not need an `onlyBuiltDependencies` entry, because `@lingui/native-tools` ships prebuilt optional binaries and `test/toolchain-floor.test.ts` asserts the allowlist. Bundle numbers are recorded in `BUDGET`.

## 3. Architecture

### 3.1 Two languages, never conflated

| | **Interface language** | **Project (content) language** |
|---|---|---|
| What | Menus, panels, notices, plan cards, findings' prose, the agent's messages to the writer | The manuscript, codex, synopses, default titles written into the project, export boilerplate (§7.1), EPUB `dc:language`, PDF shaping |
| Stored | App setting (per browser, beside the other app settings in `app-db`). Values: `'system'` or a shipped tag. Never written to the project | `project.language` (exists) |
| Default | `'system'`: first `navigator.languages` entry matched against shipped locales above the gate (D5), else `en` | App locale's language subtag at create (exists) |
| Sets | `<html lang dir>`, catalog, formatter locale (§4), UI mirroring | `lang` (and `dir="auto"`) on every content surface: editor, binder titles, corkboard cards, codex names, previews |
| Changed by | Settings › General › Interface language. Live | Project panel (exists) |

A German writer with an English UI writing a Japanese novel is a normal case. So is an Arabic UI over a French manuscript.

### 3.2 Packages

- **`packages/i18n` (`@caotang/i18n`)**, built in I2 (#192), with no React and no Lingui import. It holds `resolveUiLocale(setting, navigatorLanguages, shipped)`, `formatLocale(ui, navigatorLanguages)` (§4.1), `directionOf(tag)` (`Intl.Locale#getTextInfo()` where present, else a list: ar, fa, he, ur, ps, sd, ug, yi, dv, ckb), cached `Intl` formatter factories, `collatorFor(tag)`, `isolate(text)` (FSI…PDI), and the **`MessageRef`** type:

  ```ts
  /** Text a package hands to a UI: a stable id, its values, and the English it renders as today. */
  interface MessageRef { id: string; values?: Record<string, string | number>; message: string /* English, ICU */ }
  ```

  Packages (`harness`, `coherence`, `bus`, `store`, `exporter`) keep returning their English `string` where they do now, and **add** a `MessageRef` beside it where the app renders the text. The app renders `i18n._(ref)` when the active catalog has `ref.id`, and `ref.message` otherwise. The CLI, the MCP server and the SDK keep using the English string (D10). The `id`s are extracted from package sources by a small custom Lingui extractor that reads `MessageRef` object literals (`{ id: 'coherence.timeline.orderDrift', message: '…' }`). Packages need no macro transform, and the Node-built MCP server and CLI stay untouched.
- **`apps/desktop/src/i18n/`** holds `I18nProvider` setup, `useFormat()` (formatters bound to the formatter locale), `<UserText>` (a `<bdi>` with `lang`/`dir="auto"`), `renderRef(ref)`, the language picker model, and `locales/<tag>/messages.po`. Catalogs are compiled by `@lingui/vite-plugin`.
- Desktop code uses macros: `<Trans>` for JSX, `` t`…` `` / `msg` for attributes and model files, `<Plural>`/`plural()` and `<Select>`/`select()`. Message IDs are source-text-generated. Explicit IDs are used only for strings that packages also produce (`MessageRef`) and for long help paragraphs whose English is edited often (P4/P5).

### 3.3 Loading and switching

- `en` is the source locale. Its compiled catalog is **in the entry chunk**: production macros emit id-only descriptors, so English must be present before first paint, and it is the per-message fallback.
- Every other locale is `import(\`./locales/${tag}/messages.po\`)`, one chunk per locale, loaded before activation. The language picker shows a spinner while it loads, and a failed load leaves the UI in its current language with a notice.
- Switching calls `i18n.activate(tag)`, sets `document.documentElement.lang/dir`, and re-renders. No reload, so pending journals, the agent turn and focus survive. Focus stays on the picker.
- Lazy views (`lazy-view.tsx`) share the global catalog. Per-view catalog splitting is not worth it at ~35 kB gzip per locale (§3.5).

### 3.4 What must not be translated

- **Model-facing text:** system prompts, tool names and descriptions, JSON schemas, validation errors returned *to the model* (`harness/validate.ts`, `tools/*`), and MCP tool descriptions. These stay English in source, outside the catalog, in files the ratchet test (§8.2) exempts by a top-of-file `// i18n: model-facing` marker.
- **Stored tokens:** enum values (`timelineMode`, shot spec tokens per decisions.md), command ids, file formats and CSV headers that tools parse (the shot list keeps tokens; decisions.md).
- **Persisted prose:** English already written into projects (activity rows, finding `message`, notices in history) stays as written. New rows store a `MessageRef` beside the English (§6.2), so the app re-renders them in the current UI language.

### 3.5 Bundle discipline

At ~20k words a compiled catalog is about 120–150 kB raw and 35–45 kB gzip per locale. This is an estimate: I3 measures it and writes the real numbers into `BUDGET`. Only the active locale loads. The `en` catalog plus the runtime grows `index` (the entry is already capped "a little above what it measured", 1,270 kB), so I3 raises `index` and `initialGzip` deliberately and says why, as the gate requires. Pseudo-locales are dev-only and never in `dist/`.

## 4. Formatting

### 4.1 Which locale formats

The **formatter locale** is the UI language plus the system's region when the languages match. A UI set to `en` on an `en-GB` system formats as `en-GB`. A UI set to `de` on an `en-US` system formats as `de-DE`, the language default. This is D3. It fixes the existing split, where some calls are pinned to `en-US`, one to `en-GB`, and some follow the system. While the UI language is English it changes visible output only for non-US English systems. CHANGELOG says so. Built in I2 (#192), and recorded in decisions.md. Until the setting exists (I4) the interface language is `en` everywhere, so the formatter locale is `en` plus the system region when the system is English, and `en-US` otherwise. The app reads it from `apps/desktop/src/i18n/locale.ts` (`appFormatLocale()`), which unit specs pin with `pinFormatLocale` and the e2e suite pins through Playwright's `locale: 'en-US'`.

### 4.2 The formatters

| Need | API | Replaces |
|---|---|---|
| Counts, tokens, words | `Intl.NumberFormat(fl)` | all `'en-US'` grouping sites |
| Prices (provider USD) | `Intl.NumberFormat(fl, { style: 'currency', currency: 'USD', maximumFractionDigits: 6 })` | `$${n.toLocaleString('en-US', …)}` in `Settings.tsx` |
| Dates (footer, history, title page preview) | `Intl.DateTimeFormat(fl, { dateStyle })` | `toLocaleDateString('en-GB', …)` |
| "3 minutes ago", "yesterday" | `Intl.RelativeTimeFormat(fl, { numeric: 'auto' })` | hand-built strings |
| "Chapter 1, Chapter 2 and Chapter 3" | `Intl.ListFormat(fl, { type: 'conjunction' })` | `join(', ')` + `' and '` |
| Plurals inside messages | ICU `plural` (Lingui, `Intl.PluralRules`) | 185 ternaries and 5 helpers |
| Language names in the picker | `Intl.DisplayNames([tag], { type: 'language' })`: each language in its own name | — |
| Week start | `goal.ts` already uses `Intl.Locale`. Pass the formatter locale, not the system locale | — |

Plural categories are CLDR's: Arabic uses zero/one/two/few/many/other, and Polish and Russian use one/few/many/other. Messages must never encode "1 vs not 1" in code.

### 4.3 Sorting

Lists of the writer's own names (codex, characters, binder filters, Inspector value lists) sort with `Intl.Collator(project.language, { sensitivity: 'base', numeric: true })`. They are content, and a Swedish novel sorts å after z whatever the UI language (D9). Lists of UI terms (settings options, export formats) sort with the formatter locale. `localeCompare(b, undefined, …)` is replaced in each of the six model files. `numeric: true` makes "Chapter 10" sort after "Chapter 9".

## 5. Right-to-left interface

### 5.1 Logical layout

`<html dir>` follows the UI language. The ~70 physical declarations become logical: `margin-inline-start`, `padding-inline-end`, `inset-inline-start`, `border-inline-start`, `text-align: start`, `float: inline-start`. One custom property, `--dir: 1 | -1`, covers `translateX()` and transform math. Flex and grid rows mirror by themselves once `dir` is set. A CSS guard test (in the style of `check-bundle-size.test.ts`) fails on a new physical property outside a short allowlist: things that are truly physical, such as the editor's ruler and media scrubbers.

### 5.2 What flips and what does not

| Flips in RTL | Does not flip |
|---|---|
| Back/forward, disclosure chevrons (tree expand, "next" arrows), sidebar collapse, panel slide-in direction, Indent/Outdent, progress fill direction, the binder tree's indentation and connector lines | Play/pause and media transport, the clock and history icons, checkmarks, the search magnifier, undo/redo glyphs (the shapes depict rotation, not reading direction; confirm with the native reviewer, §5.5), logos, keyboard key glyphs, the screenplay page and PDF previews (a page is content), text-formatting icons tied to Latin glyphs (B/I) |

Icons are inline SVG components. A `mirror` prop adds `.icon-mirror`, which sets `transform: scaleX(var(--dir))`. The default is **no flip**, because an icon that flips needs a reason. This is the opposite of Obsidian's flip-all default, and it is chosen because Caotang's set is small and listed here.

### 5.3 Bidi isolation of user content inside UI strings

Every interpolation of writer content (titles, character names, file names, model names, finding evidence) is isolated:

- JSX goes through `<UserText value={title} lang={projectLang} />`, which renders `<bdi lang dir="auto">`. In messages it is a component placeholder: `<Trans>Delete <0>{title}</0>?</Trans>`.
- Attributes and plain strings (`aria-label`, `title`, notices, `document.title`, toasts) use `isolate(text)`, which wraps the text in U+2068…U+2069 (W3C).
- Single-line titles in lists use `unicode-bidi: plaintext` with `text-overflow: ellipsis`, as Obsidian does, so a Hebrew title in an English binder truncates at its own end.

### 5.4 Content direction is independent

The editor, corkboard card bodies, codex entries and previews get `lang={project.language}` and `dir="auto"` per block, so mixed paragraphs work as in the PDFs (first strong character, project language for neutral text). Mirroring the UI never changes the manuscript, and an LTR UI over a Hebrew manuscript is fully supported (P7).

### 5.5 Keyboard in RTL, and a reviewer before shipping

The binder tree follows the APG tree pattern: Left and Right swap meaning in RTL. `keymap.ts`'s `move-left/right` and `reparent-in/out` resolve through `directionOf(uiLocale)`. Corkboard arrow navigation follows visual order. The story timeline (not built) keeps its own rule: whether story time runs right to left is an open question for timeline.md, recorded here so that spec decides it. As with the PDFs' mirrored page (decisions.md: "not built until a native reader has seen it"), **an RTL interface ships as Preview until a native reader of Arabic or Hebrew has reviewed it** (D8).

## 6. The agent, findings, notices

### 6.1 Agent prompts stay English, and its prose follows the UI

- System prompts, tool descriptions and eval fixtures **stay English**. There is one tested prompt and one set of evals, and current models follow English instructions best. Translating prompts multiplies eval cost per language (D2).
- The context assembly adds one line: *"Write messages to the writer (plan titles, step summaries, questions, findings' explanations, notes) in {uiLanguageName}. Write manuscript, synopsis and codex text in {projectLanguageName}. Quote evidence exactly as written."*
- Harness-built strings that the app shows (`agent/progress.ts`, 103 sites; plan-card estimates; refusal and limit notices) become `MessageRef`s. Model-written prose arrives already in the UI language.
- Mock-provider evals gain one German-UI / English-project case and one English-UI / Japanese-project case. Each checks that the instruction line is present and that no model-facing text changed.

### 6.2 Coherence findings

`Finding.message` is persisted English in `coherence.json` and is read by the MCP server, the SDK and the coherence report. The design is additive (D7):

```ts
interface Finding { /* … */ message: string; messageRef?: MessageRef /* deterministic checks only */ }
```

- Deterministic checks (`checks/timeline.ts` and the rest) fill `messageRef` with named values (`{lateTitle}`, `{earlyTitle}`, `{lateDay}`, …). The inbox renders it through the catalog, with titles isolated. Old files without `messageRef` render `message` as before.
- `llm:*` findings: the model writes `message` in the UI language at scan time (§6.1). A later UI language change does not re-translate them. They show as written, the same rule as other persisted prose.
- The codec accepts and round-trips `messageRef`. The MCP server's merge rule ignores it.

### 6.3 Notices, undo labels, activity

Bus refusal reasons and store notices gain `MessageRef`s the same way. Activity labels (`activity-model.ts`, keyed by command id) move into the catalog keyed by command id, so history renders in the current language.

## 7. Export boilerplate and keyboard specifics

### 7.1 Boilerplate follows the document's language

Text the exporter writes *into the document* is content. It follows **`project.language`**, never the UI language (D4):

| String | Where today |
|---|---|
| "Contents" (DOCX TOC heading and field, EPUB nav `<h1>` and nav title) | `render-docx.ts:90/94`, `render-epub.ts:230/232` |
| EPUB landmarks and title page labels, "Chapter" in generated headings | `render-epub.ts`, templates |
| "Untitled", "Untitled scene", "Untitled section" written as titles | `exporter/template.ts:98`, `store/commands-script.ts:121/142`, `lifecycle.ts:385` |
| Screenplay `(MORE)` / `(CONT'D)` | `screenplay/paginate.ts:720/726` |
| Coherence report headings ("Notes", severities) | `exporter/coherence-report.ts` |

These live in `packages/exporter/src/boilerplate.ts`, a typed table `Boilerplate` keyed by language subtag (with script/region where it matters, such as `zh-Hant`) and falling back to English. A recipe can override each label (`recipe.labels.contents`), which also covers house styles. The table is a separate translation component (JSON) on the translation platform, not part of the UI catalog. Screenplay continuation marks default to the English industry forms in every language until a native screenwriter confirms the local convention. The coherence report is a report *to the writer*, so it follows the UI language. That is the one exporter exception, and the export dialog says so.

### 7.2 Shortcuts across layouts

- Match `event.key` first, so the key labelled Z is undo on QWERTY, QWERTZ and AZERTY alike. When `key` is one character outside ASCII (Cyrillic, Greek, Hebrew, Arabic layouts), fall back to `event.code` (`KeyZ`), as VS Code's scan-code bindings do. ASCII punctuation keeps its own key, so Dvorak's `;` on the physical Z is not undo. Built in #189 (`chordKey` in `app/keymap.ts`, ui-modules §2.5).
- Ignore Ctrl+Alt chords when `event.getModifierState('AltGraph')` is set. On Windows AltGr arrives as Ctrl+Alt and types characters such as `@`, `{` and `€` on German and Polish layouts. Built in #189.
- `shortcutLabel()` renders modifier names through the catalog (German Windows keyboards print "Strg"), and on Chromium renders keys with `navigator.keyboard.getLayoutMap()` where available.

### 7.3 IME

`isImeEnter(e) = e.isComposing || e.keyCode === 229` (`apps/desktop/src/app/ime.ts`; a React event is read through its `nativeEvent`), checked in every `key === 'Enter'` handler in `apps/desktop/src` (the 17 in `components/` the audit found, plus the Intent box's command list, which read only `nativeEvent.isComposing`, and the two screenplay handlers: the Source tab's cue keys and the preview's lines) and in `keymap.resolveKey`, through a `composing` fact that every caller passes and that makes any key mean nothing while it is set. The Intent box is in a form, so it also cancels the composing Enter, which would otherwise submit the half-typed line. Built (I0, #188). `test/ime-enter-guard.test.ts` fails on a file with fewer `isImeEnter` calls than Enter checks and on a `resolveKey` call without the fact. Tiptap and ProseMirror already handle composition inside the prose editor. E2e tests drive `compositionstart` → Enter (`isComposing`, and Safari's `keyCode` 229 alone) → `compositionend` in the codex Name and alias fields and the inspector's keyword field (`e2e/ime-enter.spec.ts`), and in the Intent box and a queued message's edit field (`e2e/agent-stop-queue.spec.ts`).

### 7.4 UI fonts

No UI fonts are bundled. The bundle discipline stands, and `--ui` is a system stack. With `<html lang>` set correctly the browser chooses locale-appropriate CJK fallback (Japanese forms for `ja`, Traditional for `zh-Hant`). `:lang(ar), :lang(fa), :lang(ur)` raise `line-height` by about 0.15. `:lang(ja|zh|ko)` set `word-break: keep-all` only on labels, never in the editor.

## 8. Testing

### 8.1 Pseudo-locales (dev and CI only)

Lingui's `pseudoLocale` generates **`pseudo-LOCALE`** (accented, 40% padded, with an unbroken 30-character compound injected into labels of 15 or more characters, bracketed `⟦…⟧` so truncation shows) and **`pseudo-RTL`** (`rightToLeft: true`). Both appear in the picker only under `?pseudo=1` or in dev, are never in `dist/`, and fall back to `en`.

### 8.2 CI checks, all in `pnpm verify`

| Check | Fails when |
|---|---|
| Catalog drift | `lingui extract` changes `locales/en/messages.po` (the same pattern as the THIRD-PARTY-NOTICES drift test) |
| Compile | Any catalog has an ICU syntax error (`failOnCompileError`), or a translation's placeholders differ from the source (parity script) |
| Missing translations | **Never fails** for non-source locales, because per-message fallback is the design. It reports untranslated, fuzzy and same-as-English counts per locale into `locales/stats.json`, which feeds the picker's percentage |
| Hardcoded-string ratchet | The §0.1 inventory script, promoted to `tools/check-ui-strings.mjs`, finds more unwrapped sites in a file than the committed baseline `tools/ui-strings-baseline.json`. The baseline only ever goes down, and must reach 0 for `apps/desktop/src` by I6 |
| Translator hygiene | A message with values has no comment, uses positional placeholders, or is built by concatenation (`t\`…\` + …`) |
| Physical CSS | A new physical direction property appears outside the allowlist (§5.1) |
| Model-facing marker | A file marked `// i18n: model-facing` imports from `@lingui/*` |

### 8.3 End to end

- The suite runs with UI language `en` forced (Playwright `locale: 'en-US'` plus the setting seeded), so the 2,790 text selectors stay valid.
- **Pseudo smoke** (Chromium, every PR) opens Home, Workspace, Settings, Export, Findings and the Agent panel under `pseudo-LOCALE` at 960 and 1100 px. It asserts that no toolbar or button has `scrollWidth > clientWidth`, and that no visible text node lacks the `⟦` marker (any such node is an untranslated hardcoded string).
- **RTL smoke** does the same under `pseudo-RTL`, plus a computed-style check that the binder sits at the inline start and that the tree's Right Arrow collapses.
- axe-core (already a devDependency) runs `html-has-lang`, `valid-lang` and `html-xml-lang-mismatch` on each surface, plus a check that content surfaces carry the project `lang`.
- A CSP test listens for `securitypolicyviolation` during a locale switch and fails on any.

### 8.4 Docs that tests pin

`user-guide-claims` and `not-in-this-build` keep reading English source and English `docs/USER-GUIDE.md`. Because Lingui keeps English in the `.tsx`, the existing claims are unchanged. Claims about package-produced text read `locales/en/messages.po` through a helper `enMessage(id)`. Translated guides are never pinned (§9.3).

## 9. Translation workflow for an OSS project

### 9.1 Platform

| | Weblate (Libre plan) | Crowdin OSS | Tolgee | inlang / Fink | PRs only (Joplin, Obsidian, Logseq) |
|---|---|---|---|---|---|
| Cost and terms | Free for public libre projects, with the limits of the 160k-strings plan. Caotang needs about 2.5k × (N+1) strings, so 11 languages ≈ 30k | Free OSS licence on application (Excalidraw) | Free OSS cloud tier, or self-host | No server, git-native | Free |
| Format | PO native, Git push/pull, fuzzy, glossary, checks (placeholders, plurals) | PO, GitHub sync PRs (Excalidraw's flow) | JSON/PO | inlang JSON (Paraglide-first) | PO with Poedit |
| Fit | **Best**: libre ethos, EU-hosted, used by Penpot | Good, polished translator UX | Good | Weak with Lingui PO | Fine for 1–2 languages, does not scale |

**Recommendation (D6):** PRs of `.po` files while there are one or two translators, then **Weblate Libre** when the third language arrives. Weblate commits to a `translations` branch, and a bot PR merges into `main` with a Conventional Commit title (`chore(i18n): update translations from Weblate`), so the required title check passes. Suggestions need a reviewer per language, as at Penpot. A language's first reviewer is its maintainer.

### 9.2 Release policy for stale and untranslated strings

- Extraction happens on `main` continuously. Pushing to translators happens **per release**, from the release branch, so that strings do not churn mid-wave (P4).
- Picker gates (D5): **≥ 95%** is listed plainly. **60–94%** is listed as "Deutsch, Preview, partly English". **< 60%** is hidden unless `?pseudo=1` or the developer flag is set. Hysteresis keeps an already-listed language listed down to 55%, so no user is dropped (P2).
- Missing and fuzzy messages show English per message, never a key.
- CHANGELOG lists per-release translation counts. Translators are credited in `docs/TRANSLATORS.md` from the Git history.

### 9.3 Docs translation

`docs/USER-GUIDE.md` stays English and authoritative, pinned by tests. Translated guides go in `docs/i18n/<lang>/USER-GUIDE.md`, each section carrying `<!-- source: <first 8 hex of SHA-256 of the English section> -->`. This is the Yarn `lock` idea reused. A non-failing CI report lists stale sections, and the translated guide shows a banner for each section that is older than the English. In-app help links to the guide in the UI language when it exists and is not stale, and to English otherwise. Docs translation starts only after the first UI language ships (D11). ARCHITECTURE, decisions and specs stay English.

## 10. Grammar and phrasing rules (for authors)

1. **Whole sentences, no concatenation.** "Delete" + " " + noun breaks German case and Turkish suffixes. Each variant is a full sentence: `{kind, select, chapter {Delete this chapter?} scene {Delete this scene?} other {Delete this item?}}`. German needs this because the article changes with case and gender ("das Kapitel", "die Szene").
2. **Plurals through ICU.** Never `n === 1`. Include `=0` where English says "No findings".
3. **Named placeholders with comments.** `{title}` comes with `// title: a scene title, written by the writer`.
4. **No abbreviations to save space** (W3C). Layout absorbs expansion instead: wrap, `min-width: 0`, ellipsis with a full-text `title`.
5. **No string-built UI from data tokens.** Map enum tokens to messages by `select`, never by capitalising the token.
6. **Gender of the writer** is never inferred. Messages address the writer in the second person ("you").

## 12. Decisions

Recorded on 2026-10-23: the owner approved the recommended option of each decision. One-line versions are in [decisions.md](../decisions.md).

| # | Decision | Rejected alternative and why |
|---|---|---|
| D1 | Message library: **Lingui 6, compiled PO catalogs, native macro transform (Babel fallback)**. | Paraglide: best typing and tree-shaking, but moves English out of source (doc-claim tests), reloads on switch, and has weaker rich text. |
| D2 | Agent language: **Prompts and tool text stay English. The model writes to the writer in the UI language and writes manuscript text in the project language**. | Translated prompts: an eval matrix per language, and drift between prompt copies. |
| D3 | Formatter locale: **UI language + system region when the languages match**. | Always the UI language's default region (forces en-US dates on British writers), or always the system locale (German dates inside an English UI). |
| D4 | Export boilerplate: **Project language, recipe override per label. Coherence report in the UI language**. | The UI language: a German UI would put "Inhalt" in an English novel's EPUB. |
| D5 | Release gates: **≥ 95% plain, 60–94% "Preview, partly English", < 60% hidden. Hysteresis to 55%. Per-message English fallback**. | A single hard threshold (Excalidraw 85%) drops languages on a 1% dip. |
| D6 | Translation platform: **PO-by-PR now, Weblate Libre from the third language**. | Crowdin OSS: good UX, but a proprietary SaaS for a libre, local-first project. |
| D7 | Finding messages: **Additive `messageRef`. Persisted English `message` kept for MCP, SDK and old files**. | Re-render from the check at view time: needs the check's inputs, breaks for removed scenes. |
| D8 | RTL scope: **Full shell mirroring, Preview until a native reader reviews it. Story time axis left to timeline.md**. | Ship mirrored as final: no one on the project can verify it (same rule as the PDF page, decisions.md). |
| D9 | Sorting writer content: **Collate by the project language**. | The UI locale: a Swedish novel sorts wrong under an English UI. |
| D10 | CLI, MCP server, SDK: **Stay English. They expose `MessageRef`s so a later localisation is cheap**. | Localise now: developer and model audiences, and doubles test surface. |
| D11 | Docs translation: **After the first UI language. English authoritative and test-pinned. Translations hash-marked and unpinned**. | Translate alongside: a moving target while copy changes every wave. |
| D12 | Mirror without changing language: **Not in v1. Revisit on demand (Obsidian forum 95714)**. | Ship it: a second axis to test before the first exists. |

Risks: (1) **Entry growth.** The `en` catalog and runtime raise `index` and `initialGzip`, so I3 measures and records them. Lazy views do not help because the catalog is global. (2) **Churn from source-text IDs.** Every English copy edit re-queues a translation. decisions.md favours whole-sentence rewrites, so long help text uses explicit IDs. (3) **Native-binary toolchain.** `@lingui/native-tools` has no WASM fallback. The Babel preset is the documented fallback. (4) **Persisted English** in old projects, activity rows and `llm:` findings stays English, and the guide says so. (5) **Expansion against pinned layouts.** The 960 px minimum and the 1100 px wrap are guide-pinned, and German may need the toolbar to wrap earlier. That is a guide change, not a hack. (6) **Mixed-language screens** during Waves 2–3. The pseudo smoke's untranslated-node check and the ratchet bound them. (7) **Translator quality and vandalism.** Every language has a reviewer, and Weblate suggestions need approval. (8) **The e2e text selectors** assume English. Pinning the locale keeps them valid, but a selector on package-produced text must follow `messageRef`'s English. (9) **The CSP regression path.** A future dependency with a runtime ICU compiler would be caught by the CSP e2e listener, not by review.
