# Decisions

The standing decisions behind Caotang, one line each: the rule, the reason, and whose call it was.

- **[owner]** — decided by the project owner.
- **[delegated]** — an engineering call made inside the owner's decisions; reversible when the evidence changes.
- **(being built)** — decided, and the work is in progress; the current build does not do it yet.
- **(specified, not built)** — the spec is written and binds the work when it is cut; not in this build.

Superseded decisions, research notes and history are not listed. The specs in [architecture/](architecture/) are the contract; a change to a spec is recorded here.

## Product and principles

- Caotang is a structure-first writing studio (binder → corkboard → editor → compile) with an AI agent that drives the app through its own commands, not a chat sidebar. Why: the agent is the product's difference; a passive assistant is not. [owner]
- The product is a BYOK AI writing tool with a finite first release anchored on the Scrivener bar. Why: an external quality bar and no credential or server dependency. [owner]
- Local-first: all state stays on the device; the manuscript leaves it only through the writer's own provider. Why: the writer owns the work. [owner]
- No Caotang server, no accounts in the local version, no telemetry, no analytics. Why: nothing to trust but the writer's own machine and provider. [owner]
- Stack: a web app in Vite, React and TypeScript, testable headless. Why: no packaging work, every module runs under Vitest, the whole app under Playwright. [owner]
- Every agent action routes through the command bus, grouped into undoable turns; there are no tool-less "AI features". Why: the same surface as the human, auditable and reversible. [delegated]
- Files are ownable: the on-disk folder of Markdown and JSON is the source of truth; browser storage is a working copy. Why: a writer can leave with their work in plain text. [delegated]
- Every new artifact format is plain text (Markdown, Fountain, Ink, JSON, CSV). Why: no binary or proprietary story files. [delegated]
- Launch scope is the whole planned timeline (core loop, MCP client, MCP server, media track, EPUB, filters and goals); version labels are sequencing, not scope. Why: "ready" means the whole timeline. [owner]
- The media track shipping order is coherence, then screenplay, then storyboard and prompt packs, then branching dialogue. Why: prose-adjacent first; the biggest data-model lift last. [owner]
- Screen and media formats are new document kinds, export recipes and agent tools, never a fork of the app. Why: binder, codex, context and compile generalise to any structured narrative. [owner]
- Caotang serves long-form makers, not only novelists. The structure-first spine — binder, corkboard, codex, compile, and an agent that works under approval — is the product; the forms it serves are document kinds and compile targets on top of it. Why: the spine generalises past fiction, and widening the forms it serves is cheaper than forking the studio. `ARCHITECTURE.md` §0 and `AGENTS.md` say so; `README.md` and the landing page widen when the first slice ships. [owner 2026-10-25]
- The specs in `docs/architecture/` are the contract; where code and spec disagree, the code is wrong until the spec is deliberately changed and recorded here. Why: one source of truth for builders and reviewers. [owner]
- Collaboration and sync stay out of the local version. Why: they need a server, which the hosted instance on the roadmap will provide. [delegated]
- No AI feature is gated, metered or sold through credits. Why: the writer already pays their provider directly. [owner]

## Project format and storage

- A project is one folder: `caotang.json`, `caotang.json.bak.1..3`, `coherence.json`, flat `docs/`, `codex/`, `assets/`, `exports/`, `sessions.jsonl`. Why: one canonical layout, navigable without the app. [delegated]
- Document files are named by opaque id (`n_` plus 10 Crockford base32 characters) in a flat `docs/`; the tree lives in the manifest. Why: renames and moves never touch disk or sync history. [delegated]
- Loaders ignore unknown files in a project folder, never error. Why: sync services and editors drop stray files. [delegated]
- `caotang.json` is pretty-printed with a fixed key order and one tree element per line, no column padding. Why: readable, minimal git diffs. [delegated]
- `derived.wordCounts` is written one entry per line, keys sorted, and is rebuildable and never a reason to reject a manifest. Why: a reorganisation leaves the block byte-identical. [delegated]
- The manifest identifies itself with `app: "caotang"`; any other value is refused as "not a Caotang project". Why: never guess at another app's file. [owner]
- Caotang reads no file or store from before the rename, and nothing converts them. Why: a clean break. [owner]
- `formatVersion` is an integer starting at 1; a newer version is refused with a clear message and nothing written; an older one migrates in memory first. Why: never guess-upgrade; a failed migration leaves the project untouched. [delegated]
- A refused manifest (another app, or a newer format) is not offered the recovery ladder. Why: a rebuild would write this build's format over another build's file. [delegated]
- `CAOTANG.md` (the writer's standing instructions; `AGENTS.md` is read instead only when it is absent, never both, and never written) and `memory/` (the agent's notes: `MEMORY.md` plus one Markdown file with front matter per note) are plain files at the project root, carried by the folder, the `.caotang` bundle and the browser store. A note that does not parse is kept as it is, never rewritten or deleted; a file that is not UTF-8 is held back whole. Story facts stay in the codex: a note titled with a codex name or alias is refused, naming `codex.write`. Why: the files are the writer's to read and edit anywhere, and each fact has one home. [delegated]
- Additive fields and files (codex, coherence, filters, goals, recipes, media kinds, EPUB metadata, `CAOTANG.md` and `memory/`) join format v1 without a version bump. Why: versions migrate real data, not spec growth. [delegated]
- Unknown manifest fields are kept in memory and dropped on the next save, with a notice naming each field. Why: explicit beats silent divergence; the manifest is not an append-only log. [delegated]
- Unknown status, label, kind or node type values are kept and shown as "unknown", never dropped. Why: unknown nodes may hold irreplaceable text. [delegated]
- No secrets ever go into a project, a bundle or an export: provider keys, URLs and MCP tokens live in app settings. Why: projects get zipped, shared and committed. [delegated]
- Each document body carries YAML front matter with node-local facts only (`id`, `title`, `status`, `label`, `keywords`, `synopsis`), never structure. Why: redundancy for recovery without rewrite churn on every move. [delegated]
- Front matter is read and written by an in-house codec for the specified subset; `>-` for a one-line synopsis, `|-` when it has line breaks. Why: no YAML dependency, and a byte-exact round trip. [delegated]
- The store writes and reads bodies as bytes, with no line-ending normalisation. Why: the file and the in-memory state must agree. [delegated]
- Body files follow the node kind: prose `docs/<id>.md`, screenplay `docs/<id>.fountain`, dialogue `docs/<id>.ink` (raw Ink, no front matter). An older `.md` still loads; the next save writes the kind's file. Why: each file is valid in its own format. [delegated]
- One file per scene is mandatory; there is never a single-manuscript document. Why: the editor's performance ceiling is visible DOM nodes. [delegated]
- Scenes have no title heading in the body; compile inserts headings from node titles; `***` separates scenes within a document. Why: titles are structural, bodies stay paste-agnostic. [delegated]
- Notes stay in the manifest, up to 50,000 characters per node. Why: simplicity; split to files only if real projects need it. [delegated]
- Sibling order is gap-encoded (steps of 10), renormalised only when needed. Why: a move rewrites one node's order. [delegated]
- Orphan body or codex files are imported as "Recovered" items under the manuscript, never deleted. Why: content is irreplaceable. [delegated]
- Before a manifest is overwritten it rotates to `caotang.json.bak.1..3`; recovery tries them in order, then offers a rebuild from front matter with explicit consent, and keeps the corrupt original as `caotang.json.corrupt-<timestamp>`. Why: recovery depth should be automatic and boring. [delegated]
- A recovery or rebuild is offered in a dialog that names the copy it would open; a rebuild needs its own yes. Why: the writer decides what gets written. [delegated]
- An MCP host's elicitation dialog stands in for the app's recovery dialog, but only when it names the exact source file and the loss and the folder is unchanged since the offer; a rebuild needs its own second confirmation naming the loss of folder structure and vocabulary; a host that cannot elicit is sent to the desktop app; recovery tools exist only with `--allow-writes` (read-only `project.recover` always shows the offer); a refused manifest still gets no ladder; no CLI flag counts as a yes. Why: the writer decides what gets written, and the corrupt original is always kept as `caotang.json.corrupt-<timestamp>`. [delegated 2026-10-22]
- Document and codex files are written before the manifest; a deleted document's file is removed after the manifest that stops naming it. Why: a crash leaves an orphan the next load recovers, never a dangling reference. [delegated]
- A save writes only the body and codex files whose text changed; the manifest is written every time. Why: never rewrite a file another program may have edited. [delegated]
- A save into a project folder compares the `caotang.json` text and a SHA-256 digest of every document and codex file with what the session last loaded or wrote, rechecks each file just before writing it, and refuses with a question naming each changed, removed or added file. Why: nothing is overwritten silently. [delegated]
- The folder question reads: title "Some documents in this folder changed since Caotang last saved them"; the file list; "Saving writes this tab's version over them. The folder's version is kept first, in .caotang-backup in the folder…"; choices Save as a new folder…, Save over them, Cancel. [owner]
- Saving into a folder that holds another project asks first and says the `caotang.json` is backed up and each document it replaces is copied to `.caotang-backup`; choices Save as a new folder…, Save over it, Cancel. [owner]
- A project remembers its folder handle; reopening is one click, and a mismatch asks whether to use the folder's version, keep the browser's and save it to the folder, or open a separate copy. [owner]
- A confirmed folder save copies each document and codex file it replaces or removes, if its bytes are not the ones the session last wrote, to `.caotang-backup/<time>/<path>` before the write, and stops before a file it cannot copy; the newest 20 saves' copies are kept, and the directory is in no digest and no bundle. After the write it digests the folder, `caotang.json` and the lock again and reports a change made meanwhile as a refusal marked `after`; the held digests never take that change as the save's own. `coherence.json` in an open folder is written only while it is the file the app last read or wrote. Why: the browser has no compare-and-swap, so the race can be narrowed and reported but not closed, and "reported, not lost" is the claim that holds. The question shows a compact line comparison for each readable file (− in the folder, + in this tab; long changed sections are capped), and inputs and displayed text are bounded for safety, but there is no three-way merge or app-to-server control channel (#16). [delegated]
- A `caotang.json` another program removed is a question with an offer to write it back. Why: a missing manifest is not permission to recreate silently. [delegated]
- A save removes only the documents the session deleted; the whole-folder sweep is used only for recovery write-back. Why: a shared folder keeps files other writers put there. [delegated]
- A folder of a project this browser already holds opens as that project only when manifest, bodies and codex agree; otherwise it opens as a copy that cannot be saved into that folder. Why: two diverging copies must not overwrite each other. [delegated]
- Two copies are the same book when their manifests agree with keys sorted, without the derived cache, and every body agrees. Why: a precise, testable sameness rule. [delegated]
- A project is open in one tab at a time, held by a Web Lock; a second open waits a second, then is refused in words. Why: two live editors on one revision line is the failure being prevented. [delegated]
- A stale write (revision conflict) stops the tab's session: nothing more is written, and a notice offers Export a backup and Reload. Why: a stale tab must not overwrite newer work. [delegated]
- A tab whose store another tab upgraded stops, keeps its words and says Caotang was updated in another tab. Why: an old build cannot safely write a newer store. [delegated]
- A stopped tab keeps its unsaved words in local storage and offers them back as new documents, cleared only after the put-back is saved. Why: words are never lost to a stopped tab. [delegated]
- Kept words return to the chapter they came from, or to a new "Kept from a stopped tab" chapter when it is gone. [owner]
- The browser working store is IndexedDB (`caotang` project database, `caotang-assets` for images, `caotang-app` for settings and undo journals; localStorage keys `caotang.*`); every mutation is one transaction. Why: atomic by construction; OPFS and SQLite-wasm rejected on weight. [owner]
- Autosave flushes 800 ms after the last edit (configurable 100–5000 ms) and on `visibilitychange`/`pagehide`/`beforeunload`. Why: bounded loss without write storms. [delegated]
- The typing not yet saved is also kept in `localStorage` (`caotang.pending.<projectId>`), synchronously on those events, and put back or offered on the next open. Why: IndexedDB is asynchronous and a write started during teardown may not finish, while `localStorage` is done when the handler returns. [delegated]
- The writer's undo (Lane 1) survives a reload by replaying a journal of the editor's own transactions, kept in the app database (`caotang-app` v2, `editor-history`), through public ProseMirror APIs; a replay that does not reach the stored body discards the journal. Why: `prosemirror-history`'s state is private and version-fragile, and a wrong document is worse than no undo. [delegated]
- The toolbar's and Activity's Undo (the bus undo store) still last for the open tab; checkpoints survive a reload. Why: the bus's compensations hold closures and restore artifacts, and persisting them is a separate design. [delegated]
- Every mutation, undo included, bumps a per-document revision counter that never moves back and is never serialized. Why: optimistic concurrency without a diff for a non-content number. [delegated]
- One write in flight per document; a failed flush arms no timer retry, and a conflict is terminal. Why: ordered writes and honest failure states. [delegated]
- `sessions.jsonl` is append-only, one line per writing session (`startedAt`, `endedAt`, `wordsWritten`, `docIds`), never rewritten. Why: history survives everything except folder loss. [delegated]
- The session log travels with the folder; two logs merge line by line (folder lines first, browser lines it lacks after), never refused. Why: two machines on one synced folder can both save. [delegated]
- A bundle is `<name>.caotang`, a zip with `caotang.json` at its root; import accepts a zip or a folder; it never carries the `.bak` snapshots. Why: lossless both ways, opened by Caotang rather than an archive tool. [owner]
- A bundle export is refused when a document is not UTF-8, naming the document; its file is left unchanged. Why: no silent re-encoding. [delegated]
- A document file that is not UTF-8 is detected at open: a byte-order mark is taken as certain; otherwise strict decoder candidates (Windows-1252, ISO-8859-15, GB18030, Big5, Shift_JIS, EUC-KR) are scored, a clear winner is previewed and converted on approval, close candidates are shown side by side with an "Ask the AI" option, and the original is backed up to `.caotang-backup/` first. Every conversion waits for the writer. [owner]
- Opening a project calls `navigator.storage.persist()`; Settings › Data shows the persistence state and a dismissible banner offers a backup when it is not granted. Why: browser eviction is a real failure mode. [delegated]
- Write-path failures say what is safe now and the one corrective action ("your words are waiting on your device"). Why: never a bare error code. [delegated]
- Leaving a project with changes since its last bundle is a one-time, dismissible suggestion, not a blocking prompt. Why: nudges without nagging. [delegated]
- The format is written so a desktop build can promote the folder to the primary store with no format change. Why: the desktop app is on the roadmap. [delegated]
- A project gets `project.identifier.uuid` (`urn:uuid:`) once at create, never regenerated, and a `language` from the app locale if missing. Why: EPUB identity must persist. [delegated]
- An ISBN is stored as `urn:isbn:` in ISBN-13 form; an ISBN-10 is converted. Why: one canonical form. [delegated]
- Images (shot pictures, cover) are PNG, JPEG or WebP up to 16 MB, judged by leading bytes, stored by id in `assets/`. Why: content sniffing, not extension trust. [delegated]

## Editor

- The editor is Tiptap 3 (MIT core only, no cloud or paid extensions) on ProseMirror, with `@handlewithcare/remark-prosemirror` (mdast) as the Markdown boundary. Why: the agent stack is ProseMirror-native and mdast fits ownable Markdown. [delegated]
- Lexical is the documented runner-up behind the engine-agnostic `EditorApi` seam, with a defined switch trigger. Why: nothing above the seam depends on the engine. [delegated]
- All `@tiptap/*` packages are pinned to one exact version, lockfile-enforced. Why: mixed versions break peer resolution. [delegated]
- If `remark-prosemirror` goes dormant, Caotang vendors it rather than switching boundaries. Why: a Caotang-owned handler table makes vendoring cheap. [delegated]
- The schema is CommonMark core plus GFM strikethrough and images; tables, footnotes and other constructs degrade with a named warning. Why: data-loss avoidance beats schema breadth. [delegated]
- Round trip: byte-identical for dialect-conformant input, deterministic saves everywhere; foreign dialects are normalised on first save with a notice that counts what the save writes. Why: a testable bar and no silent reformatting. [delegated]
- The serialize dialect is fixed by remark-stringify options (`bullet: '-'`, `listItemIndent: 'one'`, and the rest pinned). Why: the options are the dialect contract. [delegated]
- `%%` lines and `@` mentions stay plain text outside the AST. Why: guaranteed round trip with no extra dependency. [delegated]
- Undo has two lanes: the writer's keystrokes use editor-native history; every bus text mutation applies as one transaction excluded from history, with a body snapshot. Why: Ctrl+Z never replays agent edits, and checkpoint restores are immune to cursor-history drift. [delegated]
- A restore confirmation states its scope: edits made after the turn are included, unless the plan is provably exact, when the dialog also offers to keep them. Why: no surprise losses. [delegated]
- Agent drafts stream into a separate read-only ghost editor, never as decorations in the main editor; Apply goes through the bus. Why: no decoration churn, a clean Apply path. [delegated]
- Anchor-ladder libraries: `fastest-levenshtein` eagerly, `diff-match-patch` lazily loaded. Why: the hot path stays dependency-free. [delegated]
- Prose diffs: word-mode diff-match-patch for previews; changeset rendering for in-editor review. Why: zero new dependencies. [delegated]
- Apply-then-review mode uses `@handlewithcare/prosemirror-suggest-changes` (exact pin, vendor if a needed fix is unreleased); stored bodies always hold the all-accepted text. [delegated]
- Where an approved agent edit lands is an app-wide setting, `editor.agentEditMode` (`ghost` by default, or `suggestions`), in Settings > Writing; it is never a project field. In `suggestions` mode the store is written first, the editor shows only the changed words as review marks grouped by a local turn id, stored bodies always hold the all-accepted text, a reload keeps the agent's text and says so once, and Ink and Fountain scenes are not covered. Why: how you review is a habit not project content, so the manifest stays unchanged, and the ghost preview stays the default path. [delegated 2026-10-22]
- Word counts have one implementation, in the store. Why: every surface agrees. [delegated]
- A goal's `chars` metric counts non-whitespace code points. Why: whitespace-split words mislead for CJK manuscripts. [delegated]
- Focus mode hides the binder and inspector when Settings › Writing says so; with the setting off the rails stay, and the status line says "Focus mode is on. The binder and inspector stay open, as set in [Settings › Writing]", linking to the setting. [owner]
- The Fountain Source tab: Enter at the end of a cue moves to dialogue, Enter on an empty line after dialogue starts action, Tab completes a cue from the scene's cues and codex characters. Why: screenplay typing without an element menu. [delegated]
- The Source tab has a chord per line element: Ctrl+Shift+1..9 on Windows/Linux and Cmd+Alt+1..9 on macOS, matched on the physical digit key, ignored while AltGraph is down, while composing and on key repeat, and mirroring the element menu's digits; the menu stays a working route, a chord that cannot apply says so and changes nothing, and there is no chord that creates a section (the binder is three tiers and never creates folder-in-folder). Why: Ctrl+Alt is AltGr on Windows layouts and Cmd+Shift+3/4 are macOS screenshots, so only this family gives all nine elements on both platforms without eating a typed character. (The Ctrl+Alt+F filter chord, itself AltGr+F on Windows, ignores AltGraph too since #189.) [delegated 2026-10-22]
- The Source tab routes to the scene's binder facts with two chords in the element chords' family and guards: Ctrl+Shift+S (Cmd+Alt+S) selects the folder the scene is in, its Fountain section, and focuses its binder row; Ctrl+Shift+Y (Cmd+Alt+Y) focuses the scene's synopsis in the inspector. They go to the binder rather than write `#` or `=` lines, which import consumes and export regenerates (screenplay.md §2.2), and the section chord selects rather than wraps, because the UI never creates folder-in-folder. Why these letters: with Ctrl+Shift as the family a second Shift is not available, so the synopsis takes its own letter; S and Y are absent from Chrome's Ctrl+Shift table, and in Firefox they are Take a screenshot and (on GNOME) Downloads, neither marked reserved in browser-sets.inc, so the field's preventDefault keeps them on the Source tab. Ctrl+Shift+U (Linux IBus Unicode entry) was avoided. No route is an AltGr chord: Windows reports AltGr as Ctrl+Alt, which the Ctrl+Shift family never holds, and AltGraph is refused outright. [delegated 2026-10-30]

## Command bus and undo

- One in-process bus; no module mutates project state except by executing a command. Why: safe, auditable, reversible. [delegated]
- Reads are direct store reads, never commands. Why: only mutations need gating and undo. [delegated]
- Pipeline in fixed order: validate → permission gate → apply → postconditions → undo registration → activity log → notify. Why: a refusal at any step has zero partial effects. [delegated]
- `validate` is pure and total and runs before any effect; batches validate whole and list failures per operation. Why: one bad key costs one round trip. [delegated]
- A command's params are a closed set: an undeclared key is refused with `invalid-params`, never dropped. Why: schema validation that means it. [delegated]
- Params are flat JSON; functions never cross the bus (a filter is resolved to node ids first). Why: params travel over MCP and into the activity log. [delegated]
- `execute` is synchronous; a command whose apply awaits (e.g. `mcp.invoke`) runs through `executeAsync`, which wraps the same steps. Why: synchronous callers keep their guarantees. [delegated]
- An apply that refuses on purpose throws `ApplyRefusal` with the caller's error; a refused compile writes no undo group and no activity row. Why: a refusal is not an internal defect. [delegated]
- Agent risk classes: `read` auto, `write-auto` auto and undoable, `write-confirm` only inside an approved plan or a one-step card, `never` refused. Why: one risk level per command. [delegated]
- Hard-deny, approvable by no flow: network egress beyond the configured provider and connected MCP servers, deleting nodes or codex entries, mutating provider profiles, leaving project scope. Why: some actions are never the agent's. [delegated]
- Compound tools run their sub-mutations inside their own apply and inherit its grant; an agent emitting a `never` command directly is refused even inside a plan. Why: primitives are not separately gated or exposed, except the allowlisted deferred set below, whose tools are gated as their command is. [delegated]
- Undo is compensation-based (exact inverse or captured restore artifact), never event sourcing. Why: weight without benefit. [delegated]
- One agent turn = one undo group; one user gesture = one undo group. Why: undo matches intent. [delegated]
- An undo of a body write is a write: the revision moves up. Why: a stale `expectedRevision` can never pass over newer text. [delegated]
- Turns show as "restore to before this turn" checkpoint rows, and each turn and each step has a restore menu (the project to before it, the conversation, or both for a turn); a step restore keeps the steps before it. Why: a restore point is what makes agent edits trustworthy. [delegated]
- Checkpoints have two axes and step granularity: each turn and each plan step is a restore point; the writer can restore the project, rewind the conversation (rewound turns leave L6 before the 2-turn limit applies and show collapsed), or both, and a project-only restore marks every undone turn in L6 as "restored by the writer". Restoring an older step keeps the writer's later edits only when a pure, fail-closed plan proves node-level independence (allowlisted commands, no later write to the same document, no later structural change to an ancestor); otherwise the dialog lists the later changes and takes them back as today. No agent rewind tool, nothing new persisted (#25, #66). Why: take back one bad step without re-paying for good ones, never lose typed text on a guess, and keep the planner from assuming reverted work exists. [delegated 2026-10-22]
- Checkpoint retention: full body snapshots, cap 100 per project and 30 days (both configurable), unchanged bodies not re-stored, each document's first snapshot kept while later ones exist, orphan snapshots removed on eviction; stored in IndexedDB, never in the project. Why: bounded growth with a real baseline. [delegated]
- `callId` replays within a turn return the cached result. Why: idempotent tool calls. [delegated]
- Document-writing commands carry `expectedRevision` and opt in with `guardsRevision`, checked after the gate and before apply. Why: a new writing command cannot be silently unguarded. [delegated]
- Errors use ten codes (`invalid-params`, `not-found`, `cycle`, `revision-conflict`, `permission-denied`, `hard-denied`, `limit-exceeded`, `io-error`, `postcondition`, `internal`) with a message that names the corrective step. Why: written for the model and the writer to act on. [delegated]
- A failed postcondition is never auto-undone; the undo group stays intact. Why: the harness decides retry or report. [delegated]
- Subscribers re-render from the store, never from command params. Why: one source of truth. [delegated]
- Every executed command is logged with human titles, issuer, turn and undo group; the log exports as Markdown. Why: an auditable trail in the writer's words. [delegated]
- Every agent write is named in the writer's words on the Undo button and in the activity log. Why: the writer can tell what will be undone. [delegated]
- The registry is the single declaration seam: 60 command names, tabulated in command-bus §9. Why: one place to add a command, enforced by the compiler and a parity test. [delegated]
- Whole-manuscript and partial compiles are two commands: `export.compile` (manuscript or a saved recipe) and `export.compileSelection` (named nodes). Why: an omitted scope must never silently mean "everything". [owner]
- `project.deleteNode` is UI-only with a confirm dialog; codex deletion is UI-only too. Why: destructive operations stay with the writer. [delegated]
- The fixed roots (root, manuscript, research) cannot be moved or deleted; the project root is refused as a parent; the manuscript and research roots cannot be renamed. Why: the binder shows them under fixed names. [delegated]
- The bus refuses a new document directly under the manuscript; existing ones still load and move; the media menu's entries appear on chapters only. [owner]
- `updatedAt` is stamped by rename, metadata, synopsis, notes and body writes, never by moves. Why: date filters mean content changes. [delegated]
- Removing a vocabulary term detaches the items holding it, and one undo restores both. Why: no dangling ids. [delegated]

## Agent and tools

- The agent works in a plan → act → verify → report loop; multi-step work shows a plan card approved once. Why: batched confirmation. [delegated]
- Plan cards are editable before approval; the edited card is the executed plan, and dropping or retargeting a step flags its dependents. Why: plans are data. [delegated]
- Generated text appears as a preview with Apply / Retry / Discard; in the app, in Ask, prose is never applied without preview. Over MCP, the host's confirmation of a call whose arguments are the prose stands in for the preview (`scene.apply`, with the mode preconditions and the body snapshot). In Accept edits and Auto the draft still streams into the scene's ghost region, and the mode applies it at once. Why: the loudest agent-UX failure is auto-apply, and a mode is the writer's own choice to take it. [delegated]
- The agent has four permission modes: Plan only, Ask (the default), Accept edits and Auto, with per-turn and per-session budgets. A mode answers the cards of native tools as shown. There is still no classifier and no per-primitive approval toggle (fine-grained rules belong to the allow/ask/deny layer), and no bypass: an external write, a card with a refused, stale or cut step and every hard-denied command reach a human or the bus gate in every mode. The mode lives in app settings and a per-panel pick, never in `caotang.json`; it is printed on every turn and checkpoint row, and a card a mode approved carries an auto-approved badge. Why: one card per plan is the right default and a tax on a writer who trusts a run, and the budgets, the undo group and the checkpoint make that trust cheap to take back. [owner]
- Agent rules: allow/ask/deny per tool and per binder subtree (node-id scope), evaluated in the harness before the bus in the order deny, ask, allow, first match by effect and not by specificity, with the bus gate unchanged. ## Coherence

- Two check classes: deterministic checks with zero model calls that fire only on writer-declared expectations, and a model review shaped as a four-stage evidence pipeline. Why: arithmetic solves what it can; an undeclared story is never guessed at. [delegated]
- Findings quote both passages, group by fact, and dismiss with a reason. Why: one problem, cited evidence. [delegated]
- Findings upsert by check and fact group; a dismissed finding stays dismissed; a fixed one that recurs is reported, not reopened. Why: re-runs never re-alarm judged findings. [delegated]
- Findings and runs live in `coherence.json` beside the manifest; on corruption findings are recomputed and dismissals are the accepted loss. Why: findings are derived. [delegated]
- Coherence never edits text inline and never runs while typing. Nothing starts a model call on its own, with two exceptions the writer chooses: a review the writer queues runs in the background, and a scheduled task may run a model when the writer turned that on for the task, with a `maxModelCalls` cap and its spend shown on the run record. Why: no meter on the writer's work that the writer did not ask for. [owner]
- The model review runs only after its plan (calls, tokens, first prompt, cost) is approved; a scope over 20 documents asks first. Why: the writer controls spend. [delegated]
- The review sends only the codex entries each scene's include policies select. Why: "never" means never. [delegated]
- A jump of seven story days between consecutive scenes is noted, and a scene declared a time skip, dream or mythic silences it; the threshold is one fixed number. Why: StoryLine's precedent, and a prompt to declare rather than a rule. [delegated]
- Scene metadata uses writer-declared day offsets, POV, presence and ordering; a richer constraint model is rejected for now. Why: covers the evidenced need. [delegated]
- Dismissal is a writer verdict; the agent may set a finding only to fixed. Why: judgment calls stay with the writer. [delegated]
- Codex entries are the fact store; non-entity facts go in additive `worldRules[]`. Why: no free-floating fact table. [delegated]
- A screenplay cue counts as a mention: the larger of cue count and detector count, never their sum. Why: no double counting. [delegated]
- Who knows what is declared on scenes (a character learns a fact here, acts on it there) and the ledger is derived from the declarations, not stored per character; the quick scan reports a character who knows a fact before any scene at or before it teaches them. Why: one source of truth, and a check that fires only on what the writer declared. [delegated]
- Story order for knowledge follows declared days when both scenes have them and binder order only where it is reliable; a scene in a mode with no reliable order exempts the pair, and a dream or mythic scene neither teaches nor is checked. Why: a flashback that teaches a secret must not make chapter 3 look wrong, and an order nobody declared is not guessed. [delegated]
- A screenplay scene is paired with a dialogue container only by a writer-declared optional `SceneMeta.dialogueContainer` id in `coherence.json`; the first cross-medium check, `medium.speaker-parity`, compares speakers only, at info severity, screenplay to dialogue, and never matches by title or content; a scene with no link is counted in the run note, not compared. Why: the deterministic class fires only on what the writer declared, and a guessed pairing would stop running silently; storyboard to dialogue stays open. [delegated]
- A continuity scan the writer runs in their own CI (`caotang scan`) calls no model, reads no key, and writes nothing unless `--write` is passed, so it is not background work under the rule above (as amended on #45); a model review in CI is not offered until it can sit behind the scheduled-task opt-in and call cap. Why: no meter on the writer's work, and a key never leaves the device. [delegated 2026-10-22]

## Podcasts, video scripts and web publishing

Designed and approved on 2026-10-25; the specs are [av-script.md](architecture/av-script.md) and [web-publishing.md](architecture/web-publishing.md), each with a Decisions table that gives the rejected alternatives.

- One linear timed script serves podcasts, radio and audio drama, and narrated video: they differ in which cue track is populated, not in structure. Why: the two-column AV script, the radio script, WebVTT's cue and voice span and every chapter format converge on a linear spine of segments carrying speaker turns plus timed non-dialogue cues, and audio description is a fourth discipline over the same timeline. [owner 2026-10-25]
- The script body is Markdown (`docs/<id>.md`, `kind: 'av-script'`) parsed as text, and segments are `##` headings, never binder nodes. Why: `bodyExtensionOf` already falls through to `.md`, so no new body extension and no `paths.ts` change; codex mention detection works on it unchanged; and the binder holds the container only, the rule the dialogue container sets. [owner 2026-10-25]
- The AV script is a new pure `packages/script`, not a `linear` kind inside `packages/dialogue`. Why: Ink's compiler, knots and diverts are branching machinery a linear script does not have; the stable-line-id and speaker-resolution patterns are reused instead of the parser. [owner 2026-10-25]
- Timings are seconds and frames are never stored. Why: SMPTE drop-frame arithmetic is meaningless without a declared frame rate, and every target this track writes — WebVTT, SRT, YouTube, Spotify and Apple chapters, `podcast:soundbite` — is wall-clock. [owner 2026-10-25]
- A duration is declared or estimated, and the speech rate is a show setting preset at 150 wpm for narration or 170 wpm for broadcast. Why: the measured sources disagree by use case — the BBC's three words a second for news, 160–180 wpm in the radio literature, about 150–160 for audiobook narration — so a hidden constant is wrong for half of them. The screenplay's page-per-minute rule is not carried over: the radio figure found is for double-spaced pages and is not citable. [owner 2026-10-25]
- Cues belong to the segment and carry their own offsets, the cue vocabulary is a show setting matched case-insensitively before the speaker rule, and an unknown label is never dropped: it is kept as a speech line under the typed name and reported by `av.speaker-unknown`, which offers adding it to the codex or the vocabulary. Why: a music bed, a B-roll shot and an effect do not align one-to-one with dialogue; no citable standard defines the label set; and a closed enum would drop a writer's own `BED:` or `O.C.` on load, which the unknown-tolerance rule forbids because a dropped cue is irreplaceable content. (the parse reports an unknown speaker in its notices; the `av.speaker-unknown` check is specified, not built) [owner 2026-10-25]
- Platform chapter gates live in the exporter, not the model. Why: YouTube wants at least three chapters 10 s apart, Spotify 30 s apart and Apple 2 minutes apart, so a model-level rule would have to pick one platform and be wrong for the others. (specified, not built) [owner 2026-10-25]
- The AV script track adds no agent tools. Why: nothing is derived from the script that a model must compute, so the workflow rides `doc.read`, `scene.draft` and `export.compile` enum values as the screenplay does, and the tool registry is the most expensive surface in the app. (specified, not built) [owner 2026-10-25]
- WebVTT ships before SRT, and a feed references audio by URL and never contains it. Why: WebVTT is a W3C Candidate Recommendation with a standardised voice span and Apple prefers it, while SRT has no official specification and no speaker markup; and project files stay plain text, so a folder stays diffable and a `.caotang` bundle never becomes a media archive. (specified, not built) [owner 2026-10-25]
- Widening `DialogueCoverage.kind` past `'fountain-element'` must keep and report an unrecognised kind instead of returning `undefined`. Why: `packages/storyboard/src/shot-meta.ts` drops what it does not recognise today with only a "malformed" notice that names neither the kind nor what was lost, and callers discard it; a dropped anchor is irreplaceable content. (specified, not built) [owner 2026-10-25]
- An AV script line's id lives in the body as a trailing `<!-- lineId: sl_… -->` tag minted on save, and an episode's enclosure (audio URL, bytes, MIME type) is episode metadata; an episode missing any of the three is left out of the feed and named. Why: an id re-minted on every parse would break the VO script's `lineId` column and a shot's anchor on every edit, and a feed item without an enclosure is invalid, so inventing one is worse than omitting the episode. (the id, its minting and the episode metadata are built; the feed is specified, not built) [delegated]
- The AV script parser, as built (#209), reads a label only when its colon is followed by a space, a tab or the end of the line; counts a letter in any script as a letter in a speaker label; treats a text line as unspoken (no duration, no id tag); names a bracket in the notices only when it tries to be a timing or kept one from applying, so `[laughs]` stays quiet words; sets a cue's `under` from a `(under)` modifier or text ending in the word "under"; and reads the show's `defaultSpeaker` as a narration line's speaker. The settings commands bound a speech rate at 1,000 words a minute, a cue vocabulary at 1 to 50 labels and text at 500 characters (a description 4,000). Why: `At 10:30` and a URL must not become speakers; a codex name in Chinese must resolve; a bracketed stage note is common and is not a broken timing; radio scripts write `FADE UNDER` at the end of a cue; and a bound catches a typo without constraining a style. Minting on save is a package function the episode view (S3) calls; until then nothing mints. [delegated]
- Publish metadata lives in the manifest as `tree[].publish`, not as YAML front matter in the document body, and both RSS and Atom are emitted. Why: front matter in the body would make it a second source of truth for data the manifest holds, and the editor's lossless-Markdown contract would have to learn a new block it must never drop; Atom is the IETF standard with an IANA-registered media type and unambiguous typed content, while podcast platforms require RSS 2.0. (specified, not built) [owner 2026-10-25]
- A relative `canonical` is refused at save, a document with no `publishedAt` is a draft and is omitted from a feed, and a feed's `guid` is the stable node id with `isPermaLink="false"`. Why: resolving a relative address would write a wrong absolute URL into every syndicated copy; dating a draft with the compile instant reorders the feed on every re-export; and a URL as the guid makes a slug change look like a new episode to every aggregator. (specified, not built) [owner 2026-10-25]
