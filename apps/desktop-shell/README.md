# Caotang for desktop (development shell)

From the repository root, run `pnpm install`, `pnpm build`, then `pnpm --filter @caotang/desktop-shell start`. The launcher and smoke explicitly install the pinned Electron binary if it is missing; normal workspace installs do not download it. On Linux, `xvfb-run -a pnpm --filter @caotang/desktop-shell test:smoke` runs the bundled-app smoke with Chromium's sandbox enabled. Use a host that supports the Chromium sandbox, not `--no-sandbox`.

Electron **45.4.1** is pinned exactly: it is the spike's tested Electron 45 release and includes Chromium and other upstream fixes. The exact pin keeps the renderer runtime reproducible; see #410 for upgrade validation. This patch is new enough to need a version-scoped pnpm release-age exception when added. No Electron binary is bundled into the web build.

The shell loads the root-base production web assets from `app://caotang/`, not a dev server. Same-origin scripts, styles and Workers have a CSP header in addition to the existing meta policy; the header blocks framing and keeps HTTP(S)/WebSocket connections available to the existing browser ports without relaxing CORS or Chromium's mixed-content rules. Content cannot open remote pages in the shell. Documentation links that normally open a browser tab are blocked here. The versioned preload exposes [native project folder calls](../../docs/architecture/desktop.md#native-project-folders-402) and the `os` namespace — the menu's commands, a deep link's answer, the Save dialog, the system timezone and the window's tray state — and no generic IPC.

The application menu is the page's words in the page's language: the shell builds it from a template and rebuilds it whenever the page publishes its labels and whether a project is open ([`desktop.md` §Native menus](../../docs/architecture/desktop.md#native-menus-407)). No menu item registers a shortcut the page's keymap owns, so a text field keeps its own undo; only Ctrl+O, Ctrl+, and the window's own Ctrl+W and Ctrl+Q are the menu's. `caotang://project/<id>` opens a project folder this profile has already been granted, never a path, and a folder a file manager hands the app is accepted by the same rule the picker applies — one that holds a `caotang.json` (§Deep links and folder handoff). Both arrive as commands the page answers when it is listening, and wait for it when it is not.

Compile… saves through the operating system's Save dialog, which writes the exporter's bytes once (§Native save). The system timezone is read-only and is what "today" and a task's 09:00 are counted in (§The system timezone). Closing the window hides it to the tray instead of ending the app, so scheduled task runs keep happening in the hidden renderer; the tray says that quitting is what stops them (§The tray and scheduled task runs).

Choose an empty folder when creating a project, or use **Open a folder** for an existing project. The shell remembers these folders under **Recent project folders**; the folder itself holds the manuscript. Caotang refuses to reopen a missing or read-only folder rather than showing an older mirror. Projects stored only in this Electron profile remain available: choose **Copy to a folder** to create a separate project while keeping the original. The shell also remembers window size and maximized state and opens one instance per profile. ## Packaging (#401)

`pnpm --filter @caotang/desktop-shell run package:linux` builds an AppImage (and `package:linux:dir` an unpacked app) from the current tree; `package:win:dir`, `package:win:installer`, `package:mac-arm64` and `package:mac-x64` are the other targets, each run on its own platform. Every package stays unsigned, and [`.github/workflows/desktop-release.yml`](../../.github/workflows/desktop-release.yml) builds them from a `desktop-v<version>` tag whose version equals this package's, writing a `SHA256SUMS` file beside each. [`docs/INSTALL.md`](../../docs/INSTALL.md) is what a writer reads first. Electron's fuses are applied to the packaged binary (no Node mode, no `NODE_OPTIONS` or `--inspect`, the ASAR validated against integrity data in the executable), and the studio travels as `resources/desktop/dist`, which is where `src/main.mts` looks once its own `dist/` is inside the archive.

Provider and MCP calls: provider requests are made by the main process, so a provider that sends no CORS headers answers the app where a browser could not read it (`docs/architecture/desktop.md` §Native provider calls). That port is not a general fetcher: https only, to the origins of the provider profiles the app holds, never this computer, and capped in every direction. The local model servers keep the browser's path. Settings therefore shows no "Desktop app or hosted only" badge here: that badge would be a browser's limit, and this app does not have it.

There is no keychain, stdio MCP, code signing or update check yet. Keys and the project's own MCP server are #404 and #406, and land in this file with them.
