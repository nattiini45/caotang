# Changelog

All notable changes to Caotang are recorded here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the version follows the `version` field in each package's `package.json`.

## Unreleased

### Added

- **Footnotes in the editor.** Markdown footnotes (`[^1]` in the text, `[^1]: The note.` at the end) are now footnotes rather than plain text: a scene that has them opens without a warning and saves them byte for byte. **Ctrl+Shift+6** (Cmd+Shift+6), or **Add footnote** under the editor, adds one at the caret and puts the caret in its note at the end of the scene; the same keys in a note go back to the text, and a click on a number goes to its note. Numbers follow the reading order and renumber on every change; named footnotes keep their names. Deleting a number keeps its note and asks whether to delete it too. A screen reader reads a number as "Footnote 2", and hovering shows the note. A scene whose footnotes were in another order or place is put in this order once, with one notice. Agent rewrites that keep a `[^1]` keep the footnote. Exports are unchanged: they print `[^1]` and the note as text, and a one-word note, which an export used to drop, is now kept (#270).

- **An Interface setting: Classic or Modern (Preview).** **Settings › Appearance › Interface** chooses between **Classic**, the interface Caotang has had so far, and **Modern (Preview)**, a new interface that is still being built and for now looks almost the same as Classic. Caotang opens in Classic until you choose, whether you have used it before or not. The choice is kept in this browser, beside the theme, and applies at once, without a reload. Modern's styles load only while Modern is on, so Classic downloads nothing more.

- **Tools declare what they answer.** Every tool of Caotang's agent now states the shape of its result as well as its arguments, and Caotang's own MCP server tells a connected AI tool that shape in each tool's `outputSchema` (a result, or the answer to a confirmation you declined), so a tool that types its output can read an answer before it asks. In the other direction, an `outputSchema` a connected server declares is part of what your approval of the tool covers (a server that starts to declare one, or changes it, is a changed tool to review again, and a tool that declares none keeps the approval it has), and an answer whose `structuredContent` does not match it is refused with the paths that differ, saying the tool already ran. The structured part of an answer counts toward the 8,000-token limit. Nothing about this is visible while you write.

- **Progress and limits on long tool calls.** A connected tool that reports progress shows it on the call's card: a bar when it says how much there is, a count when it does not, and its own words as plain text. A call that is silent for two minutes fails as before, but each report starts the two minutes again, and no call runs past ten minutes. **Stop** now reaches a call that is running, a write included, and tells the server. A call that was stopped or timed out may already have done part of its work on the server, and the card, the turn's summary, the step's restore note and the run's step count say so. Progress reports are also in the agent trace.

- **Review agent edits in place.** **Settings › Writing › When you apply an agent edit** can be set to **Mark the changes for review**. An approved draft, continuation or rewrite then keeps its new text in the scene and marks only the words that changed, with a review bar (Previous, Next, Accept, Reject, Accept all, Reject all) under the scene and **Accept all** and **Reject all** on the turn's card. The agent's text is already saved when the marks appear, so accepting changes nothing in the file and rejecting a change is saved as your own edit, which Ctrl+Z takes back. The default stays the draft preview.

- **Step checkpoints and rewind.** Restore the project to before any step of a turn, and rewind the agent's conversation separately from the project. Each finished turn in the agent panel has a **Rewind** menu: restore the project to before the turn, rewind the conversation to before it, or both, and each step that changed the project has a menu to restore to before it, keeping the steps before. When your later edits are in other scenes, the dialog offers to keep them; otherwise it lists what the restore also takes back, as before. A rewound turn and the ones after it fold under "Rewound - not sent to the model" and are no longer sent to the agent; the project is untouched and their checkpoints still work. The turn's instruction goes back into the Intent box, or is offered as "Use the old instruction" when the box already holds your draft. A turn whose project changes you restored is now described to the agent as restored by you, so it does not plan as if the work were still there, and so is every later turn the restore took back.

- **Drafting with an AI tool's own model, over MCP.** The MCP server lists `scene.brief` and `dialogue.brief` in every mode: each returns what the agent would send its model for a scene or a dialogue container (the same messages the agent sends in the first turn of a session with the default context budgets, with your `CAOTANG.md`, the codex entries the scene mentions and the story so far), how to answer, and a `briefId`. With `--allow-writes` it also lists `scene.apply` and `dialogue.apply`, which take the text the tool's model wrote and put it in the project through the checks `scene.draft` and `dialogue.draft` use: draft only into an empty document, continue at the end, rewrite only a selected passage, Ink that compiles. The host asks you first, naming the document and the change in words, and one undo restores it. An id goes stale after 30 minutes or when the document changes. The server still holds no key and makes no model call. The server now lists 10 tools read-only and 26 with writes (it was 8 and 22), and 9 tools ask for confirmation. Parts of the project a read rule keeps from the agent stay out of a brief.

- **Prompt-injection guards.** Text from a connected server is marked as data in every prompt that carries it, invisible characters are shown, a turn that read such text asks before every change, and an outside call that would send your manuscript says so. What a connected server answers (an error included), and the description of a tool it offers, reach the model in a marked block with an id for that turn, and text inside it cannot close the block; hidden characters (tag characters, zero-width and direction controls) are shown as `\u{…}` in what the model reads, while the card and the activity log keep the text as it came. `CAOTANG.md` and the memory index are marked as project files in the same way. The agent's instructions (system prompt v2) say what the marks mean. A turn that has read such text shows a one-step card for a change it would have made at once, and no permission mode approves its cards. An outside call whose arguments repeat twelve words in a row from a document or a codex entry names the document on its card, and Approve asks twice. Every import (a document or codex entries through the agent, a script, an Ink story or a Twee story) notes passages that read like instructions to an AI, and imports them as they are.
- **Agent trace.** Every prompt, reply, tool call, tool result and timing of a turn, in a Trace view beside Activity, kept only in the open tab and exported on request as a JSONL file (`caotang.trace/1`, with OpenTelemetry’s GenAI field names). **Export trace** saves one turn or all of them, and **Leave out manuscript text** replaces every text with its length. The coherence and encoding reviews, which run outside a turn, are shown in their own group. Keys are removed on a best-effort basis; the trace is never saved in a project, a backup or the browser’s storage, and nothing is sent anywhere. **Keep agent traces for this tab** turns it off. A turn run in an eval can write the same trace, byte for byte the same each time (developers).

- **Macros.** Under a plan you approved, **Save as macro…** keeps its steps with the values you tick left to fill in. **Settings › Macros** lists the project's macros and runs one: fill in its values, read the steps it will take, and approve its card, as for any plan. A macro of reads runs without a card, and one undo takes a whole run back. The project's rules and the permission mode hold a macro's steps as they hold a plan's. A macro is kept in the project (`macros[]` in `caotang.json`), is checked again each time it runs, and holds data only: the agent cannot see, run or save one, and the MCP server lists none and keeps them when it saves. `macro.save` and `macro.delete` are two new commands, writer-only.

- **A Preview in the Export dialog.** Before you compile, the dialog lists what the compile will write: the title page, each chapter with its scenes and words, the totals, and every document it will leave out, in the compile log's words. It follows the recipe, the format and what to export, and its counts are the ones the compile reports. It writes nothing and adds nothing to Undo. The screenplay, dialogue and storyboard formats show their counts, or the reason Caotang would refuse the compile. This is the Draft. **Proof** beside it shows the file the compile will write, as text, for Markdown, plain text and the other text formats; Word, EPUB, the spreadsheets and the PDFs have no Proof yet, and the dialog says so.

- **A narrow layout for phones and tablets.** Below 960 px the shell is one column: **Binder** opens the binder, Codex, Activity, Trace and Findings as a drawer, **Inspector** opens the inspector as a bottom sheet, and **More** holds the rest of the toolbar. Each panel closes by its **Close** button, a tap outside it or Escape, and takes focus when it opens. Buttons, tabs, rows and fields are at least 44 px square, each binder row has an **Actions for …** button where a touch screen has no right click, and the page does not scroll sideways at 375 or 768 px. The corkboard, storyboards, dialogue containers (the branch graph and the Ink text), the screenplay Pages view, **Settings › MCP & tools** and every compile format but Markdown and plain text say **Open on desktop** in place of the view. The storage banner words its warning for a phone. At 960 px and wider nothing changes.

- **Hooks.** A rule you write down and the agent is held to: a check that runs before and after each of the agent's calls. A hook can look for words (a literal word or phrase, whole words only, in any script), require a status, bound a word count, or run the continuity checks on what a call touched. It can warn, stop the step, or add a note the agent reads with the result. A step a hook stops shows its reason beside the disabled Approve, and nothing is written. A hook never approves anything and never changes a call: the rules, the permission mode and the confirm cards decide as before, and only you can add or remove a hook (the agent has no way to). A hook that cannot run warns that the step was not checked. Hooks live in the project file under `agent.hooks` and travel with the folder and the `.caotang` bundle; a hook that would run a program or call a model is dropped when the project opens, with a notice that names it. Every hook that spoke is in the turn's report and in the Trace view. Details in [architecture/hooks.md](docs/architecture/hooks.md).

- **Prologues and epilogues.** A scene's **Day offset** can be before day 0: type a minus sign, and the inspector reads it back as "Day −14, before day 0". Days run from −10,000,000 to 10,000,000. A new **Story part** select declares a scene, or a whole folder, the **Prologue** or the **Epilogue**; a folder's part covers the scenes inside it unless a scene declares its own, and the inspector says which folder covers a scene. The scan no longer notes a long jump into the epilogue or out of the prologue as a gap; two scenes inside one part are still compared, so two epilogue scenes a month apart still draw the note. Every other check (order, follows, folder spans, overlaps and what a character knows) reads days before day 0 like any others, and a part is never guessed from the days or the binder. `coherence.json` keeps its format: a file written before loads unchanged (#175).

- **A record of every picture, and no location in photos.** Each picture in a project now has a record in `caotang.json` (`assets[]`) with its SHA-256, size and pixel size, and room for a caption, alt text and tags. Adding a cover or a shot's picture removes a photo's GPS location, maker notes and serial numbers without re-encoding it (the Orientation stays), and the same picture added twice is stored once. A HEIC photo is converted to JPEG where the browser reads HEIC and refused elsewhere with what to do; an SVG is refused. A project made before this gets a record for every picture it uses when it opens, written with the next save. Three new commands, `asset.import`, `asset.importBatch` and `asset.setMeta`, and the pure `@caotang/pictures` package; the picture board and the links to chapters and scenes are not built yet (#152).
- **Real bold for Chinese, Japanese and Korean on the contact sheet.** Text in those scripts (and Greek and Cyrillic, which the same font prints) in the storyboard contact sheet's title, page label and shot-number chip now prints in Noto Sans Mono CJK SC Bold, a designed bold weight, instead of the regular weight thickened by a stroke, so dense characters such as 鬱 and 龘 stay open and every PDF viewer shows the same weight. The Bold is fetched only when one of those places holds such text, from a small file of everyday characters (2.0 MB) or, when a rarer character needs it, the full font (10.8 MB). A sheet with no such text in those places is unchanged, and when the Bold cannot be loaded the stroke is used, as before, and the compile log says so. Black-and-white emoji there keep the stroke, and Arabic, Hebrew and Devanagari stay in their regular weight (#253).
- **Prompt caching.** On Anthropic's Claude models and OpenAI's, the agent marks where the unchanging start of each prompt ends, so the provider can reuse it on the next call of a turn for a tenth of the price or less, and keeps that start the same between calls: the word counts that change as you type now come at the end of the prompt, under **Status**, and a tool the agent loads mid-turn is added after the others. **Settings › Providers** has a **Prompt caching** switch per profile (on by default) and, for Anthropic, how long the provider keeps a cached prompt (5 minutes, or 1 hour at a dearer write). A turn's report says how much of its input was read from the cache and why a call probably missed it, and a batch's cost estimate prices the reused start at the cache rate. Providers that do not state how they cache are sent exactly what they were before.

- **Groundwork for podcasts and video scripts.** A project can hold a show folder (`kind: 'show'`) and its episodes (`kind: 'av-script'`, a Markdown body), with the show's settings (speech rate, cue labels, feed details) and each episode's (audio URL, size and type, episode and season) kept in `caotang.json` and changed by two new commands, `script.setShowMeta` and `script.setEpisodeMeta`. The new `@caotang/script` package reads an episode's segments, speakers, sound cues, line ids and timings, declared or estimated at 150 or 170 words a minute, and its runtime total. Nothing in the app shows an episode yet (#209).

### Changed

- **Bold CJK in the PDFs: one stroke for both.** The stroke that prints Chinese, Japanese and Korean text and black-and-white emoji in bold in the contact sheet's title, page label and shot-number chip now lives in the font module both PDFs share, so a bold heading in the screenplay PDF would get the same weight. Its width, 0.025 em, was also checked in Poppler at 8, 11 and 14 pt, beside pdf.js and MuPDF. The sheets it writes are unchanged. It is now the fallback for the real Bold font (#253).
- **A plan the model's output limit cut off says so.** When the agent's planning reply is cut off at the model's output limit and cannot be read, the agent is told its reply was cut and asked for a shorter one, instead of being told it sent malformed JSON, and the retry asks for twice the output cap, never above what the model advertises. A second cut ends the turn with a question about the cut (naming the output limit when the reply reached it), not about the model-call limit. On a model that calls tools natively, a plan whose reply was cut after its calls arrived whole is shown on its card as cut, since it may be missing steps, and runs only when you approve it as it is.
- **Z.ai in the browser.** Z.ai is no longer greyed out as unreachable from a web page: its chat route now answers a browser request. It is marked as untested rather than supported, because Z.ai does not document browser access.
- **Continuity scan in CI.** The `continuity-scan.yml` template is pinned to release v0.1.0 and the SHA-256 of its `caotang.mjs`, so it works as copied instead of stopping on placeholders. `server.json` carries the SHA-256 of the v0.1.0 `.mcpb`, for the MCP Registry entry.
- **Content-Security-Policy.** The built app's policy now says `frame-src 'none'`, so it refuses every frame, as its comment and this changelog already said; before, it fell back to `default-src 'self'` and allowed frames from its own origin. Nothing in the app shows a frame. The README's Self-hosting policy carries the same directive; a host that sends the policy as a header should update its copy.
- **Releases list themselves in the MCP Registry.** The release workflow now lists each release in the MCP Registry after it creates it, signing in with GitHub OIDC, so the maintainer no longer signs in or runs `mcp-publisher` by hand. It takes the `.mcpb` hash from the release's `SHA256SUMS`, and an existing release such as v0.1.0 can be listed by running the workflow by hand with its tag.
- **Every context budget in Settings.** **Settings › Context** now lists every part of the prompt that has a budget: the project summary, the structure around the focus document and the recent turns of the conversation join your instructions, the codex, the story so far and the focus document, each with its default. It also shows, read-only, how much room is kept for the reply: the reply cap of the profile the Chat role runs on, plus the thinking its level adds.
- **Numbers and dates in your region's English.** Counts, token figures, prices, dates and times now all follow one rule: the interface's language (English) with your system's region when your system is set to English, and US English otherwise. On a British, Australian or other English system the footer and inspector dates stay day first ("31 Oct 2026"), and run, activity and request-log times use that region's clock; on a US English system they read month first ("Oct 31, 2026"); on a system in another language, times that used to follow the system now read in US English. en-GB systems now see en-GB numbers, which group as before ("12,000"); a few English regions group their own way (India: "12,00,000"), and a provider price reads "US$3" outside the US. Codex names, characters and keywords sort by the project's language, without case or accents and with numbers by value, so a Swedish project puts Å after Z and "Chapter 9" comes before "Chapter 10" (#192).

### Fixed

- **Final Draft scripts keep their nested text.** A Final Draft (`.fdx`) file no longer loses or swaps text where it nests one paragraph inside another (issue #264). A scene's summary no longer replaces its heading: it becomes the scene's synopsis. An inline script note no longer replaces the line it sits on, and the notes list at the end of the file is no longer imported as a line of action: notes, and runs of hidden text, come in as Fountain notes (`[[…]]`), which do not print. A dual-dialogue pair that Final Draft, Fade In and other writers wrap in a paragraph comes in side by side, with Fountain's `^`, as an unwrapped one did. A scene length written as a fraction of a page (`3/8`, `1 3/8`) is read in eighths. Bold, italic and underline in action and dialogue become Fountain emphasis (`**…**`, `*…*`, `_…_`); strikeout is dropped and counted, and the text is kept. Before anything is written, **Import script** now shows what a Final Draft file holds: its scenes and sections, how many script notes and dual-dialogue pairs it keeps, and every notice. The reader reads the file in one pass, in time linear in its size.
- **Shortcuts on non-Latin keyboard layouts.** Ctrl+Z, Ctrl+N, Ctrl+Shift+F, Ctrl+Alt+F and the screenplay's Ctrl+E now work on a Russian, Greek, Hebrew, Arabic or other non-Latin layout: when the key types a letter outside the Latin alphabet, the shortcut follows the physical key, the one where the letter sits on an English keyboard. On Latin layouts the letter printed on the key still decides, so Ctrl+Z stays the key labelled Z on QWERTZ and AZERTY. AltGr, which Windows reports as Ctrl+Alt, is never taken as a Ctrl+Alt shortcut, so it always types its character (`@`, `{`, `[`, `€`).
- **Typing Chinese, Japanese or Korean with an input method.** The Enter that confirms a candidate no longer acts on the field: it does not commit a codex name or chip, add a keyword, save a Project panel field, blur an inspector or plan-card field, create a skill, add or save a vocabulary entry, finish an inline rename, commit a queued message's edit, send or complete in the agent's Intent box, or rewrite a screenplay cue. The Enter you press after the candidate is chosen does what it did before (#188).
- **Plan cards show the model's window warning and the cost of a draft.** A drafted step's prompt is now measured against the window, reply cap and price of the profile and model the turn runs on. Before, the app never passed those to its prompts, so a plan card could not warn that a prompt was longer than the model's window, showed no cost for a draft (only a coherence review's own estimate), and counted the reply at 4,096 tokens whatever the profile's cap. The prompt preview in **Settings › Context** uses the Chat role's model the same way.

### Known limits

- Footnotes are exported as their Markdown text (`[^1]`, `[^1]: …`) until Word, EPUB and PDF footnotes land (#271), and a compiled Markdown file keeps each scene's own numbers, so two scenes can both have a `[^1]`. Footnote words count toward the scene's word count; counting them apart, behind a setting, is not built. A copied footnote number pastes as its digits.
- A Final Draft script note from the notes list is placed at the start of its `Range`, read as a character offset into the script's text; that reading is not confirmed against Final Draft, and a note it cannot place goes to the end of the last scene with a notice. A note's colour, author and date are not kept. A bare whole-number scene length is read as pages in a file that writes fractions and as eighths in one that does not (Caotang's own export writes eighths). Scene titles and colours, outline elements, cast lists, revisions, tags, the Beat Board and alternate dialogue are still not imported (#265).
- Tool results are checked against their declared shape in Caotang's own tests and not while you write, and twenty-five of the agent's tools still allow a key their declaration does not list. A connected tool that declares an output schema this build cannot check (one that uses `unevaluatedProperties`, for example) has its answers refused.
- The narrow layout is tested in Chromium with touch input at phone and tablet sizes (a Pixel 7 and a 390 by 844 viewport), not in WebKit and not on a phone. Typing with the on-screen keyboard, selection handles, input methods, and an iPhone or Android browser clearing stored data are unchecked, so the build is not called iOS or Android supported. Nothing syncs and there is no installable app or offline mode beyond the browser's own copy, so a phone's browser is not a safe home for a book: export a bundle.
- Changes marked for review are kept only while the tab is open. A reload or a closed tab keeps the agent's text and says so once on the next open; Restore project to before this turn is still there. The marks cover prose scenes only, not Ink or Fountain, and a change to the setting applies to the next document you open.
- Hooks are written by hand in `caotang.json` until Settings › Hooks ships, and run only before and after the agent's calls: not around a compile, a save or a turn. A note a hook adds after a write reaches you in the report and the Trace view and not the agent, since a write ends the turn. Hooks run no program and call no model, and a pattern is a literal word or phrase, not a regular expression.
- Macros are run by the writer only. The agent cannot call one, a macro cannot join a value into text, and a script macro, a macro shared across projects and a macro of an external tool are not built. A `/` command that runs a macro is not built either.
- The guards make injected instructions visible and ask before acting on them; no model can be made immune to prompt injection. An imported document is not marked: after the import note, the agent reads it as it reads your own writing, and a setting to treat imported text as outside text is not built.
- Writing through an AI tool's model covers scenes and dialogue only. The host's confirmation names the document and the word change, not the text, and it is not a review. How a real host shows it has not been seen, and a run of changes is as many questions: staging them as one change is specified and not built.
- A project with a day before day 0 or a story part, opened in a build from before this one, loses them: the older build drops a negative day when it loads the project (its load report says the day offset was malformed) and drops the story part when it next saves (its load report names a field it does not know). The web app is always the current build. The timeline view that draws the prologue and epilogue as their own zones is not built yet.
- Agent traces are kept in memory for the open tab and are gone after a reload. They hold your prompts and manuscript text, so the export is yours to keep safe, and the removal of keys from it is best-effort. A trace keeps the newest 25 turns and 16 MB, and cuts a record longer than 64 KB.
- The picture registry has no screen yet: captions, alt text and tags are set through `asset.setMeta` only, and the once-per-batch question about photos above 24 megapixels or 8 MB (keep the originals, or store copies 4096 px on the long edge) is asked by no screen, so every picture keeps its original. A picture file an undo left behind is reused when the same picture is added again before a reload; after a reload it stays until the sweep is built. The MCP server and the command line do not yet give an older project its records; the app does when it opens it.
- Nothing shows a request's size as you type it in the Intent box, or how full the model's window is during a turn, and a document or codex entry cannot be added to or left out of one request. A drafted step's prompt and size are on its plan card, and a scene draft's in Settings › Context (issue #69).

## 0.1.0

The first public version: a free, local-first writing studio for novels, scripts and story worlds, with an agent that works through the app's own commands on the writer's own provider key. The version is 0.1.0 rather than 1.0 because the project file format may still change.

### Added

- **Projects.** Create, open, rename, import and remove projects in the browser, and set each project's title, author, language, ISBN and cover. Export a project as a `.caotang` bundle and import one back. In Chrome or Edge, open a project folder or save to one. A folder opens as its project and saves back to the folder. A folder of a project this browser already keeps opens as that project when it holds the same book; a different version opens as a second copy, which cannot be saved into that folder. A save asks first when the folder has changed since Caotang last saved it, and before it writes back a `caotang.json` that another program removed. A project whose project file will not load can be rebuilt from its documents, after a question; a project file that names another app or a newer format is refused, with nothing written. A folder's writing sessions come into the browser with it, and an open says what it noted, in whole sentences. A project is open in one tab at a time: a folder of a project another tab has open is refused, and a tab stops saving, and says so, when Caotang was updated in another tab.
- **Saves.** A save that Caotang would make over a folder that changed outside it is a question, not a silent write. The question names the files another program changed, a lock file left by the MCP server is a question too, and nothing is written until the writer answers. **Save over them** and **Save over it** first copy each document and codex file they replace, if another program wrote it, to `.caotang-backup/<time>/` in the folder, and the status line names that folder. The copies of the newest 20 saves are kept. The backup is in no bundle and no export. A save that cannot make a copy stops before it replaces that file. A file that changes between the save's last check and its rename stops the save before that file. When a save has finished, the folder's files, `caotang.json` and lock file are read again: a file another program changed while the save wrote, or a lock that appeared, is named in the question, and the next save asks about it. The findings file `coherence.json` is written into the open folder only while it is the one Caotang last read or wrote; a file the MCP server changed is not replaced, and the Findings tab says so. Before a confirmed overwrite, the question shows a compact line comparison of each readable changed file (`−` in the folder, `+` in this tab); long changed sections are shortened, and oversized inputs show a brief notice; the backup keeps the full file. There is no merge.
- **Binder.** A manuscript of chapters and scenes, and a research section that is never compiled. Drag to reorder, rename, set a status or a label (statuses and labels can be added, in one editor), delete and undo. A filter bar with text, status, label, word-count, keyword and recent-date criteria, and saved filters. A footer with word goals, a sprint timer, a writing history (its Today includes the open sitting), and the words a stopped tab kept. New document goes in a chapter: with no chapter selected it says so, and the empty editor offers New chapter. After a delete, focus goes to the item that takes the deleted one's place.
- **Corkboard, inspector and editor.** Cards in three sizes. The inspector holds the synopsis, notes, keywords, status and label, codex links, scene declarations, and a folder's goal. The Markdown editor saves as you type, with word counts, a daily target and focus mode. Agent drafts appear in the scene as a preview before they are applied. Focus mode says in the status line when the panels stay, and its button leaves the mode. The window is laid out for at least 960 px; below 1100 px the toolbar wraps onto a second row.
- **Undo across a reload.** Ctrl+Z in a scene still undoes your typing, one burst at a time, after a reload or a closed tab. The history is rebuilt from a journal kept in this browser and used only when it replays to the scene's saved text. An agent's draft starts the history over, so Ctrl+Z never removes it.
- **Reloads.** Text typed in the moment before a reload or a closed tab is kept in this browser and saved when the project opens again, with a notice. If the project has newer text by then, the words are offered in the binder footer as new documents, never written over it. `beforeunload` joins `visibilitychange` and `pagehide` as a flush signal.
- **Non-UTF-8 files.** A document whose file is not UTF-8 opens into an encoding review: the detected encoding, a preview, and a conversion only when the writer chooses it, with the original bytes kept in `.caotang-backup/`.
- **Storage location.** Settings › Data names the storage location, which is this browser.
- **Keyboard.** Shortcuts for the new item, the screenplay element menu, undo, focus mode, the filter, opening in the editor, renaming, deleting and moving items. Arrow keys, Home and End move between the rail tabs and the centre view, and menus return focus to the control that opened them.
- **Settings.** Provider profiles with optional prices, the agent's context budgets, the daily target and autosave delay, coherence checks, light and dark themes, checkpoint limits, **MCP & tools**, and data.
- **Faster first load.** The app's first download is small: Settings, the storyboard and its prompt pack, the dialogue view and the MCP client library are fetched when they are first opened, not with the page. React, the editor and the Markdown pipeline load as their own files, which also keeps them cached across releases. If one of those files cannot be fetched (after an update, or when the connection drops), the item says so with **Try again** and **Reload** and the rest of the app keeps working. The Ink compiler (244 kB) is its own file too: it is fetched when a project with a dialogue container opens, or when the first container is made, and a project without dialogue never downloads it. Until it has arrived the dialogue view and the container counts in the Inspector say *Loading the Ink compiler…*, and **Try again** and **Reload** if it cannot be fetched. A check, `tools/check-bundle-size.mjs`, runs after the build in CI and fails when a file, the first load or the total grows past its limit (CONTRIBUTING.md, Bundle size); the first load was 810.0 kB gzipped when last measured, against a limit of 830 kB. Sizes are measured on the build, gzip with zlib's default level.
- **Codex.** Characters, locations, objects, lore, subplots and other entries, with aliases, include policies, excluded phrases, and a list of the documents each name appears in. An entry set to Always is never cut: when the Always entries together are longer than the codex budget, they are all sent, the other entries are left out, and the prompt preview says so: "the codex's always entries need 1,400 tokens; the layer's budget is 1,000".
- **Visual references.** A codex entry takes pictures already in the project as visual references. The prompt pack names them for the scenes the entry appears in; Caotang uploads none of them.
- **Findings.** A quick scan with the checks chosen in Settings, and a model review that runs after its plan is approved. The review sends each scene only the codex entries its include policies select. A scope of more than 20 documents asks first, in the panel. Findings are grouped by severity and quote their passages; findings, run notes, the report and Undo name changes in the writer's words. A finding can be dismissed with a reason, marked fixed, or sent to the agent with Fix with agent. The run history keeps each run, with Run again and Discard run. A coherence report exports as Markdown or JSON. A scene that happens a week or more of story days after the one before it gets a note, which a scene declared **Time skip**, **Dream** or **Mythic** silences.
- **Findings and agent.** **Fix with agent** rewrites the first quote in binder order, and a finding whose first quote is in a dialogue container has no Fix. The Findings tab and the review plan show the same cost estimate. On the demo provider, Fix with agent rewrites only the demo's own sample passages.
- **Findings.** A screenplay scene can be linked to a dialogue container (**Dialogue container** in the inspector's scene declarations), and a full scan compares the characters the scene's cues name with the speakers of that container. It notes a spelling that differs between the two ("Marisol" and "Marisol Vega") where the codex knows only one of them or holds two characters, and a character only one side has. These are notes you can dismiss with a reason; only speakers are compared, and a scene with no link is counted in the run history, not compared. The link is a command, so Undo takes it back.
- **Findings.** Knowledge. The **Knowledge** list in the Findings tab holds the facts you want to track, and a scene's inspector says which character **Learns** a fact in it and which is shown to **Know** it. The scan reports a character who knows a fact in a scene before any scene at or before it teaches them, with a new check, **A character knows something before they learn it**. It names both scenes, or says the character never learns it. The order is the binder's, or the days when both scenes have a day offset; a scene whose place is not known is not compared, and a dream or mythic scene teaches no one. Removing a fact takes its declarations with it, and one Undo puts them back. A settings list saved before this check existed does not turn it on; turn it on under **Settings › Coherence**.
- **Findings.** A scene can declare a thread it plants (**Threads this scene sets up** in the inspector: a name, the scene it is paid off in, and a line on what the payoff is for), and the scan has a new check for it. It warns when the scene named as the payoff is no longer in the project, and notes a payoff the scan did not read (an empty or archived scene). Its messages say what the scene declares, and the scan report says how many scenes declare a thread. The model review is unchanged. A settings list saved before this check existed does not turn it on; turn it on under **Settings › Coherence**.
- **Screenplays.** Fountain scenes with Script, Source and Pages views, Enter and Tab on the Source tab for cues, an element menu on the Source tab (the **Element** button or Ctrl+E, Cmd+E on a Mac) that rewrites the caret's line as a scene heading, action, character, parenthetical, dialogue, transition, centered line, note or page break, import of `.fountain` and `.fdx` scripts, a Pages view that draws dual dialogue side by side, as the PDF does, and Fountain, Final Draft and PDF export (Final Draft files are not yet checked against Final Draft itself; see Known limits).
- **Screenplays.** Each line element has a chord on the Source tab: **Ctrl+Shift+1** to **9** (**Cmd+Alt+1** to **9** on a Mac), the same digits as the element menu, which shows them. A line that cannot be the element says so on the status line and is left alone. These are not yet tried on a real Mac, on an AltGr layout (German, Polish) or in Safari; the menu works wherever a chord is taken by the system.
- **Screenplays.** Two more chords on the Source tab take you to what the binder keeps about the scene: **Ctrl+Shift+S** (**Cmd+Alt+S** on a Mac) selects the folder the scene is in, its section, and moves to its binder row, and **Ctrl+Shift+Y** (**Cmd+Alt+Y**) moves to the scene's synopsis in the inspector. They use the element chords' modifiers and the same AltGr, key-repeat and input-method guards, and they change no text. Like the element chords, they are not yet tried on a real Mac, on an AltGr layout or in Safari.
- **Screenplays.** A line of the Pages view opens its element in the Source view: click it, or move with Up and Down and press Enter, and the Source view opens with the caret at the start of that element, scrolled into view. A wrapped paragraph opens as one element, each side of a dual-dialogue pair opens its own, and a speech split by (MORE) and (CONT'D) opens the one speech. Page numbers, scene numbers, (MORE), (CONT'D) and the title page open nothing. The Pages view still cannot be typed on; it is the first step towards a page you can write on.
- **Final Draft import keeps scene numbers and the title page.** A scene heading's number in a `.fdx` file (`2A` included) is kept on the imported scene, and the file's title page is read into the title page the import reports, so a Final Draft file Caotang exported reads back with its numbers and title. A file with a byte order mark or Windows line ends imports like any other. This is tested on test files written for it, not on files from Final Draft, so Final Draft files are still unchecked (see Known limits).
- **Dialogue.** Ink containers with a branch graph, an outline, findings, line ids and container settings. Import of an `.ink` story, one container for each group of linked knots. Ink story and dialogue table export, the table as CSV or as a spreadsheet (`.xlsx`). The engine target and the locale reach the exports: a Yarn container writes a Yarn Spinner strings file, the dialogue table has a locale column, and a container's own locale names its Ink story file.
- **Dialogue.** *Import Ink* has a box, *Add line ids to the imported containers (one time)*, unticked by default. When it is ticked, every line and choice of the imported story gets an id as the containers are made, from one set of ids shared by the whole story, and one undo takes the containers and their ids together. It does not turn on *Add line ids on save*. The status line says how many ids were added, names a line that could not take one with its container and line, and warns about an id the file already used more than once.
- **Twee import.** **Import Twee** in the binder reads a Twee 3 story (`.twee` or `.tw`) as one dialogue container with a knot for each passage. A dialog shows what the import will do before anything is written: the story format, the passages and choices, how many macros were stripped, the special passages skipped and any warnings. SugarCube 2 links become choices; a story in another format imports its passages and text without its links, and the dialog says so. It does not read Yarn Spinner `.yarn` files.
- **Yarn Spinner strings file.** The `lock` column is filled. It holds the first 8 hex characters of the SHA-256 of the row's `text` cell as written before the spreadsheet guard (`Speaker: text`, or the choice label), the hash Yarn Spinner for Unity writes for a line, so a tool that compares a translated row with its base row can tell that the base text changed. The file is a localisation for a Yarn project whose `.yarn` lines carry Caotang's `#line:` ids; it is not the base-language strings, which Yarn generates from the scripts.
- **Storyboards.** Shot cards in three sizes (S, M and L) with an animatic total, a card row that reads in the shot editor’s words (“Medium close-up (MCU) · Bird’s-eye view · Dolly in · 4 s · 35mm · Dissolve”, not the stored tokens), the same words on the agent’s derive plan, an empty board that offers to derive the shots of the scene beside it, shot fields, pictures (chosen, dropped or pasted, with a lightbox), script coverage (a passage that appears more than once is refused, with how many places, in every file whatever its line endings, and a selection across a line break is covered), a prompt for each target model with its checks (the shot prompt editor keeps the text typed for each vendor when the writer switches vendor), and a prompt pack exported as JSON, Markdown (with a Consistency block for each shot that names a codex entry, listing the entries that sent references and those that sent none) or CSV.
- **Storyboards.** A shot's picture whose file has gone is dropped when the project opens, from the projects list too, with a notice on the open and on the board, and not when the storyboard opens. A folder Caotang cannot attach (a different file under a picture's name, or a compile log it cannot read) is still read for its pictures, so a shot keeps one that only the folder holds. A folder file that differs from the browser's copy counts as present, and the board shows the browser's copy. Nothing is dropped when the project's pictures could not be listed.
- **Storyboard on paper.** **Paper frames** in the export dialog (the contact sheet's second setting, beside **Paper size**) prints the sheet as an empty ruled frame for every shot, to draw in by hand: the pictures are left out, and each card keeps its number chip, a caption such as `007 — The Ferry`, the camera details and the action. It is a recipe setting, `paperFrames`, and only the contact sheet reads it. Photographs of the drawings come back by dropping several on the storyboard board, outside any card: each goes on the shot whose number its file name starts with (`7.jpg`, `007.jpg` and `007-ferry.jpg` are shot 7), as one undo step, through the new command `shot.importImages`. A notice names the shot each file went on, by number and title, or why a file was not imported (not a PNG, JPEG or WebP picture, no number at the start of its name, no shot with that number, or two files for one shot, in which case neither is imported). A drop on a card and a card drag work as before. Specified in storyboard.md §6.
- **Prompt pack in the Export dialog.** The Media group offers **Prompt pack (video)** with a **Vendor template** choice. A compile writes the JSON, Markdown and CSV packs for that model and downloads them as one zip, for the whole manuscript or one item. A recipe saved with the pack keeps its vendor, and a compile with none chosen is refused beside Compile. The Prompt pack tab's export is unchanged.
- **Screenplay PDF.** A paginated PDF of the script, made in the browser: US Letter, Courier Prime 12 pt embedded in the file, the standard margins and indents, a title page, page numbers from page 2, scene headings kept with what follows, `(MORE)` and `(CONT'D)` where a speech crosses a page, dual dialogue side by side, and scene numbers in the left margin, the right or both. Scene numbers and `(MORE)`/`(CONT'D)` are recipe settings. Chinese, Japanese and Korean text prints in Noto Sans Mono CJK SC, two columns a character, with only the characters used embedded; that font loads only for a script that needs it. Emoji print in Noto Emoji, in black and white unless **Colour emoji** is on (below), one glyph and two columns each, ZWJ sequences, flags, keycaps and skin-tone sequences included, and copy out of the PDF as typed; that font loads only for a script with emoji.
- **Screenplay PDF paper and font.** The screenplay PDF can be set on A4 as well as US Letter, and in Cousine (the look of Courier New) or the Courier your PDF reader draws, as well as Courier Prime. The Export dialog has **Paper size** and **Font** for it, and a recipe keeps them. The text block is the same on both papers, six inches wide and 54 lines tall at the same left margin, so A4 breaks at the same lines, has the same page count and keeps the page-a-minute estimate; the extra height of A4 is white space at the foot of the page. A right-margin scene number ends a quarter inch right of the text block on both. A recipe that sets neither is set on US Letter in Courier Prime. Cousine is a 297 KB font that loads only when a recipe asks for it. A PDF in the reader’s own Courier embeds no font, so each reader draws it with its own face and the file is not PDF/A.
- **Fonts for both PDFs.** The screenplay PDF and the storyboard contact sheet set Chinese, Japanese and Korean text, Greek and Cyrillic in Noto Sans Mono CJK SC, and emoji in Noto Emoji, from one copy of each font. The contact sheet's Greek and Cyrillic are monospaced, as the screenplay's are. The CJK and the emoji font each come as two files: the full font, and a common file cut from it to the characters of everyday use. A screenplay PDF or a contact sheet whose Chinese, Japanese and Korean characters are all in the common file downloads 2.0 MB; the full CJK font is 10.7 MB (the regional forms of Han characters are in it). A script whose emoji are all single-character emoji or keycaps downloads 0.3 MB of emoji font; the full emoji font is 0.6 MB. The common CJK file holds the Latin, punctuation, fullwidth, kana, Greek, Cyrillic and symbol characters of the font, the 2,350 Hangul syllables of KS X 1001, and 4,460 Han characters: the 3,500 of level 1 of China's Table of General Standard Chinese Characters, the Japanese joyo kanji, and the Traditional Chinese characters of Hong Kong's first two primary grades. A script with one character outside it downloads the full font and prints that character like any other, with no question mark and no note, and the PDF holds the same glyphs whichever file was read. A family, a flag or a skin tone is outside the common emoji file, so a script with one downloads the full emoji font. The MCP server's bundle and the command-line bundle hold both files of each font, 13.9 MB of fonts together. Both PDFs lay out grapheme and emoji clusters with pinned Unicode 17 data instead of runtime ICU tables, so Node 22.12 and Node 24 lay out the same supported clusters.
- **Regional forms of Han characters in both PDFs.** The screenplay PDF and the storyboard contact sheet print a Han character in the form of the project's language: Japanese for `ja`, Korean for `ko`, Traditional Chinese for `zh-Hant`, `zh-TW` and `zh-MO`, Hong Kong for `zh-HK`; Simplified Chinese for `zh`, `zh-CN`, `zh-Hans`, `zh-SG`, any other language and none. The language is the one set in Project details. The fullwidth full stop and comma take the same forms, centred in Traditional Chinese and Hong Kong. The CJK font file holds the forms; the text still copies and searches as typed.
- **Colour emoji in both PDFs.** The Export dialog has **Colour emoji** for the screenplay PDF and the storyboard contact sheet. With it on, each emoji prints in Noto Color Emoji's design and colours, as a vector picture: 👍🏽 with its skin tone, 🏳️‍🌈 in colour, and families and flags as one picture, still copied out of the PDF as the emoji you typed. It is off by default for the screenplay PDF, which is usually printed in black and white, and on for the contact sheet, which prints an emoji in colour unless you clear the box; the choice is kept in the recipe. An emoji the colour set lacks prints in black and white in the same space and is named in the compile log; if the colour file (5 MB, fetched only when needed) cannot be read, the whole PDF prints in black and white and says so. With it off, emoji print in black and white.
- **PDF exports.** The woman and the man walking, kneeling or running facing right (🚶‍♀️‍➡️, 36 with their skin tones) print as one figure facing right in the screenplay PDF and in the storyboard contact sheet. The font draws them without a gender sign, as it draws 🚶‍♀️.
- **PDF exports.** The screenplay PDF and the storyboard contact sheet print Arabic, Persian, Urdu and Hebrew. They are set in Noto Sans Arabic and Noto Sans Hebrew (loaded only for a file that holds the script), shaped for their joined forms, and ordered by the Unicode bidirectional rules where a line mixes them with Latin letters, digits or emoji. In the screenplay, each paragraph takes its direction from its first strong letter (the project language for a neutral one) and a right-to-left paragraph ends at the right edge of its own column, inside the page. Character names in these scripts need a `@`. A speech also splits after `؟`, `۔` and `؛`. Text copied out of these PDFs, and found by search, comes out in the order it was typed in readers built on Poppler (Evince, Okular, `pdftotext`) and in pdf.js (Firefox): each glyph is drawn in its visual order with the letter it draws in its ToUnicode map, as Word and LibreOffice write right-to-left text, and a reader's bidirectional rules put the word back. The marks and joiners that are not drawn (the harakat, the Hebrew points, ZWNJ and ZWJ) are still copied, each as a glyph that draws nothing, and a mark after the last letter of a word is written after its word in marked content of its own, so `كَتَبَ` and `بِسْمِ` can be found and copied whole in Firefox. The positioned dots of an Arabic letter, glyphs of their own with no text, carry a code pdf.js skips as a format character and no ToUnicode entry, so they add no stray characters to an Arabic word. The `pdf-validate` check holds Arabic words, words with harakat to their last letter, a Devanagari file, and a contact sheet with both scripts, and it takes nothing out of what pdf.js reads except the zero-width space that the later glyphs of a Devanagari cluster map to.
- **Hindi, Marathi, Nepali and Sanskrit in both PDFs.** The screenplay PDF and the storyboard contact sheet print Devanagari. It is set in Noto Sans Devanagari (loaded only for a file that holds it), shaped with the conjuncts (क्ष, त्र, द्ध), the short ि drawn before its consonant, reph and the stacked marks, in the forms of the project's language (Marathi and Nepali differ from Hindi). In the screenplay a word takes whole Courier columns, a line breaks at spaces or between syllables, never inside a conjunct, and a speech splits after `।` and `॥`; on the contact sheet the ellipsis falls between syllables. Copying text out of either PDF gives back the words as you typed them. A character name needs a `@` in front, as for Arabic. The other Indic scripts still print as `?`, and the compile log names them. A file with no Devanagari does not load the font. These pages are machine-verified, not reader-verified.
- **Storyboard contact sheet.** A PDF of the shot cards in board order, on A4 or US Letter pages: each card's picture, shot number and action, with the camera details and duration in the shot editor's words on up to two lines, and a header on each page with the storyboard, the date, the page number, the number of shots and the animatic total. A shot with no picture shows its caption. Chinese, Japanese and Korean text prints in Noto Sans Mono CJK, and emoji print in Noto Emoji, in colour unless **Colour emoji** is cleared (see below): every emoji up to Unicode Emoji 17.0 prints. Each font is loaded only for a sheet that needs it and embedded with only the characters the sheet uses. An emoji sequence (a family, a skin tone, a flag, a keycap) prints as one picture, wraps as one character, and copies out of the PDF as typed.
- **Bold CJK and emoji on the contact sheet.** The storyboard contact sheet's header title, page label and shot-number chip print Chinese, Japanese and Korean text, and black-and-white emoji, in bold, to match a bold Latin name. The font has no Bold, so the letters are thickened by a stroke of 0.025 em with a little letter-spacing; the text you copy from the PDF is unchanged, a colour emoji is left as it is, and Arabic, Hebrew and Devanagari stay in the regular weight there. - **Contact sheet.** A WebP picture is drawn on the storyboard contact sheet. The picture is judged by its bytes, so a `.png` file that holds a WebP is drawn too. It is decoded to PNG and scaled down to 300 dpi of its card (about 700 pixels on the longer side), so a 4K picture does not swell the PDF; a smaller picture is not scaled up. The app decodes it on a canvas, with no new dependency and no change to the Content-Security-Policy. The MCP server and the command line decode it with `@jsquash/webp` (Apache-2.0), whose 138 KB `webp_dec.wasm` sits beside the `.mcpb` bundle and the `caotang` bundle. An animated WebP draws its first frame in the app, and the compile log says so; the MCP server and the command line read still images only, so there it shows the caption and the log gives the reason. A program that embeds the exporter and passes no `transcodePicture` gets the caption in place of the picture.
- **Export.** Markdown, plain text, Word (`.docx`) and EPUB, for the whole manuscript or one part of it; the media formats above; the coherence report; and recipes that keep export settings. A compile that is refused is said inside the Export dialog, beside Compile, and the title page carries the date of the day you compile, in your own time zone.
- **Export.** A scene can be marked **Section** (the **Export style** in the inspector), and its title then prints as a heading above it in Markdown (`###`), plain text (capitals), Word (Heading 2, listed under its chapter in the contents field) and EPUB (`<h2>`). A scene's title prints only when the scene is marked Section. A style that a format cannot express is named in the compile log; none is dropped yet. A project written before the field loads unchanged.
- **Spreadsheet export.** The dialogue table and the storyboard shot list export as `.xlsx` as well as `.csv`, from the Media group of the Export dialog. Each has one sheet with the CSV's columns and rows. Shot numbers, durations and character limits are numbers, and text is never run as a formula. The file is made in the browser, with no new dependency. A CI job writes the dialogue table and the shot list as `.xlsx` files, with accents, CJK, emoji, line breaks, formula characters and a cell over the limit, and opens them in openpyxl and in LibreOffice (as CSV, and re-saved as `.xlsx`), failing when a cell reads back as another value or type. `docs/testing/office-interop.md` holds the checklist for Excel, Numbers and Google Sheets, with no result recorded yet.
- **Providers.** Presets that fill in each provider's address and authentication, the published context window of each model they name (the Claude models included) in the model picker, three wire formats (OpenAI Chat Completions, OpenAI Responses and Anthropic Messages), and the Chat, Drafting and Background task roles, each with its own profile, model and thinking level.
- **Providers.** An Extra high thinking level (`xhigh`) for the four Claude 5 models, and a thinking budget a single call can set in tokens: it is sent as a number where the route takes one, and otherwise becomes the nearest level the model lists. The plan card's cost estimate adds the thinking a set level can spend and says "including thinking". The request log records the output cap each request was sent with and Settings shows it.
- **Providers.** A thinking level on an Anthropic profile works: Claude 5 models get adaptive thinking with the chosen effort, and the Thinking block shows their summary. On routes that take a thinking budget, the output cap is raised so it always exceeds the budget.
- **Providers.** Local models: **Ollama**, **LM Studio** and **llama.cpp (llama-server)** are presets under **On this computer** in Settings › Providers. They use plain `http` to an address on this computer only (`localhost`, `127.0.0.1` and the rest of `127.0.0.0/8`, `[::1]`); a LAN address, a `.local` name or any other host is refused with the reason, and the generic endpoint and every other provider still need `https`. No key is needed unless you set one on the server. They start with no native tools, no image input and a 4,096-token context window until the server says otherwise, and wait up to three minutes for a model to load. A blocked call says which setting fixes it (`OLLAMA_ORIGINS`, LM Studio's Enable CORS, llama-server's `--cors-origins`), or that the browser denied access, or that nothing is listening. That makes 28 provider presets.
- **Agent.** Plans, one-step cards and draft previews, with checkpoints and restore. It runs on a preset for one of 28 providers or any OpenAI-compatible endpoint you add (your key stays in the browser), or on a built-in demo provider that needs no key. It uses native tool calling where the model supports it. It can run the model review as a plan step, and it can call the tools of the MCP servers you connect, under the approval rules in the README. The built-in demo says in words when it cannot draft or fill synopses, and changes nothing. The conversation lives for as long as the project is open in the tab, so changing the provider, the model or the thinking level between two requests does not make the agent forget the requests before it, and each request runs on the provider you have chosen at that moment. What the agent remembers of an earlier request includes its result when nothing was written for it: a question the agent answered counts as that answer (cut to one line). The conversation is not kept across a reload.
- **Agent.** Stop, steering notes and a queue. **Stop** (or **Esc**, with the Intent box empty) ends a running turn at its next step: what the turn already applied stays, with its checkpoint, and the report says "Stopped by you." A card that waits is cancelled as **Cancel** does. The Intent box stays open while a turn runs: **Enter** queues the message as the next turn, and **Ctrl+Enter** sends it to the running turn as a note that the model reads at its next request. Queued messages can be edited, removed, reordered (with ↑ and ↓ or by dragging) and sent now with **Steer now**; they run one at a time, and the queue waits after a turn that stopped on a question until you choose **Run the queue**. A note typed while a card waits offers **Send with Cancel** or **Queue as next turn**, and a note the turn ended without reading becomes the first queued message. A step that has started is not interrupted: a command that is applying, and a compile, finish.
- **Agent.** A live task list for multi-step turns, in the agent header and at the top of the turn, with the model-call budget. The header says "Step 3 of 5 · Drafting “The Landing”", or "Waiting for you · Plan, 3 steps", with the drawer open or closed. The list is worked out from the plan and the tool calls, so it costs no model tokens and shows only work that ran.
- **Permission modes.** The agent panel has a **Mode** control: **Plan only** (the agent reads and answers; every change is refused before it is drafted and kept as a plan you can run with **Switch to Ask and run this plan**), **Ask** (the default), **Accept edits** (cards that change text and fields are approved as shown) and **Auto** (every card of the agent's own tools is approved as shown). A card a mode approved is collapsed behind an **Auto-approved** badge and its draft still streams into the scene first; every turn row and checkpoint row names its mode. Calls to outside tools, drafts that are out of date or cut off, and the changes the agent may never make still wait for you in every mode. While Accept edits or Auto decides, a turn stops on a question at its limit for tokens, cost, words changed, documents touched or steps, or when it proposes the same call three times. **Settings › Agent** sets the mode a panel starts in, can turn Auto off, and sets the limits. The mode is an app setting and a per-panel choice, never a project-file key.
- **Run limits.** Settings › Agent has **Run limits** for a turn: model calls (8 unless you change it), minutes of work (10), tokens, steps, and a cost in dollars. Before each request the agent works out the most it could use, and a request that could pass a limit is not sent, so a limit is never crossed; the time a card waits for you is not counted as work. A turn that works for its minutes is ended in the middle of a request: what it applied stays in its checkpoint, and an unfinished draft is cleared. The panel shows the tokens, cost, steps and time used while a turn works, and a turn that reaches a limit stops on a card that names it. A cost limit needs prices on the provider profile. The limits are yours, set on your own key; Caotang has no quota. A deadline ("stop by 07:00") and a meter shared by the turns of one run are in the harness, for the goal runs and background work that will use them.
- **Agent rules.** You can tell the agent where it may not go. Right-click a folder or document in the binder and choose **Agent: may read only** (the agent can read it and may not change it) or **Agent: may not read** (its text, title, synopsis and notes never reach a provider, and the agent cannot change it either); **Agent: may read and change** lifts the rule. A marked row carries an icon and the words **Agent: read only** or **Agent: hidden**, and what is inside a marked folder is held to it too. The rule is kept in the project's file (`caotang.json`, under `agent.rules`), so it goes with the folder and the bundle, and a rule in a file can only restrict the agent, never give it more. **Settings › Agent** lists the rules with where each comes from and a **Remove** for each, and lets you add a rule of your own for a tool, in every project: the agent may never use it, or must ask you first. A change the agent tries in a locked place is refused as a failed card that names the rule, before any draft is made and in every mode, and a rule that asks puts the tool's card in front of you even in Accept edits and Auto. A hidden folder is left out of what the agent reads (`binder.read_tree`, `project.overview`, the codex entries attached only to it, the quick scan and the model review) and out of every prompt; the card's prompt preview lists each item left out. Exporting a hidden folder is not stopped, since an export sends nothing to a provider. The MCP server reads a project's rules too, so a host that connects to the folder is held to them: a `deny` refuses its call, an `ask` on a write becomes its confirmation question, a hidden folder is left out of its tools, resources and prompts, and a rule in the file that could not be read refuses every write until it is fixed. The rules you set in Settings › Agent are app settings and are not read by the server. The `allow` rule, which would let a tool run without a card, is not in this build.
- **Slash commands in the agent panel.** Type `/` in the **Intent** box to open the list of commands: `/draft`, `/synopses`, `/scan`, `/review`, `/compile`, `/restore`, `/context`, `/plan` and `/help`. Each builds the step you mean from what you typed, so `/draft "Chapter 3" continue 800 -- keep the rain` is one scene draft the agent does not have to interpret, and its card is the card the agent would have shown for the same step. A title that names several documents is answered under the box with the candidates, before anything is sent. `/plan <request>` asks for a plan card even for one small change. `/context` shows what the next request would send, layer by layer, and what was left out, without sending it; `/restore` opens the same confirmation as a checkpoint row's **Restore to before this turn**. No command skips a card, a rule, a mode or a run limit. Down, Up, Tab, Enter and Escape work the list; start a request with `//` to send a slash as text. The turn's row shows the command, and the run log records it. A command that would start or restore a turn waits while a turn runs. Saved prompts as your own commands, and commands for macros and MCP prompts, are not built.
- **Agent instructions and memory.** Write your standing instructions once in `CAOTANG.md`, a plain file at the root of the project, and the agent reads them with every request: "British spelling. Past tense, close third person on Mara." The agent can also keep memory notes in a `memory` folder (one Markdown file each, with an index), so a correction you give once is not lost, and you can read, edit and forget every note. The **Instructions** panel in the toolbar edits the file and the notes, shows their size against a 1,500-token limit (**Settings › Context**, **Instructions**), and has **Initialise from this project**, which asks the agent for a first draft on one card. Over the limit the agent is sent whole lines up to it, and the panel, the prompt preview and Settings say "CAOTANG.md is N tokens; the first M were sent". The agent writes `CAOTANG.md` or a note only behind a card you approve, no permission mode approves either, and it cannot forget a note. An `AGENTS.md` is read when there is no `CAOTANG.md`, and never written. The files are in a project folder, a `.caotang` bundle and this browser's copy, a folder save is refused when `CAOTANG.md` changed on disk since the last load, and the Caotang MCP server lets a connected program read them (`memory.read`) and never change them. A note that cannot be read is kept as it is.
- **Skills.** A project can hold skills: reusable writing instructions for the agent, such as "draft in close third person, past tense" or "use these slug-line conventions", kept in the project so they travel with it. **Skills** in the toolbar opens the panel, where you write a skill, import a folder or a zip, turn a skill on or off, edit it and delete it. The agent is told about a skill only after you have read all of it and approved it: the review shows every file as plain text, makes characters that cannot be seen visible, and names any scripts. If a skill changes in any file, you approve it again, and your approval is kept in this browser and never in the project or a bundle, so a project someone shares with you starts with every skill unapproved. An approved skill that is on is listed to the agent, which loads it when your request matches it; the instructions guide the turn's drafts and change nothing about what needs your approval. A skill is a standard Agent Skills folder (`.agents/skills/<name>/SKILL.md`), so Claude Code, Codex and other programs read the same folder. Only the project's `.agents/skills` is read, up to 50 skills of 64 files each, 256 KB a file and 2 MB a skill. The folder, a bundle and the browser's copy all carry skills, and the folder-save check names a skill another program changed. The agent can never create, edit, turn on or import a skill.
- **Agent tools load on demand.** The agent starts each request with a short list of tools: the 13 it uses most and the search that finds the rest. The tools for importing, the coherence checks, storyboards, prompt packs and dialogue are found by that search when a task needs them, or are there from the start when a dialogue container or a storyboard is open. The tool list in each request is about 40% shorter, and a tool the agent loads part-way through a turn does not change what the model has already been sent. A tool that was not loaded still runs when the agent names it, and if its settings are wrong the agent is told to search for it. **Settings › Agent** has **Load every tool on every request**, off by default, for a model that searches poorly.
- **Agent.** The agent can rewrite a document's notes, set a synopsis, add or change a status or a label, save a binder filter and set a word goal, with five new tools (`notes.replace`, `synopsis.set`, `vocabulary.upsert`, `filter.save` and `goal.save`) that load on demand like the other extra tools. Rewriting the notes and changing the vocabulary ask for approval, and the notes card shows the old and the new notes word by word; the other three apply at once and can be undone. A plan can add a status and use it in the same approval. Each tool takes its approval level from the command it stands for, and deleting, writing a document's body, the view commands and the file-staging commands are never offered. `project.overview` lists the saved filters by id and name, and a refused `notes.append` names `notes.replace`.
- **Helper agents.** For a long reading job, the agent can hand the reading to a helper: the **Reader** agent reads the documents it is pointed at and returns notes, and the **General** agent also suggests changes. A helper starts from a fresh view of the project, the brief and the documents it was given, and none of your conversation with the agent. It only reads. A change it suggests is never applied by the helper: it happens only if the agent puts it in its own plan, where the step reads **Proposed by the general agent** and you approve the plan as always, so the turn stays one approval and one checkpoint. In the panel the helper's call is a card with the agent, the model calls reserved for it, where it stands in words, a timer, and its **Brief**, **Notes** and **Transcript** to open. A helper's calls count towards the turn's model calls, and the agent is told when the turn cannot afford one. The helpers use the same provider and key as the turn and nothing new is stored. Only these two helpers exist; they cannot start another helper, and they run one at a time. The tool is `agent.delegate`, the 33rd row of the registry, found by the agent with its tool search.
- **Agent.** A plan that needs five or more model calls is offered before it starts: **Run now**, **Run in background** or **Cancel**. A background task drafts one call at a time under the Background role while you keep writing, capped at the plan's estimate, and is listed under **Background tasks** in the agent panel with its status in words, its calls and tokens, and its errors. It writes nothing: **Review** opens the held drafts on the usual card with the ghost previews, a scene changed since it was drafted is marked out of date and cannot be approved, and approving applies them as one undo group. Tasks are kept in the app database (never in a project or an export), a task a closed tab left running is stopped and can be resumed, and 50 finished tasks or 14 days are kept per project. The harness gains `AgentSession.stageOnly` and `submitStaged`, `estimatedModelCalls` and `AgentSessionOptions.beforeStage`; `AppDb` gains `list(prefix)` and `delete(key)`. Coherence never runs in the background on its own: `docs/decisions.md` says a review the writer queues may.
- **Recurring tasks.** The agent panel has a **Recurring tasks** section: a task is a name, what it does (ask the agent, or scan for continuity problems), when it is due (when you run it, each time the project opens, every day, or every week, from a time of day) and what it may do. When a task is due you are offered it, with **Run now** and **Skip**, even with the panel closed; a task you missed for days is offered once. **Run now** on a task that asks the agent is an ordinary turn on the Background role's model, held to the task's own limit on model calls, and the task's permission can only lower the panel's mode. A scan task set to start by itself runs when it is due with no click, leaves out the documents an agent rule keeps from the agent, and makes no model request. A task that uses the model is offered whatever it is set to, and says so. Tasks live in `tasks.json` beside `caotang.json` (definitions only, with three snapshots and the usual recovery), travel in a bundle, and are not something the agent or the MCP server can make or read; when each last ran, what a run used and what you skipped stay in this browser (the app database goes to version 4 for it). The save indicator reads *saving* while a task is being saved, so a reload at that moment does not lose it. They run only while the project is open in a visible tab.
- **Agent runs resume after a reload.** The agent logs each turn in this browser as it works, a step's record written once the step is saved. If the page reloads, crashes or closes mid-turn, the agent panel shows an **An agent run was interrupted** card when you open the project, with how many steps were applied and what it cost so far, and two buttons: **Resume**, and **Discard log**, which keeps what the run already wrote. Resume is always your click, because it can ask the model again. A plan the run was showing comes back needing your approval. Resume stops and names the documents if a write did not reach the project or you changed a scene the run depends on, and a step sent to an MCP server that may have run is never sent again by itself. The agent rules in force when you resume apply to the rest of the run.
- **Golden writing tasks and a prompt manifest (developers).** Thirteen writing and editing tasks (draft a scene, continue in voice, rewrite a selection, fill synopses, restructure, tag point of view, find a planted contradiction, keep a `never` codex entry out, continue Fountain, draft Ink, refuse an overwrite, plan economically, derive a storyboard) run in `pnpm verify` against committed cassettes through the mock provider, with deterministic checks on what the agent wrote and a failure, with a diff, when a request no longer matches its recording. The cassettes are synthetic: hand-written model answers, labelled so in their header, so they guard the prompts and the harness and are no evidence about any model. A prompt manifest pins the planner, draft and review prompts and every tool description, and fails when a description changes without its `descriptionVersion`. The checks live in `agent/checks.ts` beside the goal checks.
- **Command line.** `caotang agent -p "<intent>" --project <folder>` runs the agent on a project folder from a terminal, a script or CI: read-only unless you say otherwise (`--permission auto` or `approve-all`, and `--approve-tools` to approve only the cards made of the tools you list), nothing written without `--write` (the diff is printed instead), the key read from an environment variable and never from a flag, and the result as text, as one JSON object (`--output-format json`) or as one JSON line per event (`stream-json`). The exit code says whether it is done (0), the turn needs input (4), the folder is held by another writer (3), or the command line is wrong (2). `caotang mcp serve` starts the MCP server. It builds to `dist/caotang.mjs`, one file with its `fonts/` beside it.
- **SDK.** `@caotang/sdk` runs the agent against a project folder from a Node script, a CLI or CI. `openProject` takes the folder's lock and returns a project whose `run(intent)` yields the turn's events and a report, with an approval policy (`'read-only'`, `'auto'`, `'approve-all'`, or your own function) answering the cards where the app has a person. Changes stay in memory until `save()` unless the project is opened with `write: true`, and `diff()` shows what a save would change. The provider is the demo provider or one profile, and its key is read once, held in memory and sent only to that profile's address. The package README has three examples. The MCP server opens its folder through the same code, and the app, the SDK and the server build their harness with one factory.
- **Continuity scan.** `caotang scan --project <folder>` runs the deterministic checks of the Findings tab on a project folder with no model and no key, for a writer's own CI. It prints text, the Markdown report, JSON, or GitHub workflow commands (`--format github`) that show each finding on its file and line, in the file where the project keeps the document (`.md`, `.fountain` or `.ink`). A finding dismissed or marked fixed in the committed `coherence.json` neither prints nor fails the run. `--fail-on error|warning|info|never` (default `error`) sets the severity that exits 7, and a document that is not UTF-8 text is named, makes the scan partial and exits 8 when nothing else fails it and `--fail-on` is not `never`; the folder is only read unless `--write` is given, and `--summary <file>` also writes the Markdown report (appended when it is `$GITHUB_STEP_SUMMARY`; without `--write` it must name a file outside the folder). The dialogue checks run too. `docs/ci/continuity-scan.yml` is a GitHub Actions template for a nightly scan with `contents: read`, and the release attaches `caotang.mjs` and its SHA-256.
- **MCP & tools.** Connect external Model Context Protocol servers over Streamable HTTP. Each server's tool list is reviewed before its tools are used, a tool can be switched off, and read-only tools can be trusted after a review. A tool whose name the model cannot take, such as one with a dot, is given a short alias for the agent, and the server still receives its own name.
- **MCP client.** Connects to servers that speak the 2025 revisions as well as 2026-07-28.
- **MCP & tools.** A connected server's prompts and resource templates are listed on its card in full, each with whether you have reviewed it, and are pinned when you approve the server's list: a prompt or template that changes afterwards reads "Changed since review" and waits for your approval, while the server's tools stay as you approved them. A server whose resource or prompt list cannot be read says so on its card ("resources unavailable: …") and keeps its tools. Nothing here attaches a resource or runs a prompt yet, and the agent cannot read a resource or run a prompt at all; the `mcp.readResource` command that reads a resource you pick is in place, closed to the agent, and its picker in the composer is still to come.
- **Tool answers.** An answer from an external tool larger than 8,000 tokens is refused, with the cap named. It is never cut down.
- **Tool lists.** A server whose tool list has changed is caught before each call, and a changed tool is refused with no request sent.
- **Caotang as an MCP server** (`@caotang/mcp-server`). Other AI tools can read a project folder over MCP. With `--allow-writes`, seven tools apply at once and seven ask for confirmation in the host. It listens on `127.0.0.1` with a bearer token, or runs over stdio. Packaged as an MCPB bundle with `pnpm --filter @caotang/mcp-server run pack`, with an "Allow changes" setting that is off by default. The import tools `doc.import` and `codex.import` bring existing writing in, `codex.read` answers from the manifest, and `export.compile` compiles the manuscript, an item or a recipe, EPUB included, after the host confirms it. The model-backed tools are not listed, because the server holds no provider key.
- **MCP over HTTP.** A 2025-era host can confirm writes over HTTP when it declares elicitation and keeps the session the server gives it, so it need not connect over stdio.
- **MCP server.** A confirmation open when the server restarts ends with it, and the server says so. A 2025-era connection that asks for a session the server no longer holds is answered `404` "Session not found" with a note that a confirmation open on it ended too and nothing was written. A 2026-07-28 retry with a `requestState` from an earlier run is refused, with the SDK's "Invalid or expired requestState"; nothing is written, and the change is asked for again. The README and the spec name both, and no key is stored on disk.
- **MCP server.** The server offers the project as resources and five prompts, besides its tools. A host can attach a document's whole text (`caotang://doc/{id}`), its notes (`caotang://notes/{id}`), a codex entry (`caotang://codex/{id}`), the overview, the binder and the codex index. The links carry ids and never file names, the list is in binder and codex order, and a document over 2 MiB is refused with its size and never cut. The prompts `draft-scene`, `fill-synopsis`, `continuity-check`, `codex-from-doc` and `revise-with-codex` hand the host's own model the context Caotang's agent assembles for the same job, plus a closing line that says whether to store the result (with `--allow-writes`) or show it to the writer; the server calls no model and holds no key. A server started with `--allow-writes` tells a subscribed host which notes or documents a write changed, and when the list changed, on a 2026-07-28 stream, on a 2025-era connection and over stdio; a read-only server reports neither. The server does not watch the folder. The MCPB manifest says its prompts are generated.
- **MCP server.** A project folder whose `caotang.json` cannot be read does not end the server at start. The server starts without a project, holds the folder's lock, and offers the recovery the app offers: `project.recover` shows which snapshot it would restore from, or that it would rebuild from the documents and what that loses, and with `--allow-writes` `project.recoverApply` applies it after you accept the host's dialog. The dialog names the exact file, the copy `caotang.json.corrupt-<timestamp>` that keeps the unreadable original, and the lock. A rebuild asks separately (`rebuild: true`) and names the loss of folder structure and vocabulary. Nothing is written if another program changed the folder since the offer, and the refusal names what changed. A manifest from another app or a newer format is still refused. The server holds no project afterwards: restart it, or reconnect the host, to open the recovered one. The dialog wording has not been seen in a real host, and there is no `--recover` flag.
- **MCP server.** The server reads the project's `coherence.json` when it opens, so `coherence.scan` finds the findings and dismissals saved in the app and reuses their ids instead of starting from nothing. Reading writes nothing, not even to repair a damaged file, and a file the server cannot read does not stop it from starting: it is reported on stderr and left as it is. With `--allow-writes`, `coherence.scan` appends its run to `coherence.json` and `coherence.setFindingStatus` keeps `fixed` there, so both are still there after a restart, and the app shows them when the folder is opened. If the app changed the file meanwhile, the file on disk wins and the server adds back only its own runs and findings; a file it cannot merge is not written, and the refusal names `coherence.json`. The file is outside the check that stops writes when the folder changes.
- **MCP server.** Steps to install the `.mcpb` bundle in the README and the user guide, including what the unsigned "Install Anyway" prompt means, and `packages/mcp-server/HOST-CHECKS.md`, a checklist for running the bundle in a real MCPB host, with no row run yet. At start the server also logs one stderr line saying whether `CAOTANG_MCP_ALLOW_WRITES` was unset, `true`, `false` or other, never the value itself.
- **MCP server.** A host that retries a write can ask for it to write once. A write-auto request (`notes.append` and the other tools that apply at once) that carries `app.caotang/idempotencyKey` in its `_meta` is answered from the first call's answer when it is repeated within 5 minutes, and writes nothing again, even when the repeat arrives while the first write is still being saved. The same key with other arguments, or for another tool, is refused and names both calls. A request without a key is a new call, and so is a retry that sends no key; the answers are held in the server's memory only, so a restart ends them.
- **Hosted instance (specified, not built).** `docs/architecture/hosted.md` specifies an optional hosted instance with end-to-end encrypted projects: the key hierarchy, the sealed file format, the encrypted index, the blob service contract, sync and rollback rules, the threat model with its honest limits, and the phases. Two private packages, `@caotang/crypto` and `@caotang/remote-store`, build the storage core against an in-memory fake server; no app code imports them, there is no server, account or network code. Neither package has had an independent security review. The user guide lists the hosted instance under what is not in this build yet.
- **Releases.** The MCP bundle and its SHA-256 are attached to each GitHub release, built from the tagged source by a workflow that stops when the tag, `package.json`, `manifest.json` and `server.json` name different versions. The landing page and the bundle name the maker as "@nattiini45 and contributors".
- **Notices.** `THIRD-PARTY-NOTICES.md` lists the third-party software in the builds, generated from the lockfile, and ships beside the desktop build and inside the MCP bundle.
- **License.** Caotang is MIT-licensed and free. There are no accounts, subscriptions or credit meters.
- **Content-Security-Policy.** The built app carries a `<meta>` policy: scripts and styles only from its own origin, no plugins, frames or form submissions, and connections open to the provider and MCP servers the writer chooses. The README's Self-hosting section shows the same policy as a header.
- **CI.** Each pull request verifies on Node 22.12.0 and 24, and runs Chromium, Firefox and WebKit end-to-end checks in parallel. The Node 22.12.0 job installs the pnpm version pinned in `packageManager` from a downloaded tarball whose SHA-512 is checked against the pinned hash, because the bundled Corepack cannot verify its current signing key. Firefox and WebKit also run nightly and on demand in two shards per browser, merged into one HTML report that is uploaded when a shard fails. Folder-access tests run only in Chromium; `e2e/non-chromium-storage.spec.ts` covers the bundle-only path.
- **CI.** A manual workflow, `provider-smoke`, runs the real-key provider round on `main` from environment secrets, for one preset or every preset with a key (`gh workflow run provider-smoke.yml -f presets="anthropic deepseek"`). Its log and job summary name only the preset, the stage and the HTTP status of a failure. It never runs on a pull request, a push or a schedule. `CAOTANG_ONLY_PRESETS` limits the round when it is run locally, and `CAOTANG_E2E_NO_SERVER=1` runs a Playwright spec without starting the dev and preview servers.

### Changed

- **Providers.** Saving an Anthropic profile whose model list the browser will not let the page read now says that ("the browser did not let this page read the model list… chat may still work") instead of "could not reach api.anthropic.com, check your connection and the base URL". Anthropic's answer to a wrong key on the model list carries no CORS header, so a mistyped key looked like a dead connection. Z.ai and OpenCode are listed as "Desktop app or hosted only": their chat routes refuse the browser's preflight, which the reachability check, now asking the chat route as well as the model list, found.
- **Word counts.** Chinese, Japanese and Thai text (and Lao, Khmer and Myanmar) is counted by words as the browser divides them, where a whole run without spaces used to count as one word, so a words goal, the daily target and the word filter now work for those manuscripts. The count is approximate and can differ between browsers; a goal in characters stays exact. Counts for Latin, Greek, Cyrillic, Korean and Vietnamese text do not change. A project saved before this is recounted once when it is opened. Sessions already recorded keep their old numbers, so weekly and monthly totals across the change mix the two. A browser without word segmentation counts each such character as a word.
- **Word export.** A `.docx` written without a contents list no longer sets Word's "update fields on open" setting, so Word has no prompt to show for it. A file with a contents list is written as before.
- **Dialogue.** The agent's `dialogue.table` tool now reports the container's engine target and locale, as the exports use them. Its table gains a sixth column after `charLimit`, `locale` (the container's own locale, else the project's language), its JSON rows gain a `locale` field, and its `data` gains `engineTarget` (or `null`) and `locale` (or `null`). A container set to Yarn string table (CSV) also gets a note that the export writes a Yarn Spinner strings file for it, not the dialogue table; the tool still returns the one dialogue table for every container. The `charLimit` column stays empty, and a note says why. The change is additive for a client that reads the CSV by header or the JSON by key; a client that reads the CSV by position needs to take the new sixth column into account.
- **MCP server.** A confirmation on a 2025-era connection waits 60 seconds for its answer instead of ten minutes, so a dialog nobody answers frees its connection's place in a minute. The question and the `initialize` instructions say how long it waits, and a refused `initialize` (every connection busy) names the limit, how many are busy and the wait, with a `Retry-After` header. A confirmation that times out writes nothing, and the host's next call asks again.

### Known limits

- **Not in this build:** a desktop wrapper and the hosted instance. The user guide's last section lists them.
- Knowledge is checked only where you declare it. The scan does not look for a fact in a character's lines or in the prose, and a group or faction cannot be said to know a fact, only the characters in it.
- Slash commands are the nine built-ins. `/draft` cannot rewrite a selection, because a command line cannot carry the editor's selection: ask for a rewrite in words. `/scan` and `/review` take one document, the changed ones or the whole manuscript, not a list. You cannot save a prompt as a command, and there are no commands for macros or for MCP prompts yet.
- The golden writing tasks replay synthetic cassettes in CI. Recording real-model responses, benchmarking models and an optional judge score are not built, so nothing here says how well any model writes through Caotang.
- Resuming an agent run asks the model again for the call that was in flight when the page closed, and that call is counted as spent. Resume has been tried against test providers only, not a real one. The undo for the steps a run had already applied is lost with the reload; a checkpoint can still take the turn back. A run's card cannot yet restore to before the run, export its log, or keep it in a project folder.
- The agent rules in Settings › Agent are the app's own and are not read by the MCP server, which reads only the rules in the project's file. A hidden folder is not hidden from your own earlier words to the agent: a request you typed that names a hidden chapter stays in the agent's memory of your last two requests, and a change the agent made there before the rule is described only as a change to a part of the project that a rule now withholds.
- The limits on steps, documents and words changed are checked before a card applies, from the drafts for a scene or a batch of synopses and from the activity log for any other step, so a restructure or an import is counted after it has run and can pass a limit by its own size. The cost limit does nothing for a provider with no price. Accept edits and Auto do not yet fall back to Ask for text that came from outside the project, because nothing marks it yet.
- Background tasks run only while the project is open in this tab, on the main thread: there is no Web Worker (no typing jank has been measured), no Service Worker, and no gateway limiter that ranks the agent ahead of a task, so a call already sent still counts against a rate-limited key. A coherence review cannot be queued yet.
- Recurring tasks run only while the project is open in a visible tab. A task that uses the model is always offered and never starts by itself: the screen that would let you allow it, and the place its results would wait for your review, are not built. There is no command line for tasks, a task's plan can be read from `tasks.json` but not written in the panel, and a task cannot be made by the agent.
- The local model presets (Ollama, LM Studio, llama.cpp) are verified against test servers that imitate each product's browser settings, not against the real servers. Firefox has not been tried and Safari is not verified. The context window and tool support of a local model are not read from the server; a server on another computer on your network is not supported.
- Skills that include scripts: Caotang uses their instructions and does not run the scripts, and the review says that other programs reading the same folder may. The agent reads a skill's instructions only: the other files kept with it are carried and shown on the review, and the agent cannot read them in this build. A skill's list of allowed tools is shown on the review and does not limit the agent here. There are no skills shared across projects, no way to run a skill by name, and `.claude/skills` is not read.
- The screenplay PDF is set in Courier Prime (Cousine or the reader's own Courier on request) with Noto Sans Mono CJK SC and Noto Emoji for other characters, and Noto Color Emoji when **Colour emoji** is on. A character no font covers, such as a Tamil letter, prints as a question mark, and the compile log names it. Bengali, Gurmukhi, Gujarati, Odia, Tamil, Telugu, Kannada, Malayalam and Sinhala print as question marks until each has a font; of the Indic scripts only Devanagari has one so far. Arabic, Persian, Urdu and Hebrew print in Noto Sans Arabic and Noto Sans Hebrew, but without their marks (the Arabic harakat, the Hebrew points), which are left out of the drawing and counted in the compile log, though a reader copies and searches them with their words; in a reader built on Poppler (Evince, Okular) a letter with two stacked marks can copy with a mark before it, and a word that a narrow paragraph wraps can copy split; Nastaliq is not drawn; and the page is not mirrored for a right-to-left project, which waits for a native reader to look at sample pages. These pages are machine-verified, not reader-verified: they are checked by tests that read the file back, not by a reader of the language, and not in Acrobat. The first time a script or a contact sheet needs the CJK font it downloads 2.0 MB when every character is in the common file, and the 10.7 MB full font when one is not; the emoji font is 0.3 MB or 0.6 MB, and the colour emoji file 5 MB. The PDF has been checked with Poppler and Ghostscript, not yet in Acrobat or on a printer.
- Emoji in the screenplay PDF and the contact sheet print in black and white, and a skin tone as the plain figure, when **Colour emoji** is off (the screenplay PDF's default); with it on they print in colour. The colour pictures have been checked in pdf.js, PDFium and MuPDF, not yet in Poppler, Ghostscript, Acrobat or Preview.
- A WebP picture on the contact sheet is drawn without its colour profile: the app draws the colours the browser converts to sRGB, and the MCP server and the command line draw the stored values. Characters that none of its fonts has (Helvetica, Noto Sans Mono CJK, Noto Emoji, Noto Sans Arabic, Noto Sans Hebrew, Noto Sans Devanagari), such as Tamil, print as `?`, and the compile log names them. The sheet has been checked by tests that read the PDF back, not yet by eye in a range of PDF readers.
- Final Draft (`.fdx`) import and export have not been checked against files that Final Draft wrote or opened. The scene numbers and page headers Caotang writes are not yet confirmed in Final Draft.
- The `.xlsx` files are checked by unit tests against the Office Open XML parts, and CI opens them in LibreOffice and openpyxl. They have not been opened in Excel or Numbers yet: the checklist for that is `docs/testing/office-interop.md`, and it records no result.
- The Word contents field has not been tested in Word, LibreOffice, Pages or Google Docs; `docs/testing/office-interop.md` holds the checklist, with no result recorded yet. Word offers to update it when the file opens; a file without a contents list does not ask. The file's structure is tested, and its entries are plain text until Word updates the field.
- The `.mcpb` bundle is checked by its pinned MCPB CLI and run over stdio. It has not been run in a real MCPB host, and it is not signed.
- Restore after a `caotang agent --write` run lasts only while the command runs: the undo history is not saved, so keep the folder under version control.
- The SDK's restore lasts for the process: the undo history is not saved, so a turn written with `write: true` cannot be restored by a later run. Read `diff()` before you set `write: true`, and keep the project in git.
- An app that already has a folder open does not show what the MCP server saved to `coherence.json` until the folder is opened again. The server's check of that file narrows the chance that it and the app lose each other's findings and does not close it.
- The app asks before it saves over the MCP server's folder lock, but a save the writer confirms can still replace a change the server made. Keep the server stopped while the app saves to the same folder.
- A change another program makes to a project folder in the instant of a save can still be replaced, because the browser cannot check a file and replace it in one step. Caotang narrows that instant and reports what it finds afterwards, but it cannot stop it. The folder question names the files another program changed and does not show what changed in them, and there is no merge: compare the folder's version in `.caotang-backup` by hand.
- The toolbar's Undo and the Undo in Activity last for the open tab; checkpoints survive a reload. Undo on a screenplay's Source tab and in Ink text is the browser's own.
- The Yarn Spinner strings file has not been loaded in Yarn Spinner itself, and its `lock` values have not been compared with the ones Yarn's own compiler writes. They follow the rule in Yarn Spinner's documentation and source.
- In the Yarn Spinner strings file, a `language`, `text`, `file` or `comment` cell that starts with `=`, `+`, `-`, `@`, a tab or a carriage return gets an apostrophe in front, as in every CSV export, so a spreadsheet does not run it as a formula. A spoken line's `text` cell starts with the speaker's name when it has one. The apostrophe is written into the cell itself, so a tool that reads the file gets it with the text; how Yarn Spinner shows it has not been checked.
- The continuity scan in CI runs the deterministic checks only, and a model review there is not offered: it would need a key in the repository's secrets and would spend on a schedule. The `continuity-scan.yml` template pins a release of `caotang.mjs` by a SHA-256 you write into it, and its version and hash are placeholders until the maintainer cuts a release that carries that file, so it is not turnkey. Annotations and logs carry short quotes from the manuscript, which anyone can read on a public repository.
- Pull requests run end-to-end tests in Chromium, Firefox and WebKit; the Firefox and WebKit suite also runs nightly and on demand, without the specs that need folder saves (File System Access is Chromium-only). CI tests Node 22.12.0 and 24; Node 26 is allowed by `engines` but not covered. The suite tests the checkpoint trim on the browser's own IndexedDB and programmatic `File` objects on a shot card; it does not drive a file dragged out of the desktop or the system clipboard.
- CI uses the built-in demo and mock providers only. An opt-in real-key smoke test (`e2e/provider-smoke.spec.ts`, one `CAOTANG_SMOKE_<PRESET>` variable per provider) runs locally, or in CI by a maintainer's manual dispatch from repository secrets; never on a pull request.
