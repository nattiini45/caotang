# Changelog

All notable changes to Caotang are recorded here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the version follows the `version` field in each package's `package.json`.

## Unreleased

### Changed

- **CI.** Each pull request verifies on Node 22.12.0 and 24, and runs Chromium, Firefox and WebKit end-to-end checks in parallel. Firefox and WebKit also run nightly and on demand in two shards per browser, merged into one HTML report that is uploaded when a shard fails. Folder-access tests still run only in Chromium; `e2e/non-chromium-storage.spec.ts` covers the bundle-only path.
- **PDF text.** The screenplay and storyboard PDFs use pinned Unicode 17 grapheme and emoji data instead of runtime ICU tables, so Node 22.12 and Node 24 lay out the same supported clusters.
- **A smaller first download for the PDF fonts.** The CJK and the emoji font each come as two files now: the full font, and a common file cut from it to the characters of everyday use. A screenplay PDF or a contact sheet whose Chinese, Japanese and Korean characters are all in the common file downloads 2.0 MB, not 10.7 MB; one whose emoji are all single-character emoji or keycaps downloads 0.3 MB, not 0.6 MB. The common CJK file holds the Latin, punctuation, fullwidth, kana, Greek, Cyrillic and symbol characters of the font, the 2,350 Hangul syllables of KS X 1001, and 4,460 Han characters: the 3,500 of level 1 of China's Table of General Standard Chinese Characters, the Japanese joyo kanji, and the Traditional Chinese characters of Hong Kong's first two primary grades. A script with one character outside it downloads the full font and prints that character like any other, with no question mark and no note, and the PDF holds the same glyphs whichever file was read. A family, a flag or a skin tone is outside the common emoji file, so a script with one downloads the full emoji font. The MCP server's bundle and the command-line bundle hold both files of each font, 13.9 MB of fonts together.
- **Dialogue.** *Import Ink* has a box, *Add line ids to the imported containers (one time)*, unticked by default. When it is ticked, every line and choice of the imported story gets an id as the containers are made, from one set of ids shared by the whole story, and one undo takes the containers and their ids together. It does not turn on *Add line ids on save*. The status line says how many ids were added, names a line that could not take one with its container and line, and warns about an id the file already used more than once. With the box unticked the import is as before.
- **MCP server.** A host that retries a write can ask for it to write once. A write-auto request (`notes.append` and the other tools that apply at once) that carries `app.caotang/idempotencyKey` in its `_meta` is answered from the first call's answer when it is repeated within 5 minutes, and writes nothing again, even when the repeat arrives while the first write is still being saved. The same key with other arguments, or for another tool, is refused and names both calls. A request without a key is a new call, as before, and the answers are held in the server's memory only, so a restart ends them. The README's known gap about retried writes now says a retry is a second write only when no key is sent.
- **Word export.** A `.docx` written without a contents list no longer sets Word's "update fields on open" setting, so Word has no prompt to show for it. A file with a contents list is written as before. The file structure is tested; how Word, Pages and Google Docs handle the field has not been, and `docs/testing/office-interop.md` holds the checklist for it, with no result recorded yet.
- **Dialogue.** The agent's `dialogue.table` tool now reports the container's engine target and locale, as the exports use them. Its table gains a sixth column after `charLimit`, `locale` (the container's own locale, else the project's language), its JSON rows gain a `locale` field, and its `data` gains `engineTarget` (or `null`) and `locale` (or `null`). A container set to Yarn string table (CSV) also gets a note that the export writes a Yarn Spinner strings file for it, not the dialogue table; the tool still returns the one dialogue table for every container. The `charLimit` column stays empty, and a note says why. The change is additive for a client that reads the CSV by header or the JSON by key; a client that reads the CSV by position needs to take the new sixth column into account.
- **Screenplays.** A line of the Pages view opens its element in the Source view: click it, or move with Up and Down and press Enter, and the Source view opens with the caret at the start of that element, scrolled into view. A wrapped paragraph opens as one element, each side of a dual-dialogue pair opens its own, and a speech split by (MORE) and (CONT'D) opens the one speech. Page numbers, scene numbers, (MORE), (CONT'D) and the title page open nothing. The Pages view still cannot be typed on; it is the first step towards a page you can write on. The PDF and Final Draft files are written byte for byte as before.
- **Word counts.** Chinese, Japanese and Thai text (and Lao, Khmer and Myanmar) is counted by words as the browser divides them, where a whole run without spaces used to count as one word, so a words goal, the daily target and the word filter now work for those manuscripts. The count is approximate and can differ between browsers; a goal in characters stays exact. Counts for Latin, Greek, Cyrillic, Korean and Vietnamese text do not change. A project saved before this is recounted once when it is opened. Sessions already recorded keep their old numbers, so weekly and monthly totals across the change mix the two. A browser without word segmentation counts each such character as a word.
- **Yarn Spinner strings file.** The `lock` column is filled. It holds the first 8 hex characters of the SHA-256 of the row's `text` cell as written before the spreadsheet guard (`Speaker: text`, or the choice label), the hash Yarn Spinner for Unity writes for a line, so a tool that compares a translated row with its base row can tell that the base text changed. The file is a localisation for a Yarn project whose `.yarn` lines carry Caotang's `#line:` ids; it is not the base-language strings, which Yarn generates from the scripts.
- **PDF exports.** The screenplay PDF and the storyboard contact sheet print Arabic, Persian, Urdu and Hebrew, which printed as `?` before. They are set in Noto Sans Arabic and Noto Sans Hebrew (loaded only for a file that holds the script), shaped for their joined forms, and ordered by the Unicode bidirectional rules where a line mixes them with Latin letters, digits or emoji. In the screenplay, each paragraph takes its direction from its first strong letter (the project language for a neutral one) and a right-to-left paragraph ends at the right edge of its own column, inside the unchanged page. Character names in these scripts need a `@`. A speech now also splits after `؟`, `۔` and `؛`. A Latin-only, Chinese, Japanese, Korean or emoji file is written byte for byte as before.
- **Faster first load.** The app's first download is smaller: Settings, the storyboard and its prompt pack, the dialogue view and the MCP client library are fetched when they are first opened, not with the page. The first load (the entry and the files it loads with it) went from 2,898.0 kB to 2,483.9 kB (849.6 kB to 746.8 kB gzipped), and the entry file alone from 2,898.0 kB to 1,097.9 kB, because React, the editor and the Markdown pipeline now load as their own files, which also keeps them cached across releases. If one of those files cannot be fetched (after an update, or when the connection drops), the item says so with **Try again** and **Reload** and the rest of the app keeps working. The Ink compiler (244 kB) is its own file too: it is fetched when a project with a dialogue container opens, or when the first container is made, and a project without dialogue never downloads it. Until it has arrived the dialogue view and the container counts in the Inspector say *Loading the Ink compiler…*, and **Try again** and **Reload** if it cannot be fetched. On the same build, the first load went from 2,657.7 kB to 2,415.9 kB (801.5 kB to 742.1 kB gzipped). A new check, `tools/check-bundle-size.mjs`, runs after the build in CI and fails when a file, the first load or the total grows past its limit (CONTRIBUTING.md, Bundle size). Sizes were measured on the same build before and after, gzip with zlib's default level.
- **MCP server.** A confirmation open when the server restarts ends with it, and the server now says so. A 2025-era connection that asks for a session the server no longer holds is answered `404` "Session not found" with a note that a confirmation open on it ended too and nothing was written. A 2026-07-28 retry with a `requestState` from an earlier run is refused as before, with the SDK's "Invalid or expired requestState"; nothing is written, and the change is asked for again. The README and the spec name both, and no key is stored on disk.
- **MCP server.** A confirmation on a 2025-era connection waits 60 seconds for its answer instead of ten minutes, so a dialog nobody answers frees its connection's place in a minute. The question and the `initialize` instructions say how long it waits, and a refused `initialize` (every connection busy) names the limit, how many are busy and the wait, with a `Retry-After` header. A confirmation that times out writes nothing, and the host's next call asks again.

### Added

- **Run limits.** Settings › Agent has **Run limits** for a turn: model calls (8 unless you change it), minutes of work (10), tokens, steps, and a cost in dollars. Before each request the agent works out the most it could use, and a request that could pass a limit is not sent, so a limit is never crossed; the time a card waits for you is not counted as work. A turn that works for its minutes is ended in the middle of a request: what it applied stays in its checkpoint, and an unfinished draft is cleared. The panel shows the tokens, cost, steps and time used while a turn works, and a turn that reaches a limit stops on a card that names it. A cost limit needs prices on the provider profile. The limits are yours, set on your own key; Caotang has no quota. A deadline ("stop by 07:00") and a meter shared by the turns of one run are in the harness, for the goal runs and background work that will use them.
- **Regional forms of Han characters in both PDFs.** The screenplay PDF and the storyboard contact sheet print a Han character in the form of the project's language: Japanese for `ja`, Korean for `ko`, Traditional Chinese for `zh-Hant`, `zh-TW` and `zh-MO`, Hong Kong for `zh-HK`; Simplified Chinese, as before, for `zh`, `zh-CN`, `zh-Hans`, `zh-SG`, any other language and none. The language is the one set in Project details. The fullwidth full stop and comma take the same forms, centred in Traditional Chinese and Hong Kong. The CJK font file now holds the forms, so the one download is 10.7 MB, not 7.2 MB; the text still copies and searches as typed. A Latin-only file is written as before. A file for a project with no language draws the same glyphs, and differs from before only in the embedded font's header (its checksum and the bounds it states for its glyphs).
- **Twee import.** **Import Twee** in the binder reads a Twee 3 story (`.twee` or `.tw`) as one dialogue container with a knot for each passage. A dialog shows what the import will do before anything is written: the story format, the passages and choices, how many macros were stripped, the special passages skipped and any warnings. SugarCube 2 links become choices; a story in another format imports its passages and text without its links, and the dialog says so. It does not read Yarn Spinner `.yarn` files.
- **Folder saves keep what they replace.** **Save over them** and **Save over it** first copy each document and codex file they replace, if another program wrote it, to `.caotang-backup/<time>/` in the folder, and the status line names that folder. The copies of the newest 20 saves are kept. The backup is in no bundle and no export. A save that cannot make a copy stops before it replaces that file. A file that changes between the save's last check and its rename now stops the save before that file. When a save has finished, the folder's files, `caotang.json` and lock file are read again: a file another program changed while the save wrote, or a lock that appeared, is named in the question, and the next save asks about it. The findings file `coherence.json` is written into the open folder only while it is the one Caotang last read or wrote; a file the MCP server changed is not replaced, and the Findings tab says so.
- **Permission modes.** The agent panel has a **Mode** control: **Plan only** (the agent reads and answers; every change is refused before it is drafted and kept as a plan you can run with **Switch to Ask and run this plan**), **Ask** (the default, as before), **Accept edits** (cards that change text and fields are approved as shown) and **Auto** (every card of the agent's own tools is approved as shown). A card a mode approved is collapsed behind an **Auto-approved** badge and its draft still streams into the scene first; every turn row and checkpoint row names its mode. Calls to outside tools, drafts that are out of date or cut off, and the changes the agent may never make still wait for you in every mode. While Accept edits or Auto decides, a turn stops on a question at its limit for tokens, cost, words changed, documents touched or steps, or when it proposes the same call three times. **Settings › Agent** sets the mode a panel starts in, can turn Auto off, and sets the limits. The mode is an app setting and a per-panel choice, never a project-file key.
- **Storyboard on paper.** **Paper frames** in the export dialog (the contact sheet's second setting, beside **Paper size**) prints the sheet as an empty ruled frame for every shot, to draw in by hand: the pictures are left out, and each card keeps its number chip, a caption such as `007 — The Ferry`, the camera details and the action. It is a recipe setting, `paperFrames`, and only the contact sheet reads it. Photographs of the drawings come back by dropping several on the storyboard board, outside any card: each goes on the shot whose number its file name starts with (`7.jpg`, `007.jpg` and `007-ferry.jpg` are shot 7), as one undo step, through the new command `shot.importImages`. A notice names the shot each file went on, by number and title, or why a file was not imported (not a PNG, JPEG or WebP picture, no number at the start of its name, no shot with that number, or two files for one shot, in which case neither is imported). A drop on a card and a card drag work as before. Specified in storyboard.md §6; the paper-photo round trip is no longer "recorded, not built".
- **Helper agents.** For a long reading job, the agent can hand the reading to a helper: the **Reader** agent reads the documents it is pointed at and returns notes, and the **General** agent also suggests changes. A helper starts from a fresh view of the project, the brief and the documents it was given, and none of your conversation with the agent. It only reads. A change it suggests is never applied by the helper: it happens only if the agent puts it in its own plan, where the step reads **Proposed by the general agent** and you approve the plan as always, so the turn stays one approval and one checkpoint. In the panel the helper's call is a card with the agent, the model calls reserved for it, where it stands in words, a timer, and its **Brief**, **Notes** and **Transcript** to open. A helper's calls count towards the turn's model calls, and the agent is told when the turn cannot afford one. The helpers use the same provider and key as the turn and nothing new is stored. Only these two helpers exist; they cannot start another helper, and they run one at a time. The tool is `agent.delegate`, the 33rd row of the registry, found by the agent with its tool search.
- **Contact sheet.** A WebP picture is drawn on the storyboard contact sheet, where its card showed the caption before. The picture is judged by its bytes, so a `.png` file that holds a WebP is drawn too. It is decoded to PNG and scaled down to 300 dpi of its card (about 700 pixels on the longer side), so a 4K picture does not swell the PDF; a smaller picture is not scaled up. The app decodes it on a canvas, with no new dependency and no change to the Content-Security-Policy. The MCP server and the command line decode it with `@jsquash/webp` (Apache-2.0), whose 138 KB `webp_dec.wasm` sits beside the `.mcpb` bundle and the `caotang` bundle. An animated WebP draws its first frame in the app, and the compile log says so; the MCP server and the command line read still images only, so there it shows the caption and the log gives the reason. A program that embeds the exporter and passes no `transcodePicture` keeps the caption and the old log line.
- **Spreadsheet files.** A CI job writes the dialogue table and the shot list as `.xlsx` files, with accents, CJK, emoji, line breaks, formula characters and a cell over the limit, and opens them in openpyxl and in LibreOffice (as CSV, and re-saved as `.xlsx`), failing when a cell reads back as another value or type. `docs/testing/office-interop.md` holds the checklist for Excel, Numbers and Google Sheets, with no result recorded yet.
- **MCP server.** The server offers the project as resources and five prompts, besides its tools. A host can attach a document's whole text (`caotang://doc/{id}`), its notes (`caotang://notes/{id}`), a codex entry (`caotang://codex/{id}`), the overview, the binder and the codex index. The links carry ids and never file names, the list is in binder and codex order, and a document over 2 MiB is refused with its size and never cut. The prompts `draft-scene`, `fill-synopsis`, `continuity-check`, `codex-from-doc` and `revise-with-codex` hand the host's own model the context Caotang's agent assembles for the same job, plus a closing line that says whether to store the result (with `--allow-writes`) or show it to the writer; the server calls no model and holds no key. A server started with `--allow-writes` tells a subscribed host which notes or documents a write changed, and when the list changed, on a 2026-07-28 stream, on a 2025-era connection and over stdio; a read-only server reports neither. The server does not watch the folder. The MCPB manifest says its prompts are generated.
- **Hosted instance (specified, not built).** `docs/architecture/hosted.md` specifies an optional hosted instance with end-to-end encrypted projects: the key hierarchy, the sealed file format, the encrypted index, the blob service contract, sync and rollback rules, the threat model with its honest limits, and the phases. Two private packages, `@caotang/crypto` and `@caotang/remote-store`, build the storage core against an in-memory fake server; no app code imports them, there is no server, account or network code, and `caotang.app` is unchanged. Neither package has had an independent security review. The user guide lists the hosted instance under what is not in this build yet.
- **Agent.** A plan that needs five or more model calls is offered before it starts: **Run now**, **Run in background** or **Cancel**. A background task drafts one call at a time under the Background role while you keep writing, capped at the plan's estimate, and is listed under **Background tasks** in the agent panel with its status in words, its calls and tokens, and its errors. It writes nothing: **Review** opens the held drafts on the usual card with the ghost previews, a scene changed since it was drafted is marked out of date and cannot be approved, and approving applies them as one undo group. Tasks are kept in the app database (never in a project or an export), a task a closed tab left running is stopped and can be resumed, and 50 finished tasks or 14 days are kept per project. The harness gains `AgentSession.stageOnly` and `submitStaged`, `estimatedModelCalls` and `AgentSessionOptions.beforeStage`; `AppDb` gains `list(prefix)` and `delete(key)`. Coherence never runs in the background on its own: `docs/decisions.md` now says a review the writer queues may.
- **MCP server.** A project folder whose `caotang.json` cannot be read no longer ends the server at start. The server starts without a project, holds the folder's lock, and offers the recovery the desktop app offers: `project.recover` shows which snapshot it would restore from, or that it would rebuild from the documents and what that loses, and with `--allow-writes` `project.recoverApply` applies it after you accept the host's dialog. The dialog names the exact file, the copy `caotang.json.corrupt-<timestamp>` that keeps the unreadable original, and the lock. A rebuild asks separately (`rebuild: true`) and names the loss of folder structure and vocabulary. Nothing is written if another program changed the folder since the offer, and the refusal names what changed. A manifest from another app or a newer format is still refused. The server holds no project afterwards: restart it, or reconnect the host, to open the recovered one. The dialog wording has not been seen in a real host, and there is no `--recover` flag.
- **Hindi, Marathi, Nepali and Sanskrit in both PDFs.** The screenplay PDF and the storyboard contact sheet print Devanagari, which printed as `?` before. It is set in Noto Sans Devanagari (loaded only for a file that holds it), shaped with the conjuncts (क्ष, त्र, द्ध), the short ि drawn before its consonant, reph and the stacked marks, in the forms of the project's language (Marathi and Nepali differ from Hindi). In the screenplay a word takes whole Courier columns, a line breaks at spaces or between syllables, never inside a conjunct, and a speech splits after `।` and `॥`; on the contact sheet the ellipsis falls between syllables. Copying text out of either PDF gives back the words as you typed them. A character name needs a `@` in front, as for Arabic. The other Indic scripts still print as `?`, and the compile log names them. A file with no Devanagari is written byte for byte as before and does not load the font. These pages are machine-verified, not reader-verified.
- **Findings.** A screenplay scene can be linked to a dialogue container (**Dialogue container** in the inspector's scene declarations), and a full scan compares the characters the scene's cues name with the speakers of that container. It notes a spelling that differs between the two ("Marisol" and "Marisol Vega") where the codex knows only one of them or holds two characters, and a character only one side has. These are notes you can dismiss with a reason; only speakers are compared, and a scene with no link is counted in the run history, not compared. The link is a command, so Undo takes it back.
- **Command line.** `caotang agent -p "<intent>" --project <folder>` runs the agent on a project folder from a terminal, a script or CI: read-only unless you say otherwise (`--permission auto` or `approve-all`, and `--approve-tools` to approve only the cards made of the tools you list), nothing written without `--write` (the diff is printed instead), the key read from an environment variable and never from a flag, and the result as text, as one JSON object (`--output-format json`) or as one JSON line per event (`stream-json`). The exit code says whether it is done (0), the turn needs input (4), the folder is held by another writer (3), or the command line is wrong (2). `caotang mcp serve` starts the MCP server. It builds to `dist/caotang.mjs`, one file with its `fonts/` beside it.
- **SDK.** `@caotang/sdk` runs the agent against a project folder from a Node script, a CLI or CI. `openProject` takes the folder's lock and returns a project whose `run(intent)` yields the turn's events and a report, with an approval policy (`'read-only'`, `'auto'`, `'approve-all'`, or your own function) answering the cards where the app has a person. Changes stay in memory until `save()` unless the project is opened with `write: true`, and `diff()` shows what a save would change. The provider is the demo provider or one profile, and its key is read once, held in memory and sent only to that profile's address. The package README has three examples. The MCP server now opens its folder through the same code, and the desktop app, the SDK and the server build their harness with one factory.
- **MCP & tools.** A connected server's prompts and resource templates are listed on its card in full, each with whether you have reviewed it, and are pinned when you approve the server's list: a prompt or template that changes afterwards reads "Changed since review" and waits for your approval, while the server's tools stay as you approved them. A server whose resource or prompt list cannot be read says so on its card ("resources unavailable: …") and keeps its tools. Nothing here attaches a resource or runs a prompt yet, and the agent cannot read a resource or run a prompt at all; the `mcp.readResource` command that reads a resource you pick is in place, closed to the agent, and its picker in the composer is still to come.
- **MCP server.** The server reads the project's `coherence.json` when it opens, so `coherence.scan` finds the findings and dismissals saved in the app and reuses their ids instead of starting from nothing. Reading writes nothing, not even to repair a damaged file, and a file the server cannot read does not stop it from starting: it is reported on stderr and left as it is. With `--allow-writes`, `coherence.scan` appends its run to `coherence.json` and `coherence.setFindingStatus` keeps `fixed` there, so both are still there after a restart, and the app shows them when the folder is opened. If the app changed the file meanwhile, the file on disk wins and the server adds back only its own runs and findings; a file it cannot merge is not written, and the refusal names `coherence.json`. The file is outside the check that stops writes when the folder changes.
- **Providers.** Local models: **Ollama**, **LM Studio** and **llama.cpp (llama-server)** are presets under **On this computer** in Settings › Providers. They use plain `http` to an address on this computer only (`localhost`, `127.0.0.1` and the rest of `127.0.0.0/8`, `[::1]`); a LAN address, a `.local` name or any other host is refused with the reason, and the generic endpoint and every other provider still need `https`. No key is needed unless you set one on the server. They start with no native tools, no image input and a 4,096-token context window until the server says otherwise, and wait up to three minutes for a model to load. A blocked call says which setting fixes it (`OLLAMA_ORIGINS`, LM Studio's Enable CORS, llama-server's `--cors-origins`), or that the browser denied access, or that nothing is listening. Presets go from 25 providers to 28.
- **Screenplays.** Each line element has a chord on the Source tab: **Ctrl+Shift+1** to **9** (**Cmd+Alt+1** to **9** on a Mac), the same digits as the element menu, which now shows them. A line that cannot be the element says so on the status line and is left alone. These are not yet tried on a real Mac, on an AltGr layout (German, Polish) or in Safari; the menu works wherever a chord is taken by the system.
- **MCP server.** Steps to install the `.mcpb` bundle in the README and the user guide, including what the unsigned "Install Anyway" prompt means, and `packages/mcp-server/HOST-CHECKS.md`, a checklist for running the bundle in a real MCPB host, with no row run yet. At start the server also logs one stderr line saying whether `CAOTANG_MCP_ALLOW_WRITES` was unset, `true`, `false` or other, never the value itself.
- **Skills.** A project can hold skills: reusable writing instructions for the agent, such as "draft in close third person, past tense" or "use these slug-line conventions", kept in the project so they travel with it. **Skills** in the toolbar opens the panel, where you write a skill, import a folder or a zip, turn a skill on or off, edit it and delete it. The agent is told about a skill only after you have read all of it and approved it: the review shows every file as plain text, makes characters that cannot be seen visible, and names any scripts. If a skill changes in any file, you approve it again, and your approval is kept in this browser and never in the project or a bundle, so a project someone shares with you starts with every skill unapproved. An approved skill that is on is listed to the agent, which loads it when your request matches it; the instructions guide the turn's drafts and change nothing about what needs your approval. A skill is a standard Agent Skills folder (`.agents/skills/<name>/SKILL.md`), so Claude Code, Codex and other programs read the same folder. Only the project's `.agents/skills` is read, up to 50 skills of 64 files each, 256 KB a file and 2 MB a skill. The folder, a bundle and the browser's copy all carry skills, and the folder-save check names a skill another program changed. The agent can never create, edit, turn on or import a skill.
- **Agent.** Stop, steering notes and a queue. **Stop** (or **Esc**, with the Intent box empty) ends a running turn at its next step: what the turn already applied stays, with its checkpoint, and the report says "Stopped by you." A card that waits is cancelled as **Cancel** does. The Intent box stays open while a turn runs: **Enter** queues the message as the next turn, and **Ctrl+Enter** sends it to the running turn as a note that the model reads at its next request. Queued messages can be edited, removed, reordered (with ↑ and ↓ or by dragging) and sent now with **Steer now**; they run one at a time, and the queue waits after a turn that stopped on a question until you choose **Run the queue**. A note typed while a card waits offers **Send with Cancel** or **Queue as next turn**, and a note the turn ended without reading becomes the first queued message. A step that has started is not interrupted: a command that is applying, and a compile, finish.
- **Findings.** Knowledge. The **Knowledge** list in the Findings tab holds the facts you want to track, and a scene's inspector says which character **Learns** a fact in it and which is shown to **Know** it. The scan reports a character who knows a fact in a scene before any scene at or before it teaches them, with a new check, **A character knows something before they learn it**. It names both scenes, or says the character never learns it. The order is the binder's, or the days when both scenes have a day offset; a scene whose place is not known is not compared, and a dream or mythic scene teaches no one. Removing a fact takes its declarations with it, and one Undo puts them back. A settings list saved before this check existed does not turn it on; turn it on under **Settings › Coherence**.
- **Findings.** A scene can declare a thread it plants (**Threads this scene sets up** in the inspector: a name, the scene it is paid off in, and a line on what the payoff is for), and the scan has a new check for it. It warns when the scene named as the payoff is no longer in the project, and notes a payoff the scan did not read (an empty or archived scene). Its messages say what the scene declares, and the scan report says how many scenes declare a thread. The model review is unchanged. A settings list saved before this check existed does not turn it on; turn it on under **Settings › Coherence**.
- **CI.** A manual workflow, `provider-smoke`, runs the real-key provider round on `main` from environment secrets, for one preset or every preset with a key (`gh workflow run provider-smoke.yml -f presets="anthropic deepseek"`). Its log and job summary name only the preset, the stage and the HTTP status of a failure. It never runs on a pull request, a push or a schedule. `CAOTANG_ONLY_PRESETS` limits the round when it is run locally, and `CAOTANG_E2E_NO_SERVER=1` runs a Playwright spec without starting the dev and preview servers.
- **Export.** A scene can be marked **Section** (the **Export style** in the inspector), and its title then prints as a heading above it in Markdown (`###`), plain text (capitals), Word (Heading 2, listed under its chapter in the contents field) and EPUB (`<h2>`). Scene titles never printed before, so an export of a manuscript with a scene marked Section differs from an earlier one. A style that a format cannot express is named in the compile log; none is dropped yet. A project written before the field loads unchanged.
- **Codex.** An entry set to Always is no longer cut when the Always entries together are longer than the codex budget. They are all sent, the other entries are left out, and the prompt preview says so: "the codex's always entries need 1,400 tokens; the layer's budget is 1,000". When the Always entries fit, nothing changes.
- **Agent.** A live task list for multi-step turns, in the agent header and at the top of the turn, with the model-call budget. The header says "Step 3 of 5 · Drafting “The Landing”", or "Waiting for you · Plan, 3 steps", with the drawer open or closed. The list is worked out from the plan and the tool calls, so it costs no model tokens and shows only work that ran.
- **Providers.** An Extra high thinking level (`xhigh`) for the four Claude 5 models, and a thinking budget a single call can set in tokens: it is sent as a number where the route takes one, and otherwise becomes the nearest level the model lists. The plan card's cost estimate adds the thinking a set level can spend and says "including thinking". The request log records the output cap each request was sent with and Settings shows it.
- **Agent.** The agent can rewrite a document's notes, set a synopsis, add or change a status or a label, save a binder filter and set a word goal, with five new tools (`notes.replace`, `synopsis.set`, `vocabulary.upsert`, `filter.save` and `goal.save`) that load on demand like the other extra tools. Rewriting the notes and changing the vocabulary ask for approval, and the notes card shows the old and the new notes word by word; the other three apply at once and can be undone. A plan can add a status and use it in the same approval. Each tool takes its approval level from the command it stands for, and deleting, writing a document's body, the view commands and the file-staging commands are never offered. `project.overview` now lists the saved filters by id and name, and a refused `notes.append` names `notes.replace`.
- **MCP server.** With `--allow-writes`, the server lists the five new tools: seven tools apply at once and seven ask for confirmation in the host (21 tools in all).
- **Agent tools load on demand.** The agent starts each request with a short list of tools: the 13 it uses most and the search that finds the rest. The tools for importing, the coherence checks, storyboards, prompt packs and dialogue are found by that search when a task needs them, or are there from the start when a dialogue container or a storyboard is open. The tool list in each request is about 40% shorter, and a tool the agent loads part-way through a turn does not change what the model has already been sent. A tool that was not loaded still runs when the agent names it, and if its settings are wrong the agent is told to search for it. **Settings › Agent** has **Load every tool on every request**, off by default, for a model that searches poorly.
- **Releases.** The MCP bundle and its SHA-256 are attached to each GitHub release, built from the tagged source by a workflow that stops when the tag, `package.json`, `manifest.json` and `server.json` name different versions. The landing page and the bundle name the maker as "@nattiini45 and contributors".

### Fixed

- **PDF exports.** Arabic and Hebrew in the screenplay PDF and the storyboard contact sheet copy and search in the order they were typed in readers built on Poppler (Evince, Okular, `pdftotext`), where a word came out backwards (`ةراس` for `سارة`, `םולש` for `שלום`). The words are no longer wrapped in `/ActualText`, which Poppler spreads over the word from left to right and then reverses again. Each glyph is drawn in its visual order with the letter it draws in its ToUnicode map, as Word and LibreOffice write right-to-left text, and a reader's bidirectional rules put the word back. The marks and joiners that are not drawn (the harakat, the Hebrew points, ZWNJ and ZWJ) are still copied, each as a glyph that draws nothing. The ToUnicode text of some joined forms was wrong (a medial beh copied as a noon) and was hidden by `/ActualText`; it is now the letter that was typed. Devanagari words keep their `/ActualText`. pdf.js read the positioned dots of an Arabic letter, glyphs of their own with no text, as the character whose number is the glyph's, which put control characters, spaces and stray letters inside Arabic words in Firefox and in pdf.js search. In Arabic and Hebrew such a glyph now has a code pdf.js skips as a format character and no ToUnicode entry (Poppler ignores it, as before); the later glyphs of a Devanagari cluster map to a zero-width space, a mapping that would cut an Arabic word in pieces in Poppler. A Latin-only, Chinese, Japanese, Korean or emoji file is written byte for byte as before. A mark after the last letter of an Arabic or Hebrew word (a final fatha, kasra or damma, a Hebrew point under the last letter) is written after its word in marked content of its own, because pdf.js appended it to the word drawn before, or to an item that came before its word, so `كَتَبَ` and `بِسْمِ` could not be found or copied whole in Firefox. The `pdf-validate` check now holds Arabic words, words with harakat to their last letter, a Devanagari file, and a contact sheet with both scripts, and it takes nothing out of what pdf.js reads except that zero-width space.
- **Agent.** Changing the provider, the model or the thinking level between two requests no longer makes the agent forget the requests before it: the conversation now lives for as long as the project is open in the tab, and each request runs on the provider you have chosen at that moment. What the agent remembers of an earlier request now includes its result when nothing was written for it: a question the agent answered counts as that answer (cut to one line), where the next draft read "no recorded changes". The conversation is still not kept across a reload.
- **PDF exports.** The woman and the man walking, kneeling or running facing right (🚶‍♀️‍➡️, 36 with their skin tones) print as one figure facing right in the screenplay PDF and in the storyboard contact sheet. They printed as their first emoji (🚶) in the screenplay, with a note in the compile log, and as three pictures side by side in the contact sheet. The font draws them without a gender sign, as it draws 🚶‍♀️.
- **Storyboards.** A shot's picture whose file has gone is dropped when the project opens, from the projects list too, with a notice on the open and on the board, and not when the storyboard opens. A folder Caotang cannot attach (a different file under a picture's name, or a compile log it cannot read) is still read for its pictures, so a shot keeps one that only the folder holds. A folder file that differs from the browser's copy counts as present, and the board shows the browser's copy. Nothing is dropped when the project's pictures could not be listed.
- **Providers.** A thinking level on an Anthropic profile no longer makes every request fail; Claude 5 models get adaptive thinking with the chosen effort, and the Thinking block shows their summary. On routes that take a thinking budget, the output cap is raised so it always exceeds the budget.

### Known limits

- A change another program makes to a project folder in the instant of a save can still be replaced, because the browser cannot check a file and replace it in one step. Caotang narrows that instant and reports what it finds afterwards, but it cannot stop it. The folder question names the files another program changed and does not show what changed in them, and there is no merge: compare the folder's version in `.caotang-backup` by hand.
- The limits on steps, documents and words changed are checked before a card applies, from the drafts for a scene or a batch of synopses and from the activity log for any other step, so a restructure or an import is counted after it has run and can pass a limit by its own size. The cost limit does nothing for a provider with no price. Accept edits and Auto do not yet fall back to Ask for text that came from outside the project, because nothing marks it yet.
- A continuity scan for a writer's own CI exists as a library (`@caotang/scan`): the deterministic checks over a project folder with no model and no key, the file and line of each open finding, and text, Markdown, JSON and GitHub annotation output. The `caotang scan` command and the CI workflow template are not in this build, so nothing runs the library yet.

## 0.1.0

The first public version: a free, local-first writing studio for novels, scripts and story worlds, with an agent that works through the app's own commands on the writer's own provider key. The version is 0.1.0 rather than 1.0 because the project file format may still change.

### Added

- **Projects.** Create, open, rename, import and remove projects in the browser, and set each project's title, author, language, ISBN and cover. Export a project as a `.caotang` bundle and import one back. In Chrome or Edge, open a project folder or save to one. A folder opens as its project and saves back to the folder. A folder of a project this browser already keeps opens as that project when it holds the same book; a different version opens as a second copy, which cannot be saved into that folder. A save asks first when the folder has changed since Caotang last saved it, and before it writes back a `caotang.json` that another program removed. A project whose project file will not load can be rebuilt from its documents, after a question; a project file that names another app or a newer format is refused, with nothing written. A folder's writing sessions come into the browser with it, and an open says what it noted, in whole sentences. A project is open in one tab at a time: a folder of a project another tab has open is refused, and a tab stops saving, and says so, when Caotang was updated in another tab.
- **Binder.** A manuscript of chapters and scenes, and a research section that is never compiled. Drag to reorder, rename, set a status or a label (statuses and labels can be added, in one editor), delete and undo. A filter bar with text, status, label, word-count, keyword and recent-date criteria, and saved filters. A footer with word goals, a sprint timer, a writing history (its Today includes the open sitting), and the words a stopped tab kept. New document goes in a chapter: with no chapter selected it says so, and the empty editor offers New chapter. After a delete, focus goes to the item that takes the deleted one's place.
- **Corkboard, inspector and editor.** Cards in three sizes. The inspector holds the synopsis, notes, keywords, status and label, codex links, scene declarations, and a folder's goal. The Markdown editor saves as you type, with word counts, a daily target and focus mode. Agent drafts appear in the scene as a preview before they are applied. Focus mode says in the status line when the panels stay, and its button leaves the mode. The window is laid out for at least 960 px; below 1100 px the toolbar wraps onto a second row.
- **Screenplays.** Fountain scenes with Script, Source and Pages views, Enter and Tab on the Source tab for cues, an element menu on the Source tab (the **Element** button or Ctrl+E, Cmd+E on a Mac) that rewrites the caret's line as a scene heading, action, character, parenthetical, dialogue, transition, centered line, note or page break, import of `.fountain` and `.fdx` scripts, a Pages view that draws dual dialogue side by side, as the PDF does, and Fountain, Final Draft and PDF export (Final Draft files are not yet checked against Final Draft itself; see Known limits).
- **Dialogue.** Ink containers with a branch graph, an outline, findings, line ids and container settings. Import of an `.ink` story, one container for each group of linked knots. Ink story and dialogue table export, the table as CSV or as a spreadsheet (`.xlsx`). The engine target and the locale reach the exports: a Yarn container writes a Yarn Spinner strings file, the dialogue table has a locale column, and a container's own locale names its Ink story file.
- **Storyboards.** Shot cards in three sizes (S, M and L) with an animatic total, a card row that reads in the shot editor’s words (“Medium close-up (MCU) · Bird’s-eye view · Dolly in · 4 s · 35mm · Dissolve”, not the stored tokens), the same words on the agent’s derive plan, an empty board that offers to derive the shots of the scene beside it, shot fields, pictures (chosen, dropped or pasted, with a lightbox), script coverage (a passage that appears more than once is refused, with how many places, in every file whatever its line endings, and a selection across a line break is covered), a prompt for each target model with its checks (the shot prompt editor keeps the text typed for each vendor when the writer switches vendor), and a prompt pack exported as JSON, Markdown (with a Consistency block for each shot that names a codex entry, listing the entries that sent references and those that sent none) or CSV.
- **Undo across a reload.** Ctrl+Z in a scene still undoes your typing, one burst at a time, after a reload or a closed tab. The history is rebuilt from a journal kept in this browser and used only when it replays to the scene's saved text. An agent's draft starts the history over, so Ctrl+Z never removes it.
- **Reloads.** Text typed in the moment before a reload or a closed tab is kept in this browser and saved when the project opens again, with a notice. If the project has newer text by then, the words are offered in the binder footer as new documents, never written over it. `beforeunload` joins `visibilitychange` and `pagehide` as a flush signal.
- **Codex.** Characters, locations, objects, lore, subplots and other entries, with aliases, include policies, excluded phrases, and a list of the documents each name appears in.
- **Findings.** A quick scan with the checks chosen in Settings, and a model review that runs after its plan is approved. The review sends each scene only the codex entries its include policies select. A scope of more than 20 documents asks first, in the panel. Findings are grouped by severity and quote their passages; findings, run notes, the report and Undo name changes in the writer's words. A finding can be dismissed with a reason, marked fixed, or sent to the agent with Fix with agent. The run history keeps each run, with Run again and Discard run. A coherence report exports as Markdown or JSON. A scene that happens a week or more of story days after the one before it gets a note, which a scene declared **Time skip**, **Dream** or **Mythic** silences.
- **Agent.** Plans, one-step cards and draft previews, with checkpoints and restore. It runs on a preset for one of 25 providers or any OpenAI-compatible endpoint you add (your key stays in the browser), or on a built-in demo provider that needs no key. It uses native tool calling where the model supports it. It can run the model review as a plan step, and it can call the tools of the MCP servers you connect, under the approval rules in the README. The built-in demo says in words when it cannot draft or fill synopses, and changes nothing.
- **Screenplay PDF.** A paginated PDF of the script, made in the browser: US Letter, Courier Prime 12 pt embedded in the file, the standard margins and indents, a title page, page numbers from page 2, scene headings kept with what follows, `(MORE)` and `(CONT'D)` where a speech crosses a page, dual dialogue side by side, and scene numbers in the left margin, the right or both. Scene numbers and `(MORE)`/`(CONT'D)` are recipe settings. Chinese, Japanese and Korean text prints in Noto Sans Mono CJK SC, two columns a character, with only the characters used embedded; that font loads only for a script that needs it. Emoji print in monochrome Noto Emoji, one glyph and two columns each, ZWJ sequences, flags, keycaps and skin-tone sequences included, and copy out of the PDF as typed; that font loads only for a script with emoji.
- **Prompt pack in the Export dialog.** The Media group offers **Prompt pack (video)** with a **Vendor template** choice. A compile writes the JSON, Markdown and CSV packs for that model and downloads them as one zip, for the whole manuscript or one item. A recipe saved with the pack keeps its vendor, and a compile with none chosen is refused beside Compile. The Prompt pack tab's export is unchanged.
- **Spreadsheet export.** The dialogue table and the storyboard shot list export as `.xlsx` as well as `.csv`, from the Media group of the Export dialog. Each has one sheet with the CSV's columns and rows. Shot numbers, durations and character limits are numbers, and text is never run as a formula. The file is made in the browser, with no new dependency.
- **Storyboard contact sheet.** A PDF of the shot cards in board order, on A4 or US Letter pages: each card's picture, shot number and action, with the camera details and duration in the shot editor's words on up to two lines, and a header on each page with the storyboard, the date, the page number, the number of shots and the animatic total. A shot with no picture shows its caption. Chinese, Japanese and Korean text prints in Noto Sans Mono CJK, and emoji print in monochrome in Noto Emoji: every emoji up to Unicode Emoji 17.0 prints. Each font is loaded only for a sheet that needs it and embedded with only the characters the sheet uses. An emoji sequence (a family, a skin tone, a flag, a keycap) prints as one picture, wraps as one character, and copies out of the PDF as typed.
- **Export.** Markdown, plain text, Word (`.docx`) and EPUB, for the whole manuscript or one part of it; the media formats above; the coherence report; and recipes that keep export settings. A compile that is refused is said inside the Export dialog, beside Compile, and the title page carries the date of the day you compile, in your own time zone.
- **Settings.** Provider profiles with optional prices, the agent's context budgets, the daily target and autosave delay, coherence checks, light and dark themes, checkpoint limits, **MCP & tools**, and data.
- **MCP & tools.** Connect external Model Context Protocol servers over Streamable HTTP. Each server's tool list is reviewed before its tools are used, a tool can be switched off, and read-only tools can be trusted after a review. A tool whose name the model cannot take, such as one with a dot, is given a short alias for the agent, and the server still receives its own name.
- **Keyboard.** Shortcuts for the new item, the screenplay element menu, undo, focus mode, the filter, opening in the editor, renaming, deleting and moving items. Arrow keys, Home and End move between the rail tabs and the centre view, and menus return focus to the control that opened them.
- **Caotang as an MCP server** (`@caotang/mcp-server`). Other AI tools can read a project folder over MCP. With `--allow-writes`, four changes apply at once and five ask for confirmation in the host. It listens on `127.0.0.1` with a bearer token, or runs over stdio. Packaged as an MCPB bundle with `pnpm --filter @caotang/mcp-server run pack`, with an "Allow changes" setting that is off by default. The import tools `doc.import` and `codex.import` bring existing writing in, `codex.read` answers from the manifest, and `export.compile` compiles the manuscript, an item or a recipe, EPUB included, after the host confirms it. The model-backed tools are not listed, because the server holds no provider key.
- **Notices.** `THIRD-PARTY-NOTICES.md` lists the third-party software in the builds, generated from the lockfile, and ships beside the desktop build and inside the MCP bundle.
- **License.** Caotang is MIT-licensed and free. There are no accounts, subscriptions or credit meters.
- **Content-Security-Policy.** The built app carries a `<meta>` policy: scripts and styles only from its own origin, no plugins, frames or form submissions, and connections open to the provider and MCP servers the writer chooses. The README's Self-hosting section shows the same policy as a header.
- **Providers.** Presets that fill in each provider's address and authentication, the published context window of each model they name (the Claude models included) in the model picker, three wire formats (OpenAI Chat Completions, OpenAI Responses and Anthropic Messages), and the Chat, Drafting and Background task roles, each with its own profile, model and thinking level.
- **Non-UTF-8 files.** A document whose file is not UTF-8 opens into an encoding review: the detected encoding, a preview, and a conversion only when the writer chooses it, with the original bytes kept in `.caotang-backup/`.
- **MCP client.** Connects to servers that speak the 2025 revisions as well as 2026-07-28.
- **MCP over HTTP.** A 2025-era host can confirm writes over HTTP when it declares elicitation and keeps the session the server gives it, so it need not connect over stdio.
- **Tool answers.** An answer from an external tool larger than 8,000 tokens is refused, with the cap named. It is never cut down.
- **Tool lists.** A server whose tool list has changed is caught before each call, and a changed tool is refused with no request sent.
- **Saves.** A save that Caotang would make over a folder that changed outside it is a question, not a silent write. The question names the files another program changed, a lock file left by the MCP server is a question too, and nothing is written until the writer answers.
- **Findings and agent.** **Fix with agent** rewrites the first quote in binder order, and a finding whose first quote is in a dialogue container has no Fix. The Findings tab and the review plan show the same cost estimate. On the demo provider, Fix with agent rewrites only the demo's own sample passages.
- **Visual references.** A codex entry takes pictures already in the project as visual references. The prompt pack names them for the scenes the entry appears in; Caotang uploads none of them.
- **Storage location.** Settings › Data names the storage location, which is this browser.

The first screenplay export that needs the CJK font now downloads 10.7 MB (the regional forms of Han characters are in it), not 16.4 MB, and the emoji font 0.6 MB, not 0.9 MB. ### Known limits

- Knowledge is checked only where you declare it. The scan does not look for a fact in a character's lines or in the prose, and a group or faction cannot be said to know a fact, only the characters in it.
- **Not in this build:** a desktop wrapper. The user guide's last section lists it.
- Background tasks run only while the project is open in this tab, on the main thread: there is no Web Worker (no typing jank has been measured), no Service Worker, and no gateway limiter that ranks the agent ahead of a task, so a call already sent still counts against a rate-limited key. A coherence review cannot be queued yet.
- The local model presets (Ollama, LM Studio, llama.cpp) are verified against test servers that imitate each product's browser settings, not against the real servers. Firefox has not been tried and Safari is not verified. The context window and tool support of a local model are not read from the server; a server on another computer on your network is not supported.
- The screenplay PDF is US Letter only, in Courier Prime with Noto Sans Mono CJK SC and Noto Emoji for other characters. Emoji are black and white, without skin tones. A character no font covers, such as a Tamil letter, prints as a question mark, and the compile log names it. Bengali, Gurmukhi, Gujarati, Odia, Tamil, Telugu, Kannada, Malayalam and Sinhala print as question marks until each has a font; only Devanagari has one so far. Arabic, Persian, Urdu and Hebrew print in Noto Sans Arabic and Noto Sans Hebrew, but without their marks (the Arabic harakat, the Hebrew points), which are left out of the drawing and counted in the compile log, though a reader copies and searches them with their words; in a reader built on Poppler (Evince, Okular) a letter with two stacked marks can copy with a mark before it, and a word that a narrow paragraph wraps can copy split; Nastaliq is not drawn; and the page is not mirrored for a right-to-left project, which waits for a native reader to look at sample pages. These pages are machine-verified, not reader-verified: they are checked by tests that read the file back, not by a reader of the language, and not in Acrobat. The CJK font is a 10.7 MB download the first time a script or a contact sheet needs it, the emoji font 0.6 MB. The PDF has been checked with Poppler and Ghostscript, not yet in Acrobat or on a printer.
- A WebP picture on the contact sheet is drawn without its colour profile: the app draws the colours the browser converts to sRGB, and the MCP server and the command line draw the stored values. Characters that none of its fonts has (Helvetica, Noto Sans Mono CJK, Noto Emoji, Noto Sans Arabic, Noto Sans Hebrew, Noto Sans Devanagari), such as Tamil, print as `?`, and the compile log names them. Emoji print in black and white, and a skin tone prints as the plain figure. Text in Noto Sans Mono CJK has no bold. The sheet has been checked by tests that read the PDF back, not yet by eye in a range of PDF readers.
- Skills that include scripts: Caotang uses their instructions and does not run the scripts, and the review says that other programs reading the same folder may. The agent reads a skill's instructions only: the other files kept with it are carried and shown on the review, and the agent cannot read them in this build. A skill's list of allowed tools is shown on the review and does not limit the agent here. There are no skills shared across projects, no way to run a skill by name, and `.claude/skills` is not read.
- Final Draft (`.fdx`) import and export have not been checked against files that Final Draft wrote or opened. The scene numbers and page headers Caotang writes are not yet confirmed in Final Draft.
- The `.xlsx` files are checked by unit tests against the Office Open XML parts, and CI opens them in LibreOffice and openpyxl. They have not been opened in Excel or Numbers yet: the checklist for that is `docs/testing/office-interop.md`, and it records no result.
- The Word contents field has not been tested in Word or LibreOffice. Word offers to update it when the file opens; a file without a contents list does not ask. The file's structure is tested, and its entries are plain text until Word updates the field.
- The `.mcpb` bundle is checked by its pinned MCPB CLI and run over stdio. It has not been run in a real MCPB host, and it is not signed.
- Restore after a `caotang agent --write` run lasts only while the command runs: the undo history is not saved, so keep the folder under version control.
- The SDK's restore lasts for the process: the undo history is not saved, so a turn written with `write: true` cannot be restored by a later run. Read `diff()` before you set `write: true`, and keep the project in git.
- An app that already has a folder open does not show what the MCP server saved to `coherence.json` until the folder is opened again. The server's check of that file narrows the chance that it and the app lose each other's findings and does not close it.
- The desktop app asks before it saves over the MCP server's folder lock, but a save the writer confirms can still replace a change the server made. Keep the server stopped while the app saves to the same folder.
- The toolbar's Undo and the Undo in Activity last for the open tab; checkpoints survive a reload. Undo on a screenplay's Source tab and in Ink text is the browser's own.
- The Yarn Spinner strings file has not been loaded in Yarn Spinner itself, and its `lock` values have not been compared with the ones Yarn's own compiler writes. They follow the rule in Yarn Spinner's documentation and source.
- In the Yarn Spinner strings file, a `language`, `text`, `file` or `comment` cell that starts with `=`, `+`, `-`, `@`, a tab or a carriage return gets an apostrophe in front, as in every CSV export, so a spreadsheet does not run it as a formula. A spoken line's `text` cell starts with the speaker's name when it has one. The apostrophe is written into the cell itself, so a tool that reads the file gets it with the text; how Yarn Spinner shows it has not been checked.
- Pull requests run end-to-end tests in Chromium, Firefox and WebKit; the Firefox and WebKit suite also runs nightly and on demand, without the specs that need folder saves (File System Access is Chromium-only). CI tests Node 22.12.0 and 24; Node 26 is allowed by `engines` but not covered. The suite tests the checkpoint trim on the browser's own IndexedDB and programmatic `File` objects on a shot card; it does not drive a file dragged out of the desktop or the system clipboard.
- CI uses the built-in demo and mock providers only. An opt-in real-key smoke test (`e2e/provider-smoke.spec.ts`, one `CAOTANG_SMOKE_<PRESET>` variable per provider) runs locally, or in CI by a maintainer's manual dispatch from repository secrets; never on a pull request.
